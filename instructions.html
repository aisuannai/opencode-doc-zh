指令文件

加一个 AGENTS.md，就能给 OpenCode 持久的项目指引：构建命令、架构要点、代码规范、验收要求，都写在这里，每次会话自动生效。

🧠 通俗理解

给新同事的入职手册怎么写？「改完 TS 要跑 bun typecheck」「数据库查询都放 src/database」「别手改生成文件」。AGENTS.md 就是写给 AI 同事的这份手册——它是 Markdown 纯文本，跟着仓库走，提交进版本库后团队每个人（包括 AI）看到的项目规则都一致。你不用每次在聊天里重复交代规矩。

AGENTS.md
# Project instructions

- Run `bun typecheck` after changing TypeScript.
- Keep database queries in `src/database`.
- Do not edit generated files directly.

把项目指令文件提交进版本库，让每个在仓库里工作的人都得到同样的指引。

作用范围

把 AGENTS.md 放在希望它生效的目录里。OpenCode 先加载全局文件，然后从当前工作区目录一路向家目录方向加载每一层 AGENTS.md；工作区在家目录之外时，会在项目根目录停下。

text
~/.config/opencode/AGENTS.md
~/code/my-project/AGENTS.md
~/code/my-project/packages/AGENTS.md
~/code/my-project/packages/web/AGENTS.md  ← current workspace

这个例子里四个文件都会加载，合并顺序如下：

text
~/.config/opencode/AGENTS.md
packages/web/AGENTS.md
packages/AGENTS.md
AGENTS.md

适用于一切场景的指引放全局文件；仓库级指引放项目根目录；越靠近代码的文件放越具体的指引。OpenCode 只做合并，不解决文件之间的冲突。

工作区在项目根之外时，只加载全局文件。设置 OPENCODE_DISABLE_PROJECT_CONFIG=1 可以跳过项目 AGENTS.md 的发现，但不影响全局文件。

CLAUDE.md 回退

在没有 AGENTS.md 的目录里，OpenCode 会改读 CLAUDE.md。没有全局 ~/.config/opencode/AGENTS.md 时，它会读 ~/.claude/CLAUDE.md。同一目录里 AGENTS.md 永远优先于 CLAUDE.md，所以两个文件之间的符号链接也只会加载一次。

设 OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1 可跳过所有 CLAUDE.md；设 OPENCODE_DISABLE_CLAUDE_CODE=1 会连 .claude 技能一起跳过。服务器在启动时读取这两个变量。对后台服务，用 opencode service set env 持久化它们，然后 opencode service restart。

💡 扩展

AGENTS.md 正在成为多家工具共同遵循的开放约定，而 CLAUDE.md 是 Claude Code 的惯例文件名。OpenCode 的回退机制意味着：一个从 Claude Code 迁移过来的仓库不用改任何文件就能直接用；反过来你也可以用符号链接让两个文件永远同步，维护一份就够。

发现机制

工作区之下的指令文件，会随着智能体探索项目而被发现。读一个文件或列一个目录时，会加载该目标与工作区之间的所有 AGENTS.md：

text
my-project/                         ← current workspace
├── AGENTS.md                       loaded initially
└── packages/
    └── web/
        ├── AGENTS.md               loaded when this area is read
        └── src/
            └── app.ts              read target

嵌套文件按「最近优先」加载，并在其指令条目还留在模型可见历史里时去重。重复读同一区域通常不会再次注入。如果压缩（compaction）或回退把那条目移掉了，之后的读取可以再次加载该文件。

嵌套文件加载之后，对它的编辑不会自动被检测。需要更新的文本立刻生效时，请开一个新会话。

指令顺序

选定的智能体或提供商系统提示词最先发送。OpenCode 然后按这个顺序组装初始指令：

text
1. Agent or provider system prompt
2. Code Mode tool guidance, when enabled
3. MCP server, reference, and skill guidance
4. Global and project AGENTS.md files, then configured instructions
5. Built-in date and environment context
6. Session-specific instruction entries supplied through the API

这些来源是叠加关系，不是互相覆盖。后来发现的嵌套 AGENTS.md 按发现顺序追加进会话历史。

热更新

会话运行中，编辑全局或向上发现的 AGENTS.md 就能更新指引：

bash
$ printf '\n- Run the integration suite before committing.\n' >> AGENTS.md

在下一次模型请求之前，OpenCode 会检测到变化，并在交付待处理输入前插入一条指令更新：

text
AGENTS.md changes
→ instruction update
→ next prompt
  • 删除所有环境内的 AGENTS.md 会告诉会话：之前的环境内指令不再适用。
  • 临时读取失败会保留最后一次已知的指令，而不是当作已删除。
  • 移动会话会保留其指令状态，目的地处的指引会以「更新」的形式引入。
  • 提交会话回退（revert）会清空指令状态，并在下一次提示词之前重新加载指令。

指令内容保持特权：客户端能看到哪些来源变了，但看不到内容本身。

配置扩展

用 instructions 数组，可以在自动发现的 AGENTS.md 之外添加文件、glob 模式或 HTTP(S) URL：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/guidelines/*.md",
    "~/rules/opencode.md",
    "https://example.com/instructions.md",
  ],
}

配置的指令在 AGENTS.md 之后按列出顺序加载。来自每个配置文档的条目都会合并。

条目形式解析方式
相对路径或 glob从工作区到项目根的每一层目录里搜索
~/ 路径从家目录解析
绝对路径按原样使用；文件名可以是 glob
http:// 或 https://配置加载时抓取，超时 5 秒
  • 本地文件变化时的更新方式与 AGENTS.md 相同。匹配 glob 的新文件在下一次配置变化时加载。
  • 缺失的文件被跳过。抓不到的 URL 会被跳过，或保留最后一次抓到的内容。
  • 设置 OPENCODE_DISABLE_PROJECT_CONFIG=1，或工作区在项目之外时，相对条目从全局配置目录解析。

⚠️ 注意

指令文件是「建议」不是「法律」：模型通常遵守，但不保证 100% 执行——强约束（比如禁止碰某些文件）要配 权限或 策略来兜底，双保险才是正解。另外，指令内容会占用上下文，写精华条目而不是把整个编码规范全文塞进去。

💡 扩展

已连接的 OpenCode Console 工作区也可以共享指令。配置的位置与优先级见 配置一章。想给单个智能体定制行为，还可以结合 Agents 使用。
