Cloudflare SDK

在 Cloudflare Durable Object 里使用 @opencode/sdk/workerd。这个版本使用 Durable Object 的 SQLite 存储，为驱逐（eviction）后的恢复持久化事件，并替换掉不可用的本地文件系统和进程服务。

sh
bun add @opencode/sdk

在 Durable Object 实例的整个生命周期里持有一个宿主，而不是每个请求都创建一个：

TypeScript
import { OpenCodeWorkerd } from "@opencode/sdk/workerd"
import myPlugin from "./my-plugin"

export class OpenCodeDO {
  private readonly opencode: Promise<OpenCodeWorkerd.Interface>

  constructor(state: DurableObjectState) {
    this.opencode = state.blockConcurrencyWhile(() =>
      OpenCodeWorkerd.create({
        storage: state.storage,
        config: { default_agent: "build" },
        plugins: [myPlugin],
      }),
    )
  }

  async fetch() {
    const opencode = await this.opencode
    return Response.json(await opencode.server.info())
  }
}

blockConcurrencyWhile 在宿主就绪之前挡住每一个 Durable Object 事件，并在初始化失败时重置该对象。保留的这个 Promise 让请求处理器在启动后直接访问同一个宿主：

TypeScript
constructor(state: DurableObjectState) {
  this.opencode = state.blockConcurrencyWhile(() =>
    OpenCodeWorkerd.create({ storage: state.storage }),
  )
}

Wrangler 通过 workerd 包条件（package condition）选择 OpenCode 的 Workerd 安全实现。Cloudflare 可能在不运行清理的情况下驱逐 Durable Object，所以正确性不能依赖 close() 被调用：

wrangler.jsoncJSONC
{
  "compatibility_flags": ["nodejs_compat"]
}

⚠️ 注意

两个最容易忽略的前提：nodejs_compat 兼容性标志必须开着（OpenCode 的很多实现依赖 Node 兼容层）；持久化是靠 Durable Object 自带的 SQLite（state.storage），不是你项目里另配的数据库。另外，被驱逐时不会有任何清理回调，你的代码必须假定「随时可能消失」，靠持久化事件自己恢复。

路由出站请求（Route outbound requests）

传一个 fetch，把 OpenCode 的出站 HTTP 请求（OpenCode Console 配置、模型请求、网页抓取与搜索、well-known 配置、远程 MCP 服务器）路由到自定义处理器，例如 Service Binding。Code Mode 里的智能体代码继续使用 globalThis.fetch：

TypeScript
OpenCodeWorkerd.create({
  storage: state.storage,
  fetch: (input, init) => {
    const request = new Request(input, init)
    return new URL(request.url).hostname === "console.example.com" ? env.CONSOLE.fetch(request) : fetch(request)
  },
})

定制（Customize）

通过注册与你的 Worker 打包在一起的插件来定制 OpenCode 实例。把插件传给 OpenCodeWorkerd.create() 以定制 agents、模型、工具和其它行为：

TypeScript
import { Plugin } from "@opencode/plugin"
import { OpenCodeWorkerd } from "@opencode/sdk/workerd"

const plugin = Plugin.define({
  id: "customize-agent",
  async setup(ctx) {
    await ctx.agent.transform((agents) => {
      agents.update("build", (agent) => {
        agent.description = "Builds features and fixes bugs for our team"
      })
    })
  },
})

await OpenCodeWorkerd.create({
  storage: state.storage,
  config: { default_agent: "build" },
  plugins: [plugin],
})

插件的钩子、转换、工具和完整插件上下文见服务器插件全篇。

💡 扩展

为什么 Durable Object 特别适合托管 OpenCode：它是单实例、有状态、自带 SQLite 的「小服务器」，天然匹配「一个宿主 + 一个存储 + 会话持久化」的形态。如果出站请求要经过 Cloudflare 的访问控制（比如让模型请求走某个 Service Binding 出网），就用上面的 fetch 参数做分流——注意它只拦 OpenCode 自己的出站请求，Code Mode 里用户代码的 fetch 不走这条路。
