GUI 插件

GUI 插件用 GUI 插件 SDK @opencode/plugin/gui 给 OpenCode Desktop 添加面板、命令、设置页和原生集成。它是插件包的 ./gui-experimental 部分，可以单独存在，也可以与服务器部分和 TUI 部分并列。

⚠️ 注意

GUI 插件 API 是实验性的，版本之间可能变化。导出名里的 -experimental 就是在包里明示了这一点。

./gui-experimental 文件与服务器、TUI 部分一样，默认导出 Plugin.define：

src/gui.tsxTypeScript · TSX
import { Command, Plugin } from "@opencode/plugin/gui"
import { Acme } from "./rpc"

export default Plugin.define({
  i18n: { en: { "command.open": "Open Acme" } },
  setup(ctx) {
    ctx.add(Command, () => ({
      id: "open",
      title: ctx.t("command.open"),
      run: () => void ctx.client.rpc(Acme).open({}),
    }))
  },
  main(ctx) {
    ctx.log.write("info", "acme started")
  },
})

GUI 插件可以跑在两个进程里：

  • setup——在每个桌面应用窗口里运行。它贡献面板、命令、设置页、插槽（slot）、服务器数据源、链接处理器和样式。见窗口一节。
  • main——只运行一次，位于 Electron 主进程。它提供类型化的 Ipc 契约、原生菜单项、WebContentsView 嵌入，以及 Node 和 Electron 集成。见主进程一节。

包（Package）

一个插件包可以从同一个 npm 包里同时发布服务器、TUI 和 GUI 代码。在 ./tui 旁边加一个 ./gui-experimental 导出，OpenCode Desktop 就会在自己的后台服务器上为每个插件加载它：

package.jsonJSON
{
  "name": "opencode-acme-plugin",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./tui": "./src/tui.tsx",
    "./gui-experimental": "./dist/gui-experimental.cjs"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "devDependencies": {
    "solid-js": "^1.9.0",
    "vite": "^7.0.0",
    "vite-plugin-solid": "^2.11.0"
  }
}

用户像安装其它插件一样安装它，没有单独的 GUI 安装步骤：

opencode.jsoncJSONC
{
  "plugins": ["opencode-acme-plugin"],
}

GUI 不声明 id：它沿用插件的 id，即服务器部分的 id；没有服务器部分的包则用包名（本地目录没有 name 字段时用目录名）。通过 ctx.id 读取。

一个文件，两个进程

每个进程都会对整个 ./gui-experimental 文件求值并读取其默认导出。窗口运行 setup，桌面应用的主进程运行 main：

src/gui.tsxTypeScript · TSX
import { shell } from "electron"
import { Plugin } from "@opencode/plugin/gui"

export default Plugin.define({
  setup(ctx) {
    // 窗口代码：Solid 组件、ctx.layout、ctx.add(Command, …)。
  },
  main(ctx) {
    // 主进程代码：electron、Node 内置模块、ctx.windows。
    ctx.windows.on("open", () => shell.beep())
  },
})

因为两个进程求值的是同一个文件，所以每个进程里，对方进程的模块都是惰性占位符（inert placeholder）：

  • 在窗口里，electron 和 Node 内置模块是惰性占位符。
  • 在主进程里，Solid 和仅窗口可用的模块是惰性占位符。

占位符接受模块作用域内的任何属性读取、调用或构造——比如 Solid 提升的模板或打包器提升的 require 调用。把每个进程的代码都放在它自己的 setup 里：跑错进程的代码只会拿到占位符，而不是能用的值。

Plugin.define 和契约辅助工具在两个进程里都来自同一个 SDK。在主进程里，@opencode/plugin/gui 解析到主 SDK，它导出同样的 Plugin、Store、Ipc、Contract 和 Registry。一份定义同时服务两个进程。它那些仅窗口可用的导出（如 Command、bindPlugin、createKeyed）在主进程里是 undefined，所以只在 setup 里使用它们。

构建 bundle

./gui-experimental 必须是一个预构建的 CommonJS 文件。用 @opencode/plugin/gui/vite 提供的 Vite 预设来构建：

vite.config.tsTypeScript
import { defineConfig } from "vite"
import { gui } from "@opencode/plugin/gui/vite"

export default defineConfig({ plugins: [gui()] })
bash
vite build

这个预设会做以下事情：

  • 用 vite-plugin-solid 编译 Solid JSX。
  • 产出一个 CommonJS 文件，并内联所有动态 import()——因为应用无法加载第二个 chunk。
  • 把应用的共享模块、Electron 和 Node 内置模块保持为外部依赖（external），其余依赖全部打包进来。
  • 对任何其它 effect/*、solid-js/* 或 @opencode/* 模块直接让构建失败。应用不提供这些模块，打包一份副本也无法共享应用的实例。
报错示例
effect/Schema is not a module the OpenCode app provides to plugin GUIs: effect, @opencode/plugin/gui, …

改为从共享入口导入，例如 import { Schema } from "effect"。

预设选项

给 gui() 传选项可以修改入口或输出文件：

vite.config.tsTypeScript
export default defineConfig({ plugins: [gui({ entry: "src/desktop.tsx", outFile: "dist/desktop.cjs" })] })
  • entry 是默认导出 Plugin.define 的文件，默认 src/gui.tsx。
  • outFile 是 ./gui-experimental 导出指向的 bundle，默认 dist/gui-experimental.cjs。

依赖（Dependencies）

把构建工具加为 devDependencies。应用在运行时提供 @opencode/plugin/gui，所以 bundle 只需要 @opencode/plugin 依赖里的类型：

bash
bun add -d vite vite-plugin-solid solid-js

要在 main 里用 Electron 和 Node 的类型，还要加 electron 和 @types/node：

bash
bun add -d electron @types/node

共享模块（Shared modules）

每个进程都会向 bundle 提供以下模块。require 一个两个进程都不提供的模块，会让插件的 GUI 失败：

TypeScript
import { Schema } from "effect" // 两个进程都可用
import { createSignal } from "solid-js" // 窗口；主进程里是惰性占位符
import { readFile } from "node:fs/promises" // 主进程；窗口里是惰性占位符
  • 两个进程都可用：effect、@opencode/plugin/gui、@opencode/plugin/gui/main、@opencode/plugin/rpc、@opencode/schema/rpc、@opencode/client、@opencode/client/effect。
  • 仅窗口可用：solid-js、solid-js/web、solid-js/store、@opencode/client/solid、@opencode/plugin/gui/{file,review,browser}。主进程里是惰性占位符。
  • 仅主进程可用：electron 和 Node 内置模块（如 node:fs）。窗口里是惰性占位符。

GUI 入口在哪里加载

OpenCode Desktop 从它自己的后台服务器加载 GUI 入口，而那个服务器已经加载了你配置里的插件，所以 GUI 入口永远不会引入新的代码来源。把插件配置在全局 opencode.json(c) 里，它的 GUI 就能在每个窗口里可用。

⚠️ 注意

TUI 从 cli.json 读插件，但桌面应用只读 opencode.json(c)。一个只发布过 TUI 部分、被用户列在 cli.json 里的包，一旦增加了 ./gui-experimental，就必须同时列进 opencode.json(c)。

桌面应用的主进程用一份只有它自己持有的凭据，从自己的服务器列出插件并读取其 bundle，然后把同一份集合发给各窗口。窗口不能提供主进程代码。

服务器部分加载失败的插件没有 GUI。

重载与更新

从本地目录加载插件，并在每次改动时重新构建：

bash
vite build --watch
  • package.json 带 name 和 exports 的本地目录，会通过它们解析 ./gui-experimental。没有这两个字段时，加载根目录下的 gui-experimental.cjs（或 .js）。入口必须是 .cjs 或 .js；其它文件会被忽略。
  • 每次重新构建都会在每个窗口和主进程里重载该插件的 GUI。服务器入口不会重启。
  • 已安装包的 GUI 只随版本变化。
  • 在 opencode.json(c) 里修改插件的 options 会重载插件。
  • opencode plugin update 在更新完成后替换包的 GUI。
  • Settings > Extensions > Plugins 列出插件并带一个开关，可以关掉它的 GUI。要移除插件，把它从 opencode.json(c) 里删掉，或运行 opencode plugin remove <package>。

⚠️ 注意

应用自带的插件保留了自己的 id。如果你的插件 id 是其中之一、用 . 嵌在它们下面、有别的 id 嵌在它下面、或在 opencode 命名空间里，它的 GUI 不会加载，并且 Settings > Extensions > Plugins 会把它列为未加载。

定义 GUI 插件

Plugin.define 声明插件运行在哪些系统上、它存储的窗口状态、它的图标和文案。宿主会在任何 setup 运行之前读取这些声明：

src/gui/definition.tsTypeScript
import { Schema } from "effect"
import { Plugin, Store } from "@opencode/plugin/gui"

export const definition = Plugin.define({
  os: ["macos", "linux"],
  stores: {
    prefs: Store.global(Schema.Struct({ enabled: Schema.Boolean }), { enabled: true }),
  },
  i18n: {
    en: { title: "Acme", "command.open": "Open Acme" },
    de: { title: "Acme", "command.open": "Acme öffnen" },
  },
})
  • 宿主把 id 给插件，即 ctx.id：服务器部分的 id，没有服务器部分的包则是包名（本地目录没有 name 时是目录名）。插件创建的所有 id 都会加上这个前缀：命令（<id>.<command>）、面板键（<id>:<tab>）、存储键（plugin.<id>.<key>），以及它提供的契约和 Ipc 的 id。
  • os 把插件限制到某些操作系统。省略它则所有系统都运行。os 不包含当前系统的插件不会运行，Settings > Extensions > Plugins 会保留它的行并显示「此系统不可用」。
  • stores 为窗口声明存储状态。通过 ctx.stores.<key> 读取。
  • icons 声明插件自己的图标，每个图标是一段 SVG 文件文本。通过 ctx.icons.<name> 读取图标名。
  • i18n 按语言保存文案。每种语言都内联写全；英文会补齐其它语言缺的键。用 ctx.t(key, params) 和 ctx.plural(key, count) 读取。在窗口里，ctx.t 还会读取应用的共享键，比如 common.*。在 main 里，缺失的键返回键名本身。
  • 定义 setup、main，或两者都定义。两者都没有的 GUI 无法加载。
  • 不带 setup 时，Plugin.define 把声明作为 Plugin.Declarations 返回，其它文件里的 setup 可以据此获得类型。Plugin.Definition 是完整定义的类型。
  • 插件不声明它提供或使用的契约。它在运行时提供和读取它们；见契约与 Token。

参考（Reference）

TypeScript类型定义
interface Declarations {
  os?: ("macos" | "windows" | "linux")[]
  stores?: Record<string, StoreDeclaration>
  icons?: Record<string, string>
  i18n?: { en: Messages; [locale: string]: Messages }
}

interface Definition extends Declarations {
  setup?(ctx: SetupContext<this>): Cleanup | void
  main?(ctx: MainContext): Cleanup | void | Promise<Cleanup | void>
}

type Cleanup = () => void | Promise<void>

拆分到多个文件

小的 GUI 插件放进 src/gui.tsx 就够了。更大的插件可以这样组织：在 definition.ts 里声明插件，把共享 token 放进 contract.ts，每个 setup 写在独立文件里，最后在 src/gui.tsx 里组合：

目录结构
src/
├── index.ts            服务器部分：来自 @opencode/plugin 的 Plugin.define
├── rpc.ts              服务器部分与其客户端之间的 RPC 契约
├── gui.tsx             ./gui-experimental 入口：export default Plugin.define({ ...definition, setup, main })
└── gui/
    ├── definition.ts   Plugin.define：os、stores、icons、i18n
    ├── contract.ts     其它代码可以导入的 Token：Ipc、Contract、Registry
    ├── window.tsx      窗口 setup：Plugin.Setup<typeof definition>
    ├── main.ts         主进程 setup：Plugin.MainSetup（仅桌面端）
    ├── page.tsx        面板和页面渲染的组件
    ├── icons/logo.svg  插件自己的图标
    └── i18n/en.ts      英文文案

窗口启动时会对整个 ./gui-experimental 文件求值，所以模块作用域和 setup 要保持轻量。在那些地方只注册贡献，把昂贵的工作放进组件、createKeyed 或 createLatest 里。

对更大的插件：先声明插件，从声明给每个 setup 定型，再用它们定义插件：

src/gui/definition.tsTypeScript
import { Schema } from "effect"
import { Plugin, Store } from "@opencode/plugin/gui"

export const definition = Plugin.define({
  stores: { notes: Store.global(Schema.Struct({ count: Schema.Number }), { count: 0 }) },
})
src/gui/window.tsxTypeScript · TSX
import type { Plugin } from "@opencode/plugin/gui"
import { Notes } from "./contract"
import type { definition } from "./definition"

export const setup: Plugin.Setup<typeof definition> = (ctx) => {
  ctx.provide(Notes, { count: () => ctx.stores.notes.value.count })
}
src/gui/main.tsTypeScript
import type { Plugin } from "@opencode/plugin/gui"

export const main: Plugin.MainSetup = (ctx) => {
  ctx.log.write("info", "acme started")
}
src/gui.tsxTypeScript · TSX
import { Plugin } from "@opencode/plugin/gui"
import { definition } from "./gui/definition"
import { main } from "./gui/main"
import { setup } from "./gui/window"

export default Plugin.define({ ...definition, setup, main })
  • Plugin.Setup<typeof definition> 是窗口 setup 的类型。它按声明的 stores 给 ctx.stores 定型，按声明的图标给 ctx.icons 定型。
  • Plugin.MainSetup 是主进程 setup 的类型；Plugin.Cleanup 是任一 setup 可返回的清理函数类型。
  • 从 @opencode/plugin/gui 导入注册表、token 和辅助工具，例如 Command、SettingsPage、Panel、Slot、Contract、Ipc、Registry、Store、createKeyed、usePlugin、bindPlugin。
  • 仅主进程可用的注册表（如 MenubarItem）从 @opencode/plugin/gui/main 导入。

共享上下文（Shared context）

两个 setup 都会收到插件的选项、OpenCode 服务器的客户端和应用元数据，与服务器、TUI 部分一样。

选项（Options）

ctx.options 保存插件在 opencode.json(c) 条目里的 options：与服务器部分拿到的值相同：

opencode.jsoncJSONC
{
  "plugins": [{ "package": "opencode-acme-plugin", "options": { "team": "core" } }],
}
TypeScript
setup(ctx) {
  const team = ctx.options.team
}
  • 修改选项会重载插件。

服务器客户端（Server client）

ctx.client 是运行该插件的服务器的 OpenCode 客户端：也就是桌面应用自己的服务器。用它通过 RPC 调用你的服务器部分：

TypeScript
import { Command } from "@opencode/plugin/gui"
import { Acme } from "./rpc"

ctx.add(Command, () => ({
  id: "search",
  title: ctx.t("command.search"),
  run: async () => {
    const result = await ctx.client.rpc(Acme).search({ query: "todo" })
    console.log(result)
  },
}))
  • 在调用处读取 ctx.client。该服务器重启后它会变化。
  • 服务器不可达期间，每次调用都会 reject。

应用元数据（App metadata）

ctx.app 描述正在运行的应用：

TypeScript
if (!ctx.app.packaged) console.log(`Acme on ${ctx.app.name} ${ctx.app.version} (${ctx.app.channel})`)
  • name 是 "opencode"，与服务器插件的 ctx.app.name 相同。
  • platform 在 Electron 应用和 main 里是 "desktop"，在浏览器标签页里是 "web"。
  • packaged 在桌面应用以打包形式运行时为 true。在 Web 上永远是 false。
  • 服务器插件会拿到 name、version 和 channel；TUI 插件拿到 version 和 channel。

契约与 Token（Contracts and tokens）

Token 让 GUI 插件跨进程、以及彼此之间通信，而不必导入对方的运行时代码。把每个 token 放进 contract.ts。一个 token 只持有它的种类和 id（Ipc 还持有 schema），所以其它插件可以不导入你的运行时代码就导入它。

  • ctx.provide(token, impl) 提供你自己的某个 token：窗口 setup 里的 Contract，或 main 里的 Ipc。
  • ctx.use(token) 跟随其它插件提供的契约或 Ipc。它返回一个 Live 访问器。
  • ctx.main(ipc) 返回你自己 main 提供的某个 Ipc 的客户端。

插件只能提供 id 等于自己 id、或以自己 id 开头（形如 <id>.<name>）的 token。其它 id 会让 ctx.provide 抛错，id 超出自己的 Ipc 会让 ctx.main 抛错。本页示例用 acme 作为插件 id，所以它们的 token id 以 acme. 开头：

TypeScript
Contract.define<AcmeBadge, "acme.badge">("acme.badge") // 插件 acme 可以提供它。
Contract.define<AcmeBadge, "badge">("badge") // 在插件 acme 里 ctx.provide 会抛错。

契约（Contracts）

当一个插件的窗口 setup 要向其它插件的窗口 setup 暴露 API 或 Solid 组件时，用 Contract.define：

src/gui/contract.tsTypeScript
import type { JSX } from "solid-js"
import { Contract } from "@opencode/plugin/gui"

export interface AcmeBadge {
  Badge(props: { readonly label: string }): JSX.Element
  count(): number
}

export const AcmeBadge = Contract.define<AcmeBadge, "acme.badge">("acme.badge")

在窗口 setup 里用 ctx.provide 提供它。契约里含组件时，在 setup 期间用 bindPlugin 包一层。这样组件内部的 usePlugin() 读到的是提供方（provider）的上下文，而不是消费方的：

src/gui.tsxTypeScript · TSX
import { bindPlugin, Plugin } from "@opencode/plugin/gui"
import { AcmeBadge } from "./gui/contract"

export default Plugin.define({
  i18n: { en: { title: "Acme" } },
  setup(ctx) {
    ctx.provide(AcmeBadge, {
      Badge: bindPlugin((props: { readonly label: string }) => (
        <span>
          {ctx.t("title")}: {props.label}
        </span>
      )),
      count: () => 42,
    })
  },
})
  • 给被 bindPlugin 包住的组件标注 props 类型，如 bindPlugin((props: FileTreeProps) => ...)。TypeScript 在 ctx.provide 内部推不出来。
  • 数据方法（如 count）不要包。
  • ctx.provide 返回一个函数，可提前撤回契约。宿主也会在当前属主结束时撤回它，否则在插件停止时撤回。

使用其它插件的契约

把 contract.ts 从你的包里导出（例如作为 ./contract），其它插件就能导入它的 token。另一个插件用 ctx.use(token) 跟随该契约。访问器的值会随着提供方启动、停止、重启而变化，所以要在使用处读取：

src/gui.tsxTypeScript · TSX
import { Plugin, Slot } from "@opencode/plugin/gui"
import { AcmeBadge } from "opencode-acme-plugin/contract"

export default Plugin.define({
  setup(ctx) {
    const badge = ctx.use(AcmeBadge)

    const count = () => {
      const live = badge()

      return live.status === "active" ? live.value.count() : 0
    }

    ctx.add(Slot, { at: "window.bottom", render: () => <span>{count()}</span> })
  },
})
  • ctx.use 对同一个 token 每次调用返回同一个访问器。
  • 提供方不在线时，消费方继续工作。见活性依赖与失败处理。

主进程与窗口之间的 IPC

用 Ipc.define 加 Effect Schema 编解码器，在 main 和 setup 之间定义一个类型化桥梁。main 用 ctx.provide 实现它，窗口通过 ctx.main 调用它：

src/gui/contract.tsTypeScript
import { Schema } from "effect"
import { Ipc } from "@opencode/plugin/gui"

export const KeepAwake = Ipc.define({
  id: "acme.awake",
  methods: {
    screenActive: { output: Schema.Boolean },
    setScreenActive: { input: Schema.Boolean },
  },
})
TypeScript
const awake = ctx.main(KeepAwake)

await awake.setScreenActive(true)
  • 其它插件用 ctx.use(KeepAwake) 跟随你的 Ipc，与契约一样。
  • 状态、事件和提供方详见定义并提供 Ipc。

插件自有的注册表（Registries your plugin owns）

用 Registry.define 定义一份你的插件拥有的清单。其它插件用 ctx.add 贡献条目，你的插件用 ctx.list 读取它们：

src/gui/contract.tsTypeScript
import { Registry } from "@opencode/plugin/gui"

export interface Exporter {
  readonly id: string
  readonly title: string
  run(text: string): void
}

export const Exporter = Registry.define<Exporter>("acme.exporter")
TSX
// 另一个插件贡献一个条目。
ctx.add(Exporter, () => ({ id: "gist", title: ctx.t("exporter.gist"), run: (text) => upload(text) }))

// 属主列出每个贡献。响应式：在 render 或 memo 里读取。
const exporters = () => ctx.list(Exporter)

窗口（The window）

插件的 setup 在每个桌面应用窗口里运行。把它传给插件 ./gui-experimental 文件里来自 @opencode/plugin/gui 的 Plugin.define。setup 是同步的，可以返回一个清理函数；见生命周期与清理：

src/gui.tsxTypeScript · TSX
import { Command, Plugin } from "@opencode/plugin/gui"

export default Plugin.define({
  i18n: { en: { open: "Open Acme" } },

组件（Components）

在 Solid 组件里，调用 usePlugin<typeof definition>() 拿到与 setup 收到的同一个上下文对象。从声明所在文件给它定型（见拆分到多个文件），组件与定义之间就不必互相导入：

src/gui/window.tsxTypeScript · TSX
import { Slot, usePlugin, type Plugin } from "@opencode/plugin/gui"
import type { definition } from "./definition"

function StatusLabel() {
  const ctx = usePlugin<typeof definition>()

  return <span>{ctx.t("title")}</span>

export const setup: Plugin.Setup<typeof definition> = (ctx) => {
  ctx.add(Slot, { at: "window.bottom", render: () => <StatusLabel /> })
}

图标（Icons）

SDK 的每个 icon 字段，以及 ctx.ui.Icon，都接受一个 IconName：应用自带图标之一的名字，或你的插件声明的一个图标的名字。其它字符串无法通过编译：

TypeScript
ctx.add(TitlebarItem, () => ({ id: "sync", label: ctx.t("sync"), icon: "server", run: () => sync() }))

声明自己的图标

应用没有的图稿（比如你产品的标志），把 SVG 文件放进你的包里，并在 icons 里声明。用 ?raw 导入文件，gui() 预设会把它打包成文本：

src/gui/definition.tsTypeScript
import { Plugin } from "@opencode/plugin/gui"
import logo from "./icons/logo.svg?raw"

export const definition = Plugin.define({
  icons: { logo },
})

然后在任何接受 IconName 的地方传 ctx.icons 里的图标名：

src/gui/window.tsxTypeScript · TSX
import { ComposerPill, Slot, type Plugin } from "@opencode/plugin/gui"
import type { definition } from "./definition"

export const setup: Plugin.Setup<typeof definition> = (ctx) => {
  ctx.add(ComposerPill, {
    id: "sync",

}
  • ctx.icons 里每个声明的图标有一个名字。没声明的名字无法通过编译。
  • 宿主会在 setup 运行前注册你的图标，并在插件消失时撤回它们。
  • 不是 SVG 文档的值会让插件在启动时失败。
  • 要让 ?raw 导入通过类型检查，在 tsconfig.json 的 types 里加上 "vite/client"。

绘制图标

宿主绘制你的图标与绘制它自己的一样：按展示位置的尺寸和颜色：

  <circle cx="8" cy="8" r="6.5" stroke="currentColor" />
  <path d="M5 8.5 7 10.5 11 6" stroke="currentColor" stroke-linecap="round" stroke-linejoin="round" />

让图标动起来

图标可以动，比如表示工作正在进行。在文件内部使用 SVG 动画元素，例如 animate 和 animateTransform：

  • 没有任何位置展示的图标不占任何成本。

注册表（Registries）

把一个注册表 token 和一个条目传给 ctx.add，即可向窗口外壳（shell）做贡献。当条目要跟随响应式状态（比如语言）时，把条目作为函数 () => item | undefined 传入。宿主会在函数读到的内容变化时再次执行它。返回 undefined 表示撤回条目，直到函数再次返回一个条目为止：

TypeScript
ctx.add(Command, () => ({ id: "open", title: ctx.t("command.open"), run: () => open() }))
  • 在函数内部用 ctx.t 读取标签。在固定条目里读取一次的标签，会保留读取时的语言。
  • 当条目有字面量类型字段（如 hidden: true、某个 section、icon 或菜单名）时，给函数标注返回类型：(): Command => ({ ... })。否则 TypeScript 会把字段扩宽成 string 或 boolean，没有重载能匹配。
  • 从不变化的条目（比如某个样式）直接传固定条目。
  • 宿主会让某些对象保持稳定：面板从 list 返回的标签页，以及带 render 的条目（如面板和设置页）。从 getter 里读它们的标签，例如 get title() { return ctx.t("title") }。
  • ctx.add 返回一个函数，可提前撤回条目。

命令（Commands）

Command 向命令面板、Settings > Shortcuts、以及可选的输入框 / 菜单添加动作。宿主把命令发布为 <plugin id>.<command id>：

TypeScript
import { Command } from "@opencode/plugin/gui"

ctx.add(
  Command,
  (): Command => ({
    id: "toggle",
    title: ctx.t("command.toggle"),
    keywords: "notes scratch",
    group: ctx.t("command.category.view"),
    section: "terminal",
    bind: "ctrl+`",
    slash: { name: "notes", after: "open" },
    featured: true,
    enabled: !!ctx.sessions.current(),
    run: () => {
      const session = ctx.sessions.current()

      if (session) ctx.layout.toggle(`${ctx.id}:main`, session)
    },
  }),
)
  • title 是面板里的标签，description 是第二行，group 是分类，都以翻译后的文本呈现。
  • keywords 保存面板额外匹配的词，用空格分隔。
  • section 是 Settings > Shortcuts 的分区。默认 general。
  • bind 是默认键位，例如 mod+shift+t。用户可以修改。
  • slash 让命令同时出现在 / 菜单里。带 arguments: true 时，名称后的文本会传给 run(input)。
  • hidden 把命令从面板里藏起来，但它的键位仍然有效。
  • suggested 让命令在启用期间同时列在 Suggested 下；featured 让它在面板无查询打开时列出。
  • enabled: false 把命令从面板里移除并关闭其键位。它是响应式的。
  • scope 是一个 CSS 选择器，键盘焦点必须落在其中键位才生效。带 editable 时，文本框有焦点时绑定也会触发。
  • 要在自己的代码里运行命令，用 ctx.commands.run；见运行命令。

从键位触发时，run 可以返回 false 来拒绝这个按键。事件随后继续流向目标，就像命令没有键位一样。下面这个命令在用户于空提示词里按 Enter 时继续会话，其余的 Enter 都留给输入框：

TypeScript
ctx.add(Command, () => ({
  id: "continue",
  title: ctx.t("command.continue"),
  bind: "enter",
  editable: true,
  hidden: true,
  run: () => {
    const composer = ctx.screen.current()?.composer
    const session = ctx.sessions.current()

    if (!composer?.focused() || composer.text().trim() || !session) return false
    void session.server.client.session.prompt({ sessionID: session.id, text: ctx.t("continue") })
  },
}))
  • 同步返回 false；返回 Promise 表示接管了这个按键。
  • 从面板或斜杠命令返回 false 没有其它效果。

面板（Panels）

Panel 向会话的侧边区域（region: "side"）贡献标签页。用户可以把标签页拖到时间线下方的底部窗格：

TSX
import { Panel, type PanelTab } from "@opencode/plugin/gui"

const mainTab: PanelTab = {
  id: "main",
  get title() {
    return ctx.t("panel.title")
  },
  closable: "compact",
  fallback: true,
}

ctx.add(Panel, {
  id: "main",
  region: "side",
  mobile: {
    get title() {
      return ctx.t("panel.title")
    },
    order: 45,
    kind: "menu",
    icon: "file-tree",
  },
  list: (input) => (input.open.includes("main") ? [mainTab] : []),
  render: (props) => <NotesView session={props.session} screen={props.screen} tab={props.tab} />,
})

面板的所有回调（list、render、focus、enter、close、closed、restore、normalize）都收到一个输入对象：

  • 在使用处把 props.session 和 props.tab 作为响应式 getter 读取。永远不要在 render 顶部解构它们：当用户从会话 A 切到会话 B 时，面板保持挂载，props.session 原地更新。
  • props.screen 是拥有 SessionScreen 的常量（file、comment、composer）。它的动作始终指向被路由的会话。
  • 标签页未变时，list 要返回同一个 PanelTab 对象，宿主就不会重新挂载它的触发器。从 getter 里读标签，这样不用新对象也能跟随语言。

面板的回调：

  • list 返回要展示的标签页。input.open 持有本插件存储在该会话里的标签页 id。它是响应式的。
  • render 渲染一个标签页的内容，仅一次。
  • focus 在标签页被选中时运行。区域初始挂载的那次选中 restored 为 true。
  • enter 在用户用切换按钮在某个标签页上打开侧边区域时、该标签页上屏之后运行。把键盘焦点移到标签页自己的目标上，比如文本框。焦点仍在区域外时，宿主会聚焦该区域。
  • close 在宿主移除标签页之后运行。
  • closed 和 restore 让用户重新打开已关闭的标签页；见重新打开已关闭的标签页。
  • normalize 返回存储标签页 id 的规范形式——当一个 id 有多种存储写法时用。

面板的选项：

  • mobile 添加面板的窄屏视图。带 cached: true 时，用户查看别的视图期间该视图保持挂载。默认每次显示时重新挂载。
  • wide 在侧边区域打开时请求更宽的会话最小宽度。
  • width 给面板一个自己的侧边区域宽度；见面板宽度。
  • transient 面板的标签页不会被恢复。

面板宽度

默认情况下，侧边区域里的所有标签页共享会话的宽度。当你的面板需要比「审查」或「浏览器」更小（或更大）的空间时，设置 width。传 CSS 像素，或用 "narrow" 表示区域的最窄值：

TypeScript
ctx.add(Panel, {
  id: "quota",
  region: "side",
  width: "narrow",
  list: (input) => (input.open.includes("quota") ? [tab] : []),
  render: () => <Quota />,
})
  • 宽度在侧边窗格显示该面板的某个标签页时生效。其它标签页保持会话的宽度。
  • 当用户在该面板的某个标签页上拖动分隔条时，宿主会把那个宽度保存为该面板全应用范围的宽度，替代 width。
  • 宿主保持会话处于其最小宽度，且区域至少 "narrow"。
  • ctx.layout.side.width(panel) 读取保存的宽度，ctx.layout.side.resize(panel, width) 保存一个宽度，效果与拖动相同。保存的宽度对没有 width 的面板也生效。

标签页的选项：

  • id 是标签页 id；其宿主键为 <plugin id>:<id>。title 是其无障碍名称；label 渲染自定义触发内容。
  • pinned 标签页不打开也列出，排在最前，且永远不会被关闭或拖动。
  • draggable 允许用户重排标签页。默认 true。
  • closable 设置关闭按钮的样子："compact"、"hover"，或 false 表示没有。
  • transient 标记一个启动器标签页，比如 Open file，它会被下一次预览替换。
  • fallback 选择加入「存储的选中项缺失时」的回退选择。
  • 同一 group 的标签页共享一个保持挂载的 render。
  • missing 给标签页加删除线，比如文件已不存在时。
  • hidden 让一个被恢复的标签页保持列出、可选中，但不绘制，因为其内容还未知。
  • file 是标签页展示的工作区路径，会作为会话打开的文件之一列出。
  • tabbable 把标签页面板放进 Tab 焦点顺序，适用于没有可聚焦元素的内容。

重新打开已关闭的标签页

宿主为用户关闭的每个侧边标签页保留一条记录。焦点在侧边区域时，⌘⇧T 重新打开最近关闭的一个。侧边区域的 New tab 视图会把带 file 的已关闭标签页列在 Recently closed 下。添加 closed 和 restore 可以控制标签页在那里如何呈现、以及如何回来：

TSX
ctx.add(Panel, {
  id: "page",
  region: "side",
  list: (input) => input.open.map(pageTab),
  render: (props) => <PageView tab={props.tab} />,
  closed: (input) => {
    const url = pages.get(input.tab.id)

    return url ? { icon: "globe", detail: new URL(url).host, data: url } : false
  },
  restore: (input) => {
    if (input.data) openPage(input.session, input.data)
  },
})
  • closed 在用户关闭标签页时运行。此刻就把重新打开所需的东西捕获下来：返回该行如何呈现、以及 restore 需要的 data；标签页回不来时返回 false。
  • title 默认取标签页标题，icon 默认取面板的 mobile 图标。带 file 的标签页显示其文件图标，文件夹作为 detail。
  • 宿主会存储这条记录，所以 data 要保持很小，比如一个 URL。
  • restore 收到被关闭标签页的 id 和 closed 返回的 data。没有 restore 时，宿主按同样的键再次打开。
  • 没有 closed 时，非 transient 的标签页按其标题列出，并在同样的键下重新打开。

Slot 向四个窗口插槽之一渲染 UI：

import { Slot } from "@opencode/plugin/gui"

ctx.add(Slot, {

import { MenuItem } from "@opencode/plugin/gui"

  const session = ctx.sessions.current()

  return {
    menu: "session.panel",
    id: "open",
    title: ctx.t("menu.open"),
    icon: "folder",
    keybind: `${ctx.id}.open`,

  • order 升序排序条目，默认 0。
  • server.row 条目的 run 收到该行的服务器键。when 让条目只在某些行出现；enabled 让它在其它行以禁用态出现。

  • ctx.layout.side.menu() 列出所有插件的 session.panel 条目，供你做自己的启动器；见布局。

输入框药丸（Composer pills）

ComposerPill 在会话输入框上方那一行加一个药丸，与应用的后台工作和待办药丸并排。适合展示「属于用户当前会话」的状态，比如其分支的 pull request。药丸悬浮在时间线之上，所以药丸的出现或消失永远不会改变输入框的尺寸。这一行跟随用户的后台活动对齐方式，且不会出现在子智能体的会话里。

show 返回某个会话的药丸，返回 undefined 表示那个会话不显示。宿主会对每个挂载的输入框运行它，并在它读到的内容变化时再次运行。下面这个插件通过其服务器部分的 RPC 列出每个会话目录的开放 pull request，并把它们显示为一个药丸：

TSX
import { createStore } from "solid-js/store"
import { ComposerPill, createKeyed } from "@opencode/plugin/gui"
import { GitHub, type Pull } from "./rpc"

const [pulls, setPulls] = createStore<Record<string, readonly Pull[]>>({})

createKeyed(
  () => ctx.sessions.current()?.directory,
  (directory) =>
    void ctx.client
      .rpc(GitHub)
      .pulls({ directory })
      .then((list) => setPulls(directory, list)),
)

ctx.add(ComposerPill, {
  id: "pulls",
  show: (input) => {
    const list = pulls[input.session.directory] ?? []

    if (list.length === 0) return undefined

    return {
      icon: "github",
      label: ctx.plural("pulls", list.length),
      tone: list.some((pull) => pull.checks === "failure") ? "danger" : undefined,
      title: ctx.t("pulls.title"),
      rows: list.map((pull) => ({
        id: String(pull.number),
        label: `#${pull.number} ${pull.title}`,
        icon: pull.checks === "failure" ? "circle-x" : "circle-check",
        tone: pull.checks === "failure" ? "danger" : "success",
        detail: pull.branch,
        run: () => ctx.system.openExternal(pull.url),
      })),
    }
  },
})
  • label 是药丸的文本，过长会截断。icon 可选。
  • tone 给图标着色："success"、"warning" 或 "danger"。
  • 应用没有的字形（比如一个会动的状态标记），可以声明自己的图标并传 ctx.icons.<name>。它像其它图标一样接受 tone，只要 show 再次运行它的动画就会继续。
  • rows 让药丸点击后打开一个菜单，标题用 title（没有时用 label）。每行有自己的 icon、tone 和弱化的 detail，选中时运行 run；没有 run 的行只展示。
  • 没有 rows 时，药丸在点击时运行 run。
  • title 也是与 label 不同时的药丸无障碍名称。
  • order 把你的药丸排在其它插件药丸之中，最小者在前。应用自己的药丸在最前。
  • show 抛错只会让你的插件的贡献失败。

代码块（Code blocks）

CodeBlock 把你列出的语言的围栏代码块渲染成自己的 UI，替代高亮源码。适合「画出来比源码更好读」的内容，比如 ```csv 表格或 ```latex 公式：

TSX
import { For } from "solid-js"
import { CodeBlock } from "@opencode/plugin/gui"

ctx.add(CodeBlock, {
  languages: ["csv"],
  render: (props) => {
    const rows = props.code.split("\n").map((line) => line.split(","))

    if (rows.length < 2) return undefined

    return (
      <table>
        <tbody>
          <For each={rows}>
            {(row) => (
              <tr>
                <For each={row}>{(cell) => <td>{cell}</td>}</For>
              </tr>
            )}
          </For>
        </tbody>
      </table>
    )
  },
})
  • languages 与围栏信息串的第一个词（小写）比较：```CSV title="Q3" 匹配 csv。宿主不解析别名，所以你接受的每个名字都要列出。
  • render 收到块的 code、language 和展示它的 session。返回 undefined 或 null 可以保留高亮源码，比如源码解析不了的时候。
  • render 抛错会把错误记录在你的插件名下，该块显示其源码。你的其它贡献继续工作。
  • 多个插件列出同一语言时，第一个贡献者渲染它。你列出 mermaid 时，渲染器也会替换应用自带的 Mermaid 图。

流式（Streaming）

宿主只在块的闭合围栏到达后才渲染。块正在流式输出、或消息停在半块中间时，用户看到的是高亮源码；随后你的 UI 原地替换它。你的 render 永远不会看到半截块。

LinkHandler 打开用户在消息或输入框芯片里点击的本地文件或自定义链接。在 match 返回 true 的处理器里，priority 最高的那个打开链接：

import { LinkHandler } from "@opencode/plugin/gui"

服务器（Servers）

Server 贡献一组服务器连接，比如你的插件在其它机器上启动的服务器：

TypeScript
import { Server } from "@opencode/plugin/gui"

ctx.add(
  Server,
  (): Server => ({
    ready: loaded(),
    entries: machines().map((machine) => ({
      id: machine.id,
      name: machine.name,
      label: "Acme",
      state: machine.url ? "ready" : "starting",
      http: machine.url ? { url: machine.url } : undefined,
    })),
  }),
)
  • 启动会等待每个数据源就绪（ready）。就绪数据源的条目即其完整清单。
  • order 升序排序数据源。
  • 每个条目的键是 <plugin id>:<id>。label 是 name 旁的短徽标。
  • auth 表示服务器在等用户登录；incompatible 表示它运行的版本本应用不支持。
  • listed: false 把条目从应用的服务器列表里隐藏。Settings 仍然显示它。
  • http 是端点，服务器 ready 之后提供。
  • reconnect 重新解析掉线的端点；connect 准备一个未就绪的服务器；remove 在条目被移除前运行。
  • row 渲染服务器的设置行；cover 在服务器未就绪时盖住被路由的会话。
  • row 会收到宿主的状态 Indicator、最新一次 health() 检查，以及该行 server.row 菜单的 Items。它的 remove() 先运行条目的 remove，再关闭服务器的标签页。

布局（Layout）

ctx.layout.open(key, session, options?) 按键打开一个面板标签页，键为 <plugin id>:<tab id>。对未挂载的会话同样有效：

TypeScript
const session = ctx.sessions.current()

if (session) ctx.layout.open(`${ctx.id}:main`, session, { tab: "select", background: true })
  • tab: "open"（默认）在预览槽里选中该标签页；"preview" 把它变成新的预览；"append" 添加但不选中；"select" 添加并选中、保留预览。
  • background: true 在窄屏上保留当前视图并打开侧边区域，适合用户不是从面板发起的动作。
  • close(key, session) 移除标签页并调用其面板的 close。toggle(key, session) 关闭一个可见标签页，否则打开它。
  • hide(key, session) 隐藏展示某个可见标签页的窗格，但不关闭标签页：侧边区域，或用户拖到底部的那个底部窗格。再次打开该标签页会重新显示其窗格。
  • state(key, session) 在标签页不在标签条中时为 "closed"；在标签条中但窗格显示其它标签页时为 "open"；窗格显示它但窗格被隐藏（侧边区域关闭，或底部窗格隐藏）时为 "active"；上屏时为 "visible"。
  • stored(session) 是本插件存储在该会话侧边标签条里的标签页 id。
  • ready() 在存储的布局加载完成后为 true；narrow() 在视口小于 768px 时为 true。
  • side.opened(session) 在侧边区域打开时为 true；side.toggle(session) 打开或关闭它。
  • side.menu() 按 order 列出所有插件的 session.panel 菜单条目，供你做自己的启动器。
  • side.width(panel) 和 side.resize(panel, width) 读取和保存你某个面板的侧边区域宽度；见面板宽度。
  • sidebar.opened() 是所有侧面板共享的内部侧栏偏好。
  • scroll 按会话和键存储滚动偏移。
  • settings(page?) 打开 Settings。project(server, title) 打开项目目录选择器和一个新草稿。
  • draft({ server, directory, prompt }) 在自己的标签页里打开一个新草稿会话，提示词已填好，供用户检查后发送。

const session = ctx.sessions.current()

会话与会话屏幕

ctx.sessions.current() 是被路由的会话，ctx.screen.current() 是它的屏幕。在主页和草稿上两者都是 undefined。在动作处读取它们，永远不要在 setup 里只读一次：

TypeScript
const session = ctx.sessions.current()
const file = ctx.screen.current()?.file

if (session && file) void file.sync("README.md")
  • key 是 <server id>\n<session id>，跨服务器唯一。按它为会话级状态做键。
  • tab 是拥有该会话的 shell 标签页的键。服务器还在创建它时 pending 为 true。
  • directory 是会话的工作区目录；该目录就是项目根时 local 为 true。
  • listedProject 是会话所属的侧栏项目。
  • visit 是每次路由到该会话时的新对象。
  • background 列出会话正在运行的子智能体和 shell 命令。
  • ctx.sessions.list() 返回打开的 shell 标签页里的会话。

  • file.sync(path) 加载一个文件并让服务器监视它的变化。文件标签页关闭时调用 file.unwatch(path)。

附加到输入框（Attach to the composer）

在事件处理器或命令里用 ctx.screen.current()?.composer，把文件、附注（note）或引用（quote）附加到用户的下一条提示词：

TypeScript
const composer = ctx.screen.current()?.composer

composer?.attach({
  type: "note",
  origin: ctx.id,
  commentID: crypto.randomUUID(),
  label: "button#submit",
  icon: "globe",
  subject: 'element <button id="submit">Save</button>',
  comment: "Make this button primary and disable it while saving.",
  href: "http://localhost:3000/settings",
})
  • attach 不改变键盘焦点。调用 focus() 把焦点移到提示词。
  • update(commentID, { comment?, preview? }) 修改一个附加部分；附注或引用只接受新的 comment。
  • detach(commentID) 移除一个附加部分。
  • 附注的 live 会在该附注还留在本应用进程内时替换其 subject 和 href，适用于只有本进程能解析的引用，比如某个页面元素。存储的草稿会丢弃它；被回滚（revert）或分叉（fork）恢复的已发送消息也会丢弃它。

引用是用户从你的插件展示的内容（比如日志输出）里引用的文字，可带一条注释。它像会话时间线里的引用一样渲染，在来源的图标和标签之下。先检查 quotable()：在子智能体的会话里（没有输入框）、以及输入框正在运行 shell 命令时，它是 false：

TypeScript
const composer = ctx.screen.current()?.composer

if (composer?.quotable()) {
  const commentID = crypto.randomUUID()

  composer.attach({
    type: "quote",
    commentID,
    text: selection,
    source: { label: ctx.t("source.label"), icon: "console", subject: "the Acme log" },
  })
  composer.focus(commentID)
}
  • source.subject 是给模型看的来源名称，例如 the terminal。它不做本地化。
  • 省略 comment 可以让用户在芯片上自己添加。
  • focus(commentID) 打开附加引用的注释编辑器。输入框未展示时（比如窄屏上显示的是面板），编辑器会在输入框出现后打开。
  • 模型读到的是 The user quoted the following from <subject>:，然后是每行以 > 为前缀的文本，然后是注释（如有）。

读写提示词

用 text() 读用户输入的内容，用 focused() 判断是否正在输入：

TypeScript
const composer = ctx.screen.current()?.composer
const empty = !composer?.text().trim()
  • text() 是纯文本形式的提示词：一个 mention 读作它的 @ 文本，附件和附加部分不包含在内。shell 模式下它是 shell 命令。会话草稿加载之前、以及没有输入框的子智能体会话里，它是 ""。它是响应式的。
  • focused() 在键盘焦点位于提示词内时为 true。它不是响应式的，所以要在动作处读取，比如命令的 run 里。

insert(text) 把文本打进提示词，供用户检查后发送。输入框上的任何操作都不会替用户发送提示词：

TypeScript
const composer = ctx.screen.current()?.composer

composer?.insert(`Explain ${path}`)
composer?.focus()
  • insert 把文本加在用户上次留在提示词里的光标处（否则加在末尾），并把光标移到其后。它不替换已选中的文本。
  • 文本不会被解析：@path 仍是文本，不是 mention。
  • setText(text) 替换提示词文本（包括 mention）。附件和附加部分保留。setText("") 清空文本。
  • 两者都不改变键盘焦点。调用 focus() 把焦点移到提示词。
  • 会话存储草稿加载之前的写入（insert、setText、attach、update、detach）会等待草稿，然后按调用顺序应用到调用时被路由的那个会话。它永远不会替换存储的草稿。
  • 在子智能体的会话（没有输入框）里，这些写入不做任何事。

选择模型

model() 是下一条提示词将使用的模型；setModel 像模型选择器一样选择一个：

TypeScript
const composer = ctx.screen.current()?.composer

if (composer && !composer.setModel({ providerID: "anthropic", modelID: "claude-sonnet-4-5", variant: "high" })) {
  ctx.toast.show({ variant: "error", title: ctx.t("model.unavailable") })
}
  • model() 是用户为被路由会话做的选择，否则是 agent 的默认值，否则是应用的默认值。模型目录加载中、没有已连提供商提供该模型时、以及子智能体会话里，它是 undefined。它是响应式的。
  • setModel 把该模型设为会话的选择及其最近使用列表的第一位。不带 variant 时，模型保留选择器会为它显示的变体。
  • setVariant(variant) 选择当前模型的一个变体。undefined 选择模型默认变体。
  • 目录加载中、没有已连提供商提供该模型、或模型没有该变体时，setModel 返回 false 且不做任何修改。
  • 没有当前模型或模型没有该变体时，setVariant 返回 false 且不做任何修改。
  • 在子智能体的会话里，两者都返回 false。

服务器与服务器事件

ctx.servers.get(id) 返回一个活性的（live）ServerRef。运行你插件的桌面应用自带服务器的 id 是 "sidecar"。用 data.on 响应它的事件：

TypeScript
import { onCleanup } from "solid-js"

  (data) => onCleanup(data.on("session.created", (event) => console.log(event))),

  • id 是宿主键："sidecar"、一个 http URL，或贡献的服务器的 <plugin id>:<id>。

  • 应用自带服务器 builtin 为 true。

对话框（Dialogs）

ctx.dialogs.open(render, { replace? }) 在已打开的对话框之上打开一个对话框，并返回一个句柄，其 close() 关闭它。拥有它的作用域结束时对话框也会关闭：

TSX
const handle = ctx.dialogs.open((dialog) => <ConfirmDialog onDone={dialog.close} />)
  • replace: true 先关闭所有打开的对话框，包括宿主的和其它插件的。

询问用户（Ask the user）

confirm、alert、prompt 和 select 用应用自己的对话框提问，你的插件不需要自建对话框 UI。每个都返回一个 Promise，兑现为答案：

TypeScript
const ok = await ctx.dialogs.confirm({ title: ctx.t("end.title"), confirm: ctx.t("end"), danger: true })
  • 只有用户确认时 confirm 才以 true 兑现。danger 把确认按钮渲染为破坏性样式，并把初始焦点放在取消按钮上。
  • 每个对话框像 open 一样打开，随提问者关闭，否则随你的插件关闭。
  • 取消、按 Escape、点击外部、被替换，或属主结束，会让 confirm 以 false 兑现，prompt 和 select 以 undefined 兑现。

alert 告知用户一件必须确认的事，只有一个按钮。无论怎么关闭，它都在对话框关闭时兑现：

TypeScript
await ctx.dialogs.alert({ title: ctx.t("export.done"), description: path })

prompt 请求一行文本。初始 value 处于全选状态，所以直接输入会替换它。它永远不会以空字符串兑现：字段为空时提交无效。secret: true 隐藏用户输入的内容，适合密码或 token：

TypeScript
const token = await ctx.dialogs.prompt({ title: ctx.t("token.title"), placeholder: "ghp_…", secret: true })

select 在一个可搜索列表里列出选项（像命令面板那样），兑现为选中项的 value：

TypeScript
const url = await ctx.dialogs.select({
  title: ctx.t("links.title"),
  options: links.map((link) => ({ title: link.title, description: link.url, value: link.url, group: link.host })),
})

if (url) ctx.system.openExternal(url)
  • 搜索匹配每个选项的 title 和 description。
  • 相同 group 的选项在该标题下列在一起。
  • current 是要最先高亮的选项值。

应用组件（App components）

插件 bundle 不能导入 @opencode/ui，所以 ctx.ui 把应用自带的组件给它用。它们以用户的主题、字体和语言渲染，你的插件 UI 看起来、表现起来就像应用的一部分：

TSX
import { Show } from "solid-js"
import { createLatest, Panel } from "@opencode/plugin/gui"

const ui = ctx.ui
const summary = createLatest(
  () => ctx.sessions.current()?.directory,
  (directory, signal) => fetchSummary(directory, signal),
)

ctx.add(Panel, {
  id: "summary",
  region: "side",
  list: () => [summaryTab],
  render: () => (
    <div>
      <ui.Tooltip value={ctx.t("copy")}>
        <ui.IconButton icon="copy" label={ctx.t("copy")} onClick={() => void ctx.system.copy(summary.latest ?? "")} />
      </ui.Tooltip>
      <Show when={summary.latest} fallback={<ui.Loader size="large" />}>
        {(text) => <ui.Markdown text={text()} />}
      </Show>
    </div>
  ),
})
  • Icon、Button、IconButton 接受任意 IconName，与 SDK 的每个 icon 字段一样：应用图标之一，或 ctx.icons 里你自己的图标。IconButton 的 label 是其无障碍名称；包一层 Tooltip 可以在悬停时显示。
  • 按钮的 busy 会把图标换成加载指示并禁用按钮，直到再次为 false。
  • 所有非「AI 工作中」的加载状态都用 Loader，比如面板、搜索或连接加载。
  • Menu 打开一个 items 列表：动作、{ type: "separator" } 和 { type: "group", label, items }。
  • Switch 和 TextInput 不保存状态：把 onChange 或 onInput 收到的值传回 checked 或 value。
  • Keybind 把按键显示成芯片，比如 ctx.keybinds.keybind(command)。
  • Markdown 以时间线渲染消息的方式渲染；Code 展示一个高亮的只读代码块。两者在挂载后不久填入内容。

Dialog 是应用的对话框框架：一个标题、内容和按钮。从 ctx.dialogs.open 里渲染它；在别处它渲染不出有用的东西：

TSX
const ui = ctx.ui

ctx.dialogs.open((dialog) => (
  <ui.Dialog
    title={ctx.t("rename.title")}
    footer={
      <ui.Button variant="contrast" onClick={dialog.close}>
        {ctx.t("done")}
      </ui.Button>
    }
  >
    <ui.TextInput label={ctx.t("rename.label")} value={name()} onInput={setName} onSubmit={dialog.close} autofocus />
  </ui.Dialog>
))
  • size 默认 "fit"：480px 宽、与内容同高。"normal"、"large"、"x-large" 是固定尺寸。
  • Escape 和点击外部会关闭对话框。closable: false 隐藏头部的关闭按钮。

菜单行（Menu rows）

MenuItem、MenuSub、MenuGroup 和 MenuSeparator 是给宿主渲染的菜单（比如 session.location.menu 插槽）用的行。它们支持键盘导航、显示宿主的弱化图标和快捷键芯片，并在选中时关闭菜单：

TSX
import { For } from "solid-js"

const ui = ctx.ui

ctx.add(Slot, {
  at: "session.location.menu",
  render: (input) => (
    <>
      <ui.MenuItem
        label={ctx.t("usage")}

      </ui.MenuSub>
    </>
  ),
})
  • MenuItem 接受与 Menu 的 items 条目相同的字段。
  • MenuSub 在行旁的子菜单里打开它的子节点。onOpenChange 告诉你何时打开，这样你可以只在打开期间加载它的行。
  • MenuGroup 把行放在一个标题下；MenuSeparator 在行之间画一条线。
  • MenuItem、MenuSub、MenuGroup 在菜单之外会抛错：宿主记录错误，该贡献不渲染任何内容。

选择器（Selects）

Select 从一组选项中挑一个，就像应用设置行里选语言那样。它的值是字符串；options 的类型会收窄它：

TSX
const [period, setPeriod] = createSignal<"day" | "month">("day")

    { value: "day", label: ctx.t("period.day") },

  • label 是选择器的无障碍名称；选中项的 label 是它显示的内容。

Toast

ctx.toast.show 在窗口角落显示一条短消息，并返回一个句柄，其 dismiss() 关闭它：

TypeScript
ctx.toast.show({ variant: "success", title: ctx.t("invite.copied") })
  • variant 是 "default"、"success"、"error" 或 "loading"。success toast 默认显示对勾图标，除非你设置了 icon。
  • duration 是 toast 展示的时长，单位毫秒。默认 5 秒。
  • persistent: true 让 toast 一直留到用户或 dismiss() 关闭它，并忽略 duration。
  • 与一个仍在显示的 toast 相同的新 toast 会替换它，而不是叠一份。
  • 你的插件的 toast 会在它停止时关闭，所以没有按钮会活得比运行它的代码更久。toast 不会随展示它的组件或 createKeyed 运行而关闭。

工作运行期间显示一个 loading toast，结束时关掉它：

TypeScript
const saving = ctx.toast.show({ variant: "loading", title: ctx.t("saving"), persistent: true })
await save()
saving.dismiss()

actions 添加按钮。点击会运行该动作并关闭 toast：

TypeScript
ctx.toast.show({
  variant: "error",
  title: ctx.t("sync.failed"),
  actions: [{ label: ctx.t("retry"), run: () => void sync() }],
})

通知（Notifications）

ctx.attention.notify 在用户看向别处时唤起注意：一条系统通知和一个提示音，规则与应用自己的通知相同：

TypeScript
const session = ctx.sessions.current()

if (session) {
  void ctx.attention.notify({
    title: ctx.t("tests.done"),
    message: ctx.t("tests.summary", { failed: 0 }),
    session: { server: session.server.id, id: session.id },
    id: run.id,
  })
}
  • 系统通知只在没有任何应用窗口有焦点时显示。提示音则无论如何都播放。
  • 两者都遵循 Settings > Notifications。variant: "default" 走 Agent 行，variant: "error" 走 Errors 行。两者的桌面通知默认关闭；提示音默认开启。
  • sound: false 永远不播放提示音。
  • 点击通知会把应用带到前台，并在你提供了 session 时打开它。
  • 每个应用窗口都运行插件自己的一份副本。传一个事件 id（比如某次运行的 id），这样只有第一个发送它的窗口会通知并播放声音。不给 id，每次调用都会通知。
  • 应用界面挂载之前，notify 会等待它。

notify 永远不会 reject。它兑现自己做了什么：notification 在应用请求系统显示通知时为 true；sound 在提示音开始播放时为 true：

TypeScript
const result = await ctx.attention.notify({ title: ctx.t("deploy.failed"), variant: "error" })

if (!result.notification) ctx.toast.show({ variant: "error", title: ctx.t("deploy.failed") })
  • notification 为 false 的情况：用户关掉了它、某个应用窗口有焦点、或另一个窗口已经发送过同一个 id。即使应用请求系统显示通知，系统仍可能隐藏它，比如用户拒绝了浏览器的通知权限。

标签页（Tabs）

ctx.tabs 读取和修改 shell 的标签条：以标签页形式打开的会话和草稿。下面代码在某个会话的运行结束时把它的标签页移到最前：

TypeScript
import { onCleanup } from "solid-js"
import { createKeyed } from "@opencode/plugin/gui"

createKeyed(
  () => ctx.servers.get("sidecar")?.data,
  (data) =>
    onCleanup(
      data.on("session.execution.succeeded", (event) => {
        const tab = ctx.tabs.list().find((item) => item.session?.id === event.data.sessionID)

        if (tab) ctx.tabs.move(tab.key, 0)
      }),
    ),
)
  • list() 按标签条顺序返回打开的标签页。它是响应式的。草稿的标签页 session 为 undefined；屏上标签页 active 为 true。
  • open({ server, id }, { focus? }) 把会话作为标签页打开在标签条末尾，除非 focus 为 true，否则在后台打开。已打开的会话保留其标签页；父标签页正在展示的子智能体也一样。
  • focus(key) 展示一个标签页；move(key, index) 移动它；close(key) 像用户那样关闭它。
  • 没有打开标签页持有的键不做任何事。应用界面挂载前的写入会等待它。

存储状态（Stored state）

桌面窗口通过 IPC 加载存储状态，而 Web 端立即读取 localStorage。在 Plugin.define({ stores }) 里声明 store，宿主会替你加载：

  • Store.global——整个应用保存一份值。它在 setup 运行前加载，所以 ctx.stores.name.value 永远不是 undefined。
  • Store.session——每个会话保存一份值。它在会话挂载时加载；在那之前 ctx.stores.name(session).value 是 undefined。

声明的 store 是给窗口用的。main 用 ctx.storage.store 打开自己的状态，它是同步读取的；见主进程上下文。

用 update(draft => …) 原地修改值（必须不返回任何东西），或用 set(next) 整体替换：

const enabled = ctx.stores.prefs.value.enabled

  draft.enabled = !draft.enabled
})
  • ready() 在值加载完成后为 true。在那之前做的写入会等待并按调用顺序应用。
  • from 指定其它存储键，在 store 还没有值时一次性导入，比如你重命名前的 store 的键："plugin.acme.settings"。传一个列表可以按新到旧依次尝试。另一个键保留其副本，直到该 store 被删除。

运行时存储（Runtime stores）

ctx.storage.store(key, options) 为一个只在运行时才知道的键打开 store。scope 可以按服务器、目录或会话各保存一份值：

TSX
import { Schema } from "effect"
import { usePlugin, type MountedSession } from "@opencode/plugin/gui"
import type { definition } from "./definition"

function DraftView(props: { readonly session: MountedSession }) {
  const ctx = usePlugin<typeof definition>()

  const draft = ctx.storage.store("draft", {
    schema: Schema.Struct({ text: Schema.String }),
    initial: { text: "" },
    scope: { server: props.session.server.id, directory: props.session.directory },
  })

  return <p>{draft.value?.text}</p>
}
  • scope: "global"（默认）整个应用保存一份值。
  • scope: { server, directory? } 每个服务器（或其上的每个工作区目录）保存一份值。
  • scope: { session } 每个会话保存一份值；会话移动到新目录时会重新打开。
  • 运行时 store 的 value 在加载之前是 undefined。
  • ctx.storage.memory(key, { initial }) 保存窗口本地的状态，插件重载后仍在，但窗口重载后消失。
  • ctx.storage.remove(key, { scope, from }) 删除值，键随后再次读取为 initial。

响应式原语（Reactive primitives）

优先使用这些辅助函数，而不是原始的 createEffect、createRenderEffect 和 createComputed。它们遵循插件的生命周期及其依赖的重启——手写 effect 往往在这上面出错。

createKeyed

createKeyed(source, fn, { otherwise?, equals? }) 为每个键在全新的属主里运行 fn：ctx.use 访问器的每个活跃代际（generation），或普通访问器的每个值。fn 内注册的一切都随该次运行结束：

TSX
import { onCleanup } from "solid-js"
import { createKeyed, usePlugin, type SessionScreen } from "@opencode/plugin/gui"
import { Changes } from "@opencode/plugin/gui/review"

function ChangedFiles(props: { readonly screen: SessionScreen }) {
  const ctx = usePlugin()

  // Changes 的每个活跃代际都让该视图的变更保持加载；监视随它一起结束。
  createKeyed(ctx.use(Changes), (changes) => onCleanup(changes.watch(props.screen, "files")))

  return <FileMarkers screen={props.screen} />
}
  • otherwise 在源没有键时运行：Live 访问器未激活，或普通访问器的值为 undefined、null、false。
  • equals 决定普通访问器的新值是否算同一个键，从而 fn 不再运行。源每次都构建新对象时用它。Live 访问器永远按代际分键。

主进程（The main process）

在 OpenCode Desktop 上，插件的 main setup 在 Electron 主进程里运行一次，是全应用的单例。它可以完整访问 Node.js 内置模块、electron 和主进程宿主 API。把它传给插件 ./gui-experimental 文件里的 Plugin.define，与窗口 setup 并列或单独使用：

src/gui.tsxTypeScript · TSX
import { Schema } from "effect"
import { powerSaveBlocker } from "electron"
import { Plugin } from "@opencode/plugin/gui"
import { KeepAwake } from "./gui/contract"

export default Plugin.define({
  main(ctx) {
    const stored = ctx.storage.store("keepScreenActive", { schema: Schema.Boolean, initial: false })
    let blockerId: number | undefined

    const release = () => {
      if (blockerId === undefined) return
      powerSaveBlocker.stop(blockerId)
      blockerId = undefined
    }

    const setActive = (enabled: boolean) => {
      if (enabled && blockerId === undefined) blockerId = powerSaveBlocker.start("prevent-display-sleep")
      if (!enabled) release()
      stored.set(enabled)
    }

    if (stored.value) setActive(true)

    ctx.provide(KeepAwake, {
      screenActive: () => blockerId !== undefined && powerSaveBlocker.isStarted(blockerId),
      setScreenActive: (enabled) => setActive(enabled),
    })

    return release
  },
})

在窗口里，electron 是惰性占位符，所以在共享的 ./gui-experimental 文件里导入它是安全的。见一个文件，两个进程。

主进程上下文（Main context）

main 收到一个 MainContext。与窗口 setup 不同，main 可以是 async，并且可以返回（或兑现为）一个清理函数：

  ctx.log.write("info", "acme started", { version: ctx.app.version })

定义并提供 Ipc

一个 Ipc 规格可以声明每窗口的 state、可调用的 methods、和推送的 events。Effect Schema 校验并编码所有跨桥的值：

src/gui/contract.tsTypeScript
import { Schema } from "effect"

  id: "acme.counter",

    increment: {
      input: Schema.Number,
      output: Schema.Number,

    reset: {},
  },
  events: {
    overflow: Schema.Struct({ limit: Schema.Number }),

在 main 中实现提供方

每个方法收到解码后的输入和一个 Caller（{ window, signal }）。state 变化时调用 provider.changed(window?) 把新快照推给订阅的窗口；用 provider.emit(name, payload, window?) 发送事件：

src/gui/main.tsTypeScript
import type { Plugin } from "@opencode/plugin/gui"
import { Counter } from "./contract"

export const main: Plugin.MainSetup = (ctx) => {
  const counts = new Map<number, number>()

  const provider = ctx.provide(Counter, {
    state: (window: number) => ({ count: counts.get(window) ?? 0 }),
    increment: (step, caller) => {
      const next = (counts.get(caller.window) ?? 0) + step
      counts.set(caller.window, next)
      provider.changed(caller.window)

      if (next > 100) provider.emit("overflow", { limit: 100 }, caller.window)

      return next
    },
    reset: (_input, caller) => {
      counts.set(caller.window, 0)
      provider.changed(caller.window)
    },
  })
}
  • 带 state 的规格在实现里也需要 state(window)。主进程在窗口订阅时以及每次 changed 时读取它。
  • 抛错的方法会让窗口那次调用 reject。
  • 省略 window 时，changed 和 emit 到达每个窗口。
  • dispose() 提前撤回该 Ipc。窗口看到它处于 pending，ctx.main 的调用等待，直到插件再次提供或停止。宿主也会在插件停止时撤回它。

在窗口中使用 Ipc

在窗口里，ctx.main(Counter) 返回你的 main 提供的该 Ipc 的客户端。没有 input schema 的方法只接受可选的 { signal } 调用选项，不要把 undefined 当第一个参数传：

src/gui/window.tsxTypeScript · TSX
import { Command, type Plugin } from "@opencode/plugin/gui"
import { Counter } from "./contract"
import type { definition } from "./definition"

export const setup: Plugin.Setup<typeof definition> = (ctx) => {
  const counter = ctx.main(Counter)

  // 跨重启跟随 main；插件停止时移除。
  counter.on("overflow", (data) => console.log(`Counter exceeded ${data.limit}`))

  ctx.add(Command, () => ({
    id: "increment",
    title: ctx.t("command.increment"),
    enabled: ctx.app.platform === "desktop",
    run: async () => {
      await counter.increment(1, { signal: ctx.signal })
      await counter.reset({ signal: ctx.signal })
    },
  }))
}
  • 调用在 main 启动期间等待。main 无法应答时会 reject：在 Web 上（插件的 main 不在或失败），或方法抛错时。在用户需要反馈的地方接住这个拒绝。
  • state() 和 on() 跨重启跟随 main。监听器随当前属主结束，否则随插件结束。
  • ctx.main 对同一个 token 每次调用返回同一个客户端。

活性依赖与失败处理

ctx.use(token) 返回一个响应式 Live<T> 的访问器：提供该 token 的插件的状态。提供方不在线时你的插件继续运行，所以要处理非 active 的状态。任何控件都不应该死掉，任何加载指示都不应该永远转下去：

TypeScript
import { Browser } from "@opencode/plugin/gui/browser"

const browser = ctx.use(Browser)

ctx.add(Command, () => {
  const live = browser()
  const session = ctx.sessions.current()

  return {
    id: "preview",
    title: ctx.t("command.preview"),
    enabled: live.status === "active" && !!session,
    run: () => {
      if (live.status === "active" && session) live.value.open(session, "http://localhost:3000")
    },
  }
})
  • pending：提供方还没启动，比如它的插件正在加载或重启。展示加载态，或隐藏可选控件。
  • active：提供方在运行，value 是它的契约或 Ipc 客户端。generation 计数激活次数，重启过的提供方会带着新的计数回来。
  • inactive, disabled：提供方被关闭、不存在、或在该平台不可用——Web 上所有 Ipc 都如此。展示不可用态，或省掉控件。
  • inactive, failed：提供方的 setup 抛了错。展示不可用态。
  • 你自己的 main 没有 Live 状态。通过 ctx.main 的调用在它启动期间等待，无法应答时 reject。

生命周期与清理

通过 ctx 注册的一切（ctx.add、ctx.provide、ctx.dialogs.open、ctx.embeds.create 以及 Ipc 事件监听器）都会在所属作用域结束时被撤回：

  • 在组件或 createKeyed 回调里，注册在该组件或 createKeyed 运行销毁时结束。
  • 在 setup 顶层，注册在插件被禁用、重载、移除，或其窗口关闭时结束。
  • 在 main 里，注册在插件被禁用、重载、移除，或应用退出时结束。embed 还会在其窗口关闭时结束。

其它资源（比如定时器或 socket），从 setup 返回一个清理函数。它与上面的撤回同时发生：

  • 窗口 setup不能是 async，因为它运行在 Solid 属主之下。返回一个清理函数，或用 onCleanup 或 ctx.signal。
  • main可以是 async。返回（或兑现为）一个清理函数，或用 ctx.onCleanup(fn)。

窗口 setup

窗口 setup 必须是同步的。在 createKeyed 或 createLatest 里启动异步工作：

src/gui.tsxTypeScript · TSX
import { Command, createKeyed, Plugin } from "@opencode/plugin/gui"
import { Changes } from "@opencode/plugin/gui/review"

export default Plugin.define({
  i18n: { en: { changes: "Show changes" } },
  setup(ctx) {
    // 对 Changes 的每个活跃代际运行一次；命令随它一起撤回。
    createKeyed(ctx.use(Changes), (changes) => {
      ctx.add(Command, () => ({
        id: "changes",
        title: ctx.t("changes"),
        run: () => {
          const session = ctx.sessions.current()

          if (session) changes.open(session)
        },
      }))
    })

    const timer = setInterval(() => console.log("still here"), 60_000)

    return () => clearInterval(timer)
  },
})

主进程 setup

main 可以是 async。为它打开的资源返回（或兑现为）一个清理函数，或用 ctx.onCleanup(fn) 注册：

TypeScript
async main(ctx) {
  const socket = await connect(ctx.options)

  ctx.onCleanup(() => socket.close())
}
  • ctx.onCleanup 在插件被禁用、重载、移除或应用退出时运行其函数，后注册的先运行。插件已经不在时，它会立即运行该函数。
  • await 之后，在注册或修改任何东西之前，先检查 ctx.signal 是否已中止并提前返回。
  • 异步清理会把退出延迟到它完成，最多 3 秒。

🧠 通俗理解

GUI 插件的「所有权」模型一句话概括：谁注册，谁的作用域结束谁收回。你在 setup 顶层注册的东西活得和插件一样长；在组件或 createKeyed 里注册的东西只活到那次运行结束。这套模型让你几乎不用手写「取消订阅」——但定时器、socket 这类 ctx 不知道的资源仍要自己返回清理函数。
