插件

插件（Plugin）可以给 OpenCode 加工具、钩子、集成、命令和智能体。已发布的 npm 包、带版本号的包、scoped 包或本地插件目录，都可以加进 opencode.json(c)。

🧠 通俗理解

如果说 MCP 是「外接工具的 USB 标准」，插件就更像「给智能体刷固件」：它能在 OpenCode 内部流程的各个钩子点（hook）上插手——比如「每次写完文件自动 lint」「聊天前先注入一段提示」「给桌面端加一个新面板」。MCP 解决的是「让 AI 多几只手」，插件解决的是「改变 AI 的行为习惯」。

配置

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}

相对路径从包含该条目的配置文件所在目录解析。

配置里的本地路径必须是目录；指向单个文件的路径会被跳过。OpenCode 如何在一个目录里找到各个部分，见插件总览的加载机制说明。

来自各适用配置文件的插件数组按「从低到高」的优先级依次叠加应用，而不是互相替换：

text
~/.config/opencode/opencode.jsonc
./opencode.jsonc
./.opencode/opencode.jsonc

发现机制

除了配置，OpenCode 还会自动从每个被发现的 .opencode/plugins/ 目录里，加载直接的 .ts 和 .js 文件，以及紧邻的插件包目录：

text
.opencode/
└── plugins/
    ├── concise.ts
    ├── reviewer.js
    └── acme-package/

全局插件使用相同的发现布局，位置在 OpenCode 配置目录下：

text
~/.config/opencode/plugins/

⚠️ 注意

与项目根目录 opencode.json(c) 并排的 plugins/ 目录不会被自动发现。要么在配置里显式写出这些插件目录，要么把它们挪到 .opencode/ 下面：

opencode.jsonc
{
  "plugins": ["./plugins/local"]
}

启用与禁用

插件条目按顺序处理。在 ID 或通配符前加 - 表示禁用；* 匹配所有插件；.* 匹配 ID 前缀。后面的 ID 会重新启用插件。

opencode.jsonc
{
  "plugins": ["*", "-opencode.provider.*", "opencode.provider.openai", "-acme.reviewer"]
}

要关掉「新 fork 加提示公告」这个行为，在 plugins 里加上 "-opencode.fork-notice"。

💡 扩展

有两个内置插件无视禁用指令，这样仓库自身就无法关掉策略（policy）强制：opencode.config.policy 和 opencode.provider.opencode（后者是交付组织策略的 Console 连接）。这是刻意设计——企业策略如果允许被项目里的配置文件一改就绕过，那就形同虚设。

管理

用 CLI 安装、列出、检查、更新或删除全局包插件：

bash
opencode plugin add opencode-acme-plugin@1.2.0
opencode plugin list
opencode plugin list --builtin
opencode plugin check
opencode plugin update
opencode plugin update opencode-acme-plugin
opencode plugin remove opencode-acme-plugin@1.2.0

plugin check 检查 server、仅 GUI、仅 TUI 这三类包插件的更新。plugin update 更新所有过期的包；传入已配置的包目标则只检查或更新该包。本地插件和锁定了精确版本的包会被跳过。

包安装接受带版本、tag 或范围的 npm 名称，以及与 npm 兼容的 Git 包规格。Git 仓库可以用托管平台简写、HTTPS 或 SSH，包括用你现有 Git 凭证可访问的私有仓库：

bash
opencode plugin add @acme/opencode-plugin@latest
opencode plugin add github:acme/opencode-plugin
opencode plugin add git+ssh://git@github.com/acme/opencode-plugin.git#main
opencode plugin add 'github:acme/plugins#main::path:packages/opencode-plugin'

支持分支、tag、完整 commit 哈希，以及 npm 的 ::path: 仓库子目录选择器。本地路径直接写进配置；plugin add 不接受 tarball 和 npm alias 形式的目标。

热重载

被监听的配置目录下的改动会自动重载。服务器启动时立即加载已缓存的包插件，在后台安装缺失的包，并对未锁定版本的 npm 和 Git 插件检查更新（不改动已安装的包）。精确的 npm 版本和完整 Git commit 哈希保持锁定。未被监听的本地依赖有改动时，可能仍需重启 OpenCode：

bash
touch .opencode/plugins/concise/index.ts
opencode service restart

桌面端

导出 ./gui-experimental 的插件还能给 OpenCode Desktop 添加面板、命令或设置。应用从它运行的服务器加载插件，所以想在每个窗口里都用某个插件，就把它配进全局 opencode.json(c)：

~/.config/opencode/opencode.jsonc
{
  "plugins": ["opencode-acme-plugin"],
}

Settings > Extensions > Plugins 在选中应用自带服务器时会列出它们。某个插件的开关只关闭它的桌面 UI，Reload 可以在失败后重新加载。要整个关掉插件，在 plugins 里加 - 和它的 ID，例如 "-acme"。

终端端

仅 TUI 的插件单独配置，且在连接远程服务器时依然生效：

cli.json
{
  "plugins": ["opencode-acme-cli"]
}
