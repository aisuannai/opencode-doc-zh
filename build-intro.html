构建总览

每天有数百万人使用 OpenCode。在它之上构建你自己的应用、集成和智能体体验，不必从零开始。

这一页是「构建与集成」章节的总览：OpenCode 提供三条扩展路径，覆盖从「稍微加点功能」到「整个产品嵌入它」的全部需求。

🧠 通俗理解

把 OpenCode 想象成一栋带水电煤的毛坯房：插件（Plugin）是不动承重墙的装修——加工具、加命令、改行为，但主体还是 OpenCode；服务器模式（Server）是只租这栋房子——通过客户端连上 OpenCode 服务端，TUI 和桌面应用用的就是同一个客户端，你可以围着它盖任何界面；嵌入（SDK）是把整栋房子买下来放进你的地皮——把 OpenCode 直接嵌进你的应用里，做一个完全自定义的智能体产品。

三条路径

  • 扩展 OpenCode——编写插件，添加工具、集成、命令、agents 和自定义行为，同时保持 OpenCode 其余部分原封不动。
  • 把它跑成服务器——用与 TUI 和桌面应用完全相同的客户端连接 OpenCode，然后在它之上构建任何界面、工作流或智能体体验。
  • 把它嵌入应用——将 OpenCode 直接嵌入你的应用程序，围绕它构建一个完全自定义的智能体、界面或开发者产品。

Effect API

除了标准 JavaScript/TypeScript API 之外，OpenCode 还为三块内容提供了 Effect 风格的 API，适合已经采用 Effect 生态的团队：

  • Effect 插件——用 Effect 编写服务器插件；
  • Effect 客户端——用 Effect 连接 OpenCode 服务器；
  • Effect SDK——用 Effect 嵌入 OpenCode。

💡 扩展

Effect 是一个 TypeScript 的函数式运行时框架，特点是强类型错误处理和结构化并发。如果你没接触过 Effect，完全不用慌——本站每一对页面（如客户端与 Effect 客户端）讲的都是同一个功能，Effect 版只是 API 风格不同，先读非 Effect 版就够了。

💡 扩展

按目的选入口：只想「让 OpenCode 多会点本事」→ 从插件总览读起；想做「围绕 OpenCode 会话的前端/自动化」→ 从客户端 (JS) 读起，能直接对接 HTTP API；想把「智能体能力做成产品卖点」→ 从 SDK 读起，Cloudflare 部署见 Cloudflare SDK。
