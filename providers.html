Providers

OpenCode 内置了来自 models.dev 的提供商（Provider）与模型目录。大多数提供商只需先连接账号，再选择模型。

🧠 通俗理解

OpenCode 本身不带模型，它更像一个「万能插线板」：OpenAI、Anthropic、Google、Azure、Bedrock、Ollama……各家 API 规格不同，OpenCode 把它们都翻译成自己统一的一套。你只需要提供「插头」（API key 或登录）和「插座地址」（endpoint），剩下的请求格式、重试、超时都由它打理。

快速设置

运行 /connect，选择一个提供商，输入凭证。然后运行 /models 选择它的一个模型。

text
/connect
/models

OpenCode Go

OpenCode Go 是可选订阅，提供经过 OpenCode 团队实测的编码模型。在 Console 里订阅，复制 API key，然后以 OpenCode Go 名义连接：

text
/connect
# Select OpenCode Go, then paste your API key.
/models

用量限制、端点和隐私细节见 Go 订阅指南。

ChatGPT

可以用 ChatGPT Plus 或 Pro 订阅代替 OpenAI API key。连接 OpenAI，然后选择 Sign in with ChatGPT 或某个旧版 Codex 登录方式。用量计入你的订阅额度，所以这些模型不显示费用。

text
/connect
/models

上下文限制

默认情况下，OpenCode 会把这类登录的上下文窗口限制在每个模型真实上限以下。这些上限与 Codex 的默认值一致，因此你的订阅用量消耗速度与在其它 OpenAI 产品里相似。

模型输入上限
GPT-6.1 Sol 及更新500,000
更早的模型272,000

想退出这个限制，在配置里禁用 cap 插件。- 前缀只关闭这一个内置插件，其余插件保持启用：

opencode.jsonc
{
  "plugins": ["-opencode.provider.openai-context-caps"],
}

自定义提供商

当某个 API 不在目录里时，添加一个提供商。下面的 OpenAI 兼容示例一次性定义了凭证、运行时包、端点和第一个模型：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}

providers 对象以提供商 ID 为键，模型引用里会用它，例如 acme/qwen3-coder。

字段用途
name显示名称。
env可提供凭证的环境变量名，按顺序尝试。
package运行时提供商包。
canonical要继承其目录默认值的内置提供商 ID。
compatibility该提供商所有模型共享的 API 怪癖。见 模型的兼容性一节。
settingsOpenCode 的类型化控制项，以及传给运行时包的 JSON 选项。
headers附加到请求的字符串 HTTP 头。
body合并进请求体的 JSON 字段。
models要添加或覆盖的模型，以 OpenCode 模型 ID 为键。

端点

覆盖 settings.baseURL 可以让目录里的提供商走代理或兼容端点。它原有的包、模型和连接设置仍然生效：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}

settings 是随包而定的：只有所选包支持的字段才会生效。

请求定制

用 headers 附加 HTTP 头，用 body 把 JSON 字段合并进每个请求体：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}

只有部分流量需要覆盖时，这两个字段也可以设在模型或变体（variant）上：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}

超时

HTTP 请求等待响应头最长 5 分钟，两个流式响应块之间最长等 15 分钟。设置提供商的 settings.headerTimeout 或 settings.chunkTimeout（毫秒数）可以调整限制，设为 false 则禁用。settings.timeout 额外限制整个请求从发出到响应完成的全过程，没有默认值。这些配置是提供商级的，不区分模型或变体。在 WebSocket 传输上，chunkTimeout 限制的是帧间隔，默认 30 分钟。

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}

超过任一限制的请求以传输错误失败。OpenCode 对超时请求最多重试 3 次，然后放弃。

请求编码

settings.encoding 用 "zstd" 或 "gzip" 压缩 HTTP 请求体，用 "none" 发送纯 JSON。它可以设在提供商、模型或变体上，取最具体的那个值。只开启端点能解码的编码：大多数提供商和网关会拒绝压缩请求体。用 ChatGPT 登录且未配置自定义 baseURL 时，OpenAI 默认 "zstd"；API key 则发纯 JSON。WebSocket 消息不受影响。

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}

模型

在提供商的 models 映射里添加或覆盖模型。映射的键是 OpenCode 使用的模型 ID；modelID 则改变发送给提供商的 ID。

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Coding",
        },
      },
    },
  },
}
字段用途
modelID发送给提供商的模型或部署 ID。
name显示名称。
family模型家族，用于把相关模型分组。
type模型产出什么，如 chat、image 或 decision。默认 chat；只有 chat 模型可用于会话。
releaseDate发布日期，格式 YYYY-MM-DD 或 YYYY-MM。
package该模型的运行时覆盖。
settings模型级 OpenCode 控制项和包专属 JSON 设置。
headers额外的字符串请求头。
body额外的 JSON 请求体字段。
capabilities工具支持、可接受的输入输出媒体类型、温度支持与推理控制。
compatibility该模型的 API 怪癖，覆盖提供商的设置。见 模型的兼容性一节。
variants具名变体，各有自己的 settings、headers 和 body。
cost每百万 token 的输入、输出及可选缓存价格。
limit上下文、输入和输出 token 上限。
disabled为 true 时从选择列表移除该模型。

模型的选择方式、默认值、能力、限制、成本和变体，见 模型一章。

Azure

Azure 的标准目录端点除了凭证外还需要资源名称。先设置一次 settings.resourceName，然后连接 API key，或按 连接模型里描述的方式使用 Azure CLI 的 Microsoft Entra ID 会话：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}

在 Azure 门户或 Microsoft Foundry 里可以找到 Resource name。它也是 https://my-models.openai.azure.com/ 和 https://my-models.services.ai.azure.com/ 这类端点的第一段：

bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table

要使用 Entra ID，安装 Azure CLI、登录，然后在连接 Azure 时选择 Microsoft Entra ID (Azure CLI)：

bash
az login

如果配置和环境变量都没有提供资源名称，连接时会提示输入。连接时保存的资源名优先于配置；想改就重新连接。

Azure CLI 连接使用 Azure CLI 里选中的账号。资源在另一个租户或订阅下时，要显式选择两者：

bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID

也可以不用配置，由 AZURE_RESOURCE_NAME 给 OpenCode 服务器提供资源名。旧变量 AZURE_COGNITIVE_SERVICES_RESOURCE_NAME 同样有效。

部署（Deployments）

Azure 只通过部署（deployment）来提供模型，所以 OpenCode 会列出你资源里的部署，并显示这些而不是整个 Azure 目录。列表在启动后、连接后、切换账号后于后台加载。想用到后加的部署，重启 OpenCode 或重新连接。

  • 在列表加载完成前（或加载失败时），整个目录仍然可用。
  • 同一连接的重载失败时，会保留上次的完整清单。
  • 切换账号绝不显示前一个账号的清单；新账号从整个目录开始。
  • 部署继承其目录模型的限制、成本和能力。

部署名就是它的模型 ID，小写（因为 Azure 忽略名称大小写），例如 azure/gpt-production。以模型命名的部署（如 gpt-6-luna）保留目录 ID。这些 ID 在其它部署增删时保持稳定。

OpenCode 按部署的模型把它匹配到目录；当 Azure 的模型拼写不同（比如用 gpt-4 表示 GPT-4 Turbo）时，按名称匹配。以另一个模型命名的部署（如部署 gpt-6.1-sol 跑的是 gpt-6-luna），会显示那个模型的名字、限制和成本。

使用 Azure CLI 时，OpenCode 通过 Azure 管理 API 列出部署，这需要资源的读取权限。如果失败——以及在使用 API key 时——它会使用资源的旧版部署清单。发现过程会先读完所有分页再发布列表。自定义 settings.baseURL 会保留整个目录。

模型不在目录里（比如微调模型）时，或想自己把模型 ID 映射到部署时，显式配置一个部署。OpenCode 会记录一条警告点名这类部署。显式配置的模型始终保留：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-6-luna": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}

你的身份需要以下角色之一：

  • Cognitive Services OpenAI User：使用 Azure OpenAI 模型。
  • Cognitive Services User：使用其它 Foundry 模型。

如果请求用了错误租户的 token，用所需租户重新登录：

bash
az login --tenant TENANT_ID

Bedrock

Amazon Bedrock 使用 AWS 默认凭证链。命名的 AWS profile 是最省事的持久配置；OpenCode 也识别访问密钥环境变量、web identity 和容器凭证：

bash
aws configure sso --profile work
aws sso login --profile work

在提供商设置里选择 profile 和 region。配置了 profile、AWS_PROFILE、AWS_ACCESS_KEY_ID、web identity token 文件或容器凭证 URI 才会激活该提供商；只有 region 不会。

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}

未显式指定 region 时，OpenCode 依次使用 AWS_REGION、AWS_DEFAULT_REGION，然后是 us-east-1。私有或 VPC 端点，设置 baseURL 并保持相同的 profile 和 region：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}

Bedrock API key 用 AWS_BEARER_TOKEN_BEDROCK。其它 AWS 变量用于 SigV4 签名，不会被当作 OpenCode 的 API-key 账号存储。

Vertex

Google Vertex 使用应用默认凭证（Application Default Credentials，ADC），并且需要先有项目，它的模型才会出现。先创建本地 ADC，然后在提供商设置里设置项目和位置：

bash
gcloud auth application-default login
opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}

OpenCode 也按顺序从 GOOGLE_VERTEX_PROJECT、GOOGLE_CLOUD_PROJECT、GCP_PROJECT、GCLOUD_PROJECT 解析项目；从 GOOGLE_VERTEX_LOCATION、GOOGLE_CLOUD_LOCATION、VERTEX_LOCATION 解析位置，默认 us-central1。

bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone

服务账号走同样的 ADC 路径。把 GOOGLE_APPLICATION_CREDENTIALS 指向服务账号 JSON 文件，并仍然通过设置或上面的项目变量提供项目：

bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone

Gemini、Anthropic 以及 OpenAI 兼容的 Vertex 目录模型统一用 google-vertex 这一个提供商 ID。旧的 google-vertex-anthropic 提供商 ID 在 V2 里已不可用。

Copilot

GitHub Copilot 支持设备 OAuth，而不是手动输入 API key。连接 GitHub Copilot，选择 GitHub.com 或 GitHub Enterprise，完成设备流程，然后打开 /models：

text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models

GitHub Enterprise 要在提示时输入部署 URL 或域名。OpenCode 优先使用 GitHub 返回的 Copilot API 端点；否则从企业域名推导：

text
company.ghe.com

连接的账号需要有 Copilot Chat 权限。如果 GitHub 显示没有授权，先注册 Copilot Free 或让组织分配一个 Copilot 席位，再重新连接。OpenCode 会在登录后以及活动 Copilot 账号变化时拉取该账号当前的模型列表。

Ollama

启动 Ollama 并拉取一个模型。OpenCode 会探测 http://127.0.0.1:11434，发现补全（completion）模型，并自动加进 /models，无需连接账号：

bash
ollama serve
ollama pull qwen3:8b

用 settings.baseURL 把 OpenCode 指向远程或代理的 Ollama 服务器。要包含 /v1；OpenCode 会从它推导出原生的 /api/tags 和 /api/show 发现路径。apiKey 可选，会作为 bearer token 发给发现和模型请求：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}

发现结果会定期刷新，临时故障期间保留上一次成功的清单。纯嵌入（embedding）模型不会出现，因为 OpenCode 只添加 Ollama 元数据里带 completion 能力的模型。

本地运行时

LM Studio 和 vLLM 也内置了本地发现。它们的默认端点分别是 http://127.0.0.1:1234/v1 和 http://127.0.0.1:8000/v1：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}

LM Studio 从 /api/v1/models 发现语言模型。vLLM 先检查 /health 再读 /v1/models；它的发现无法推断工具支持，所以发现的 vLLM 模型默认禁用工具。其它 OpenAI 兼容运行时，用上面的「自定义提供商」配方并显式列出它的模型。

网关

OpenRouter 使用原生运行时和目录。给 OpenCode 服务器提供 OPENROUTER_API_KEY 或连接 OpenRouter 账号，然后用提供商前缀之后的完整 OpenRouter 模型 ID 引用模型：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-5.5",
}

覆盖它的端点、或经由 OpenRouter 兼容网关路由时，保留原生 OpenRouter 包，这样能保住 OpenRouter 的请求和推理行为：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}

暴露 OpenAI 兼容 API、但有自己模型清单的网关，请定义一个自定义提供商。配置键变成提供商前缀，每个 models 键变成可选的模型 ID：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}

报错排查

提供商和模型的报错通常会指明失败阶段。改包之前，先检查服务器进程环境和确切的模型 ID。

报错或症状检查
No model is available for session ...当前没有任何可选的已启用模型。先完成该提供商的专属设置，再在 /models 里选模型。
Model unavailable: provider/model提供商未激活、模型 ID 不存在或被禁用、或动态发现不再返回它。自定义别名要检查 models 映射的键，而不是 modelID。
Cannot initialize provider/model: NAME is required to resolve the provider endpointbaseURL 里还留着 ${NAME} 占位符。给 OpenCode 服务器设置该变量，或把模板换成完整端点。
Azure resource name is missing设置 providers.azure.settings.resourceName、AZURE_RESOURCE_NAME，或一个完整的 settings.baseURL。
Vertex 没出现在提供商设置或支持的项目变量里设置一个可解析的项目。只有 ADC 不会激活提供商。
Bedrock 没出现提供 profile 或其它受支持的 AWS 凭证链输入。AWS_REGION 本身只选区域。
Ollama 没有模型确认服务器在从 baseURL 推导的路径上暴露 /api/tags 和 /api/show，且 /api/show 报告了 completion 能力。
Copilot 没有模型确认活动的 OAuth 账号有 Copilot Chat 权限。模型同步失败会记录为 failed to sync GitHub Copilot models。

⚠️ 注意

V2 拒绝已退役的提供商 ID 并给出直接替代：用 azure/<model> 替代 azure-cognitive-services/<model>，用 google-vertex/<model> 替代 google-vertex-anthropic/<model>。从 V1 迁移的老配置尤其容易踩这个坑，见 从 V1 迁移。

WebSocket

OpenAI、xAI 和受支持的 Azure Responses 模型可以每个会话保持一条 WebSocket 连接。连续的步骤复用未变化的请求前缀，只发送上一次响应之后新增的内容，减少长会话里的上传量。

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}

WebSocket 行为遵循这些规则：

  • 内置提供商按自己的策略把受支持的路由加入 WebSocket。
  • 提供商的 settings.transport: "websocket" 启用；"http" 禁用。
  • 对没有 WebSocket 通道的路由设 "websocket" 会记录警告并退回 HTTP。
  • OpenAI 提供商的上下文压缩（compaction）使用同一条连接。
  • xAI 只从已存储的响应继续。默认 store: false 时，每个步骤通过复用连接全量发送。
  • 关闭的套接字在下一步重连。如果连不上，会话改用 HTTP 继续。
  • 带 http.request 或 http.response 钩子的提供商插件会保持在 HTTP 上，保证每个请求都可被观测。
