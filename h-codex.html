Harness · Codex

Codex 讲的是 OpenAI Responses API。把它指向 Console，就能使用任何付费模型或 Go 模型——包括 Claude、Gemini 和开源模型。对于不接受 Responses 协议的模型，Console 会自动做协议翻译。

💡 扩展

Console CLI 可以一条命令完成 Codex 的接入，并附带工作区的策略（policies）、MCP 服务器、Skills 和指令文件：npx @opencode/console setup codex。本文其余部分讲的是手动配置的步骤。

配置（Configure）

在 ~/.codex/config.toml 里把 Console 添加为一个模型提供商（model provider），并设为默认：

~/.codex/config.toml按量付费
model = "gpt-6.1-sol"
model_provider = "opencode"

[model_providers.opencode]
name = "OpenCode Console"
base_url = "https://opencode.ai/inference/openai/v1"
env_key = "OPENCODE_API_KEY"
wire_api = "responses"

Codex 会在 base URL 后面自动拼接 /responses，并从 env_key 指定的环境变量读取 key。先创建一个个人 API key，再导出它：

bash
export OPENCODE_API_KEY="oc_sk_..."
codex

⚠️ 注意

Codex 只从 ~/.codex/config.toml 读取模型提供商配置。项目里的 .codex/config.toml 不能设置提供商——所以别费劲在仓库里放一份供应商配置，它不会生效。想换工作区或套餐，改的永远是用户目录下的那份文件。

Go 订阅

使用 Go 的 base URL，以及来自订阅了 Go 的工作区的 key：

~/.codex/config.tomlGo 订阅
model = "kimi-k3"
model_provider = "opencode-go"

[model_providers.opencode-go]
name = "OpenCode Go"
base_url = "https://opencode.ai/inference/go/openai/v1"
env_key = "OPENCODE_API_KEY"
wire_api = "responses"

模型（Models）

把 model 设为 Console 或 Go 端点表里的任何模型 ID。单次运行时可以用 --model 覆盖：

bash单次运行换模型
codex --model claude-sonnet-5-5

🧠 通俗理解

用非 OpenAI 模型时，Codex 会打一条警告：「不认识这个模型」。这是因为 Codex 只了解自家目录里模型的上下文窗口和推理设置，对其它模型只能套用一组通用默认值。这只是提醒，可以无视——实际推理请求由 Console 兜底翻译，不影响使用。

Profiles（配置档）

用 profile 可以让按量付费和 Go 并存、随时切换。先在 ~/.codex/config.toml 里定义两个提供商，再加一个切到 Go 的 profile 文件：

~/.codex/go.config.tomlGo 配置档
model = "kimi-k3"
model_provider = "opencode-go"
bash用 go 档启动
codex --profile go

💡 扩展

profile 的实用场景：白天用工作区额度跑重活（按量付费），跑个人小项目时切到 Go 订阅的套餐限额，账目互不干扰。两个提供商都定义在同一个 config.toml 里，profile 文件只负责「选哪个 + 默认用什么模型」，非常轻量。

Console MCP

添加 Console MCP 服务器，并在浏览器中完成登录：

bash
codex mcp add opencode-console --url https://opencode.ai/console/mcp

如果登录没有自动启动，手动运行：

bash手动触发登录
codex mcp login opencode-console
