连接模型

在 TUI 里运行 /connect 连接一个提供商（provider），再用 /models 挑选它的模型。不想开 TUI 也可以用 opencode auth 命令行完成同样的操作。

在 TUI 中连接

textTUI 内输入
/connect
/models

/connect 会列出当前服务器和项目可用的集成。选中一个提供商，如果它提供多种认证方式就选择其一，然后跟着提示走即可。

TUI 里的认证方式

TUI 支持 API key、OAuth 以及提供商自带的认证命令。OAuth 会打开一个授权 URL 或显示一个待输入的授权码；按 o 打开 URL，按 c 复制授权信息：

text示例
/connect
# 选择 OpenAI，再选 Codex device code (legacy)。

再运行一次 /connect 可以添加另一个账号。选中一个已连接的提供商，会打开它的账号列表，你可以激活、重命名或删除已保存的账号。

命令行方式

用 auth login 可以不开 TUI 完成同样的提供商认证。不带提供商参数时，命令会打开一个交互式提供商选择器：

bash
opencode auth login

传入集成 ID 或名称可以跳过第一步选择器。用 --method key 可以显式选择 API key 输入方式：

bash
opencode auth login anthropic --method key

方式 ID（method ID）由各提供商自行定义。当某提供商有多种方式时，不带 --method 运行即可看到可用方式列表：

bash
opencode auth login openai

⚠️ 注意

API key 输入和提供商表单都需要交互式终端；需要你粘贴授权码的 OAuth 方式也一样。在 CI 脚本、无终端的后台任务里走这条路会直接失败——那种场景请改用环境变量方式注入密钥（见下文）。

四种认证方式

OpenCode 通过四种集成方式接收提供商凭据：

方式行为
API key提示输入密钥，保存为一个提供商账号。
OAuth给出浏览器 URL、设备码或授权码提示，保存 token，并在支持时自动刷新。
命令（Command）运行提供商指定的认证命令，把其标准输出保存为 key。
环境变量（Environment）直接从服务器进程读取受支持的环境变量，不落盘保存。

提供商可以为 API key 和 OAuth 方式附加表单，用于收集必需的细节（例如 Azure 资源名或 GitHub Enterprise 域名）。CLI 和 TUI 会在开始认证前渲染这些表单。

环境变量连接

把提供商支持的环境变量设置到执行模型请求的服务器进程上。一次性私有服务器可以在启动独立模式时传入：

bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone

对共享后台服务器，则把变量加进它的托管环境。这会停止正在运行的服务，下一条 OpenCode 命令会用新值把它启动起来：

bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list

环境变量连接在 auth list 里显示为 environment 类型。它们不是账号：auth logout 无法移除它们，想断开就 unset 那个变量。同一集成下，已保存的账号优先于环境变量连接：

bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY

原生凭据链

除了 API key 变量，一些提供商还会使用它们各自的原生环境凭据链：

  • Amazon Bedrock 支持 AWS 默认凭据链，包括 profile、access key 环境变量、web identity 和容器凭据；也支持 AWS_BEARER_TOKEN_BEDROCK。
  • Google Vertex 使用 Application Default Credentials 和一个可解析的项目。例如先用 gcloud auth application-default login 认证，再设置 GOOGLE_CLOUD_PROJECT。
  • Azure 在安装了 az 时，把 Microsoft Entra ID (Azure CLI) 暴露为一种连接方式。先运行 az login，然后在 /connect 或 auth login azure 中选择该方式。
bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode

提供商专属配置和服务器端设置见 Providers 一章。

账号管理

每次成功的 API key、OAuth 或命令登录都会创建一个已保存的账号。最新的账号自动成为当前激活账号；可以用标签或凭据 ID 切换激活账号：

bash
opencode auth list
opencode auth switch anthropic work

用 auth logout 移除已保存的账号。这两个命令省略参数时都会打开选择器：

bash
opencode auth logout anthropic work

在 TUI 里，/connect 提供对已保存账号同样的添加、激活、重命名和删除操作。

🧠 通俗理解

「多账号 + 激活」的模型好比一个钥匙串上挂了好几把同一家的钥匙：你可以有个人号和公司号两个 Anthropic 账号（比如标签分别叫 personal 和 work），平时用 auth switch 一键换钥匙。换的不是工具，只是它下个项目该用谁的额度。

凭据存储

已保存的 API key 和 OAuth token 存放在服务器的 SQLite 数据库里。本地服务器的数据库路径可以这样打印：

bash
opencode debug paths db

常规发布渠道的路径是 ~/.local/share/opencode/opencode.db；XDG_DATA_HOME、发布渠道和 OPENCODE_DB 都可能改变它。不要直接编辑数据库来管理凭据，请使用 /connect 或 auth 命令。

V2 在数据库迁移期间会从 OpenCode 数据目录里旧版的 auth.json 导入受支持的凭据。新的和更新的凭据存入 SQLite，不会写回那个文件。

💡 扩展

从 V1 迁移的老用户不用担心：旧 auth.json 里的凭据会在首次启动 V2 时自动搬进数据库，之后 auth.json 就只是历史遗迹了。如果你在多台机器间同步凭据，用 opencode auth export / import 这对官方命令（详见TUI 命令的 auth 部分），注意导出文件里是明文密钥，务必妥善保管。
