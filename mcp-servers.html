MCP 服务器

OpenCode 可以连接 MCP（Model Context Protocol，模型上下文协议）服务器，获得工具、提示词、资源和指令等能力。MCP 工具会占用模型上下文，所以只加你真正需要的服务器。

🧠 通俗理解

MCP 是一个「外设标准」：任何程序只要按这个协议实现，就能把自己的一组工具插进任何 AI 客户端——就像 USB 设备插上就能用。OpenCode 支持 MCP 意味着你可以给智能体装上几乎无限的外挂：查数据库、管 Sentry 告警、搜 GitHub、读 Notion……不用自己写一行工具代码。

快速上手

在要用它的项目里添加一个远程服务器，然后检查连接：

bash
opencode mcp add context7 --url https://mcp.context7.com/mcp
opencode mcp list

这条命令会把服务器写进项目的配置。加 --global 可以让它在所有项目里可用：

bash
opencode mcp add context7 --global --url https://mcp.context7.com/mcp

远程服务器默认使用 OAuth。如果列表显示 needs authentication，打开 OpenCode 运行 /mcps，选中该服务器并完成登录。连上之后，智能体就能直接用了：

text
✓ context7  connected

配置

手动配置服务器时，在 mcp.servers 下给它一个唯一名称。V2 不允许把服务器名直接放在 mcp 下面。

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
      },
    },
  },
}

服务器会自动连接。如果想保留配置但不连接，用 disabled 字段（不是 enabled）：

opencode.jsonc
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
        "disabled": true,
      },
    },
  },
}

⚠️ 注意

更高优先级的项目配置会整个替换同名服务器对象，而不是逐字段合并。要么给不同连接/账号起不同名字，要么在覆盖时把所有必填字段全部重写一遍——漏一个就会连接失败。

opencode.jsonc
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
      },
    },
  },
}

本地服务器

本地服务器是 OpenCode 通过 MCP stdio 传输启动的一条命令。用 -- 之后跟命令来添加：

bash
opencode mcp add everything -- npx -y @modelcontextprotocol/server-everything

环境变量用重复的 --env 标志传入：

bash
opencode mcp add everything --env LOG_LEVEL=info -- npx -y @modelcontextprotocol/server-everything

其它进程选项（比如工作目录）用配置文件写：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "everything": {
        "type": "local",
        "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
        "cwd": ".",
        "environment": {
          "LOG_LEVEL": "info",
          "MCP_API_KEY": "{env:MCP_API_KEY}",
        },
      },
    },
  },
}
字段必填说明
type是必须是 "local"。
command是可执行文件及其参数。
cwd否进程目录。相对路径从工作区解析，这也是默认值。
environment否追加到 OpenCode 继承的进程环境里的字符串变量。
disabled否为 true 时阻止连接。默认 false。
codemode否设为 false 可让工具直接暴露，而不是走 Code Mode。默认 true。
timeout否针对单个服务器的超时覆盖。
protocol否legacy（默认）、auto 或 2026-07-28。见「协议版本」。
pool否跨目录共享一条连接。默认 false。见「共享连接」。

环境变量替换用 {env:NAME} 写法。JSON 字符串里不会展开 $NAME 这类 shell 表达式：

opencode.jsonc
{
  "environment": {
    "MCP_API_KEY": "{env:MCP_API_KEY}",
  },
}

远程服务器

远程服务器使用 MCP Streamable HTTP 传输，要求绝对 URL：

bash
opencode mcp add context7 --url https://mcp.context7.com/mcp

请求头用重复的 --header 标志传入。{env:NAME} 引用要加引号，让 shell 原样写出：

bash
opencode mcp add context7 --url https://mcp.context7.com/mcp --header 'CONTEXT7_API_KEY={env:CONTEXT7_API_KEY}'

其它选项用配置文件。密钥放在环境变量里，别写进文件：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "oauth": false,
        "headers": {
          "CONTEXT7_API_KEY": "{env:CONTEXT7_API_KEY}",
        },
      },
    },
  },
}
字段必填说明
type是必须是 "remote"。
url是绝对的 Streamable HTTP 端点。
headers否发送到端点的字符串 HTTP 头。
oauth否OAuth 设置，或设为 false 禁用 OAuth。
disabled否为 true 时阻止连接。默认 false。
codemode否设为 false 可让工具直接暴露，而不是走 Code Mode。默认 true。
timeout否针对单个服务器的超时覆盖。
protocol否legacy（默认）、auto 或 2026-07-28。见「协议版本」。
pool否跨目录共享一条连接。默认 false。见「共享连接」。

只有当服务器完全依赖 API key 或其它头凭证时，才用 oauth: false：

opencode.jsonc
{
  "type": "remote",
  "url": "https://mcp.example.com/mcp",
  "oauth": false,
  "headers": { "Authorization": "Bearer {env:MCP_API_KEY}" },
}

OAuth

远程服务器默认启用 OAuth，除非把 oauth 设为 false。OpenCode 会发现授权服务器、用 PKCE 登录并自动刷新令牌。凭证存储在项目配置之外。

大多数服务器只需要一个 URL：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
      },
    },
  },
}

如果服务器需要认证，运行 /mcps、选中它，然后在浏览器里完成授权。CLI 也能发起同样的流程：

bash
opencode mcp auth sentry

浏览器不在本机时

当 OpenCode 通过 SSH、容器或远程服务器运行时，你登录之后浏览器无法回调到 OpenCode，会显示一个加载不出来的页面。把地址栏里那个页面的 URL 复制下来，粘贴到登录提示里：

text
http://127.0.0.1:52817/callback?code=...&state=...

在 OpenCode 等待浏览器的过程中，这个提示会出现在 /mcps、opencode mcp auth，以及桌面端和 Web 端的登录对话框里。

客户端注册

OpenCode 按以下顺序、用第一个适用的方式向授权服务器标识自己：

方式何时使用
预注册客户端配置了 oauth.client_id。
Client ID Metadata Document（CIMD）授权服务器支持 CIMD 和公共客户端，且未设置 oauth.redirect_uri。
动态客户端注册（DCR）前两者都不适用时。OpenCode 注册一个客户端并在之后的登录里复用。

授权服务器通过元数据声明支持 CIMD：

json
{
  "issuer": "https://auth.example.com",
  "client_id_metadata_document_supported": true,
  "token_endpoint_auth_methods_supported": ["none"]
}

使用 CIMD 时，OpenCode 把自己的元数据文档 URL 作为 client_id 发送，并跳过注册：

text
https://opencode.ai/oauth/opencode/client.json

该文档允许以下不带端口的回环重定向：

  • http://127.0.0.1/callback
  • http://localhost/callback
  • http://127.0.0.1/mcp/oauth/callback（给较旧的客户端）

按照 RFC 8252 的要求，授权服务器对这类重定向接受任意回环端口，所以 callback_port 与 CIMD 兼容；而自定义的 redirect_uri 不行，那种情况下 OpenCode 会退回 DCR。

如果授权服务器既不支持 CIMD 也不支持 DCR，就配置预注册客户端。

预注册客户端

当提供商给了你客户端凭证时，用 V2 的 snake_case OAuth 字段：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "company-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "oauth": {
          "client_id": "{env:MCP_CLIENT_ID}",
          "client_secret": "{env:MCP_CLIENT_SECRET}",
          "scope": "tools:read tools:execute",
          "callback_port": 19876,
          "redirect_uri": "http://127.0.0.1:19876/callback",
        },
      },
    },
  },
}
字段说明
client_id预注册的客户端 ID。优先于 CIMD 和 DCR。
client_secret机密客户端（confidential client）的密钥，放在令牌请求体里发送。公共客户端省略它。
scope空格分隔的请求范围。默认使用服务器拒绝未认证请求时给出的 scope。
callback_port本地回调端口，1 到 65535。默认取 redirect_uri 的端口，其次取一个可用的临时端口。
redirect_uri预注册的回环 URI，其路径和端口要能到达本地回调监听器。设置它会禁用 CIMD。
auth_server_metadata_url授权服务器的 OAuth 或 OpenID Connect 元数据文档 URL。当 MCP 服务器没有公布指明其授权服务器的受保护资源元数据时设置它。

需要重新登录或切换账号时，删除已存的 OAuth 凭证：

bash
opencode mcp logout sentry

超时

超时值为正整数毫秒。在 mcp.timeout 下设置默认值；单个服务器的 timeout 对象覆盖同名默认值。

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "timeout": {
      "startup": 45000,
      "catalog": 30000,
      "execution": 600000,
    },
    "servers": {
      "slow-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "timeout": {
          "catalog": 60000,
        },
      },
    },
  },
}
超时项默认值作用对象
startup30 秒传输连接和服务器初始化。
catalog30 秒列出工具、提示词、资源和资源模板。
execution12 小时工具调用、提示词获取和资源读取。

协议版本

OpenCode 默认用经典的 MCP initialize 握手打开每个服务器。把某个服务器的 protocol 设置好，就能与基于 2026-07-28 修订版构建的服务器对话：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "modern": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "protocol": "auto",
      },
    },
  },
}
取值行为
legacy默认。发送 initialize，支持到 2025-11-25 为止的协议修订版。
auto用 server/discover 探测 2026-07-28 修订版，服务器不支持时退回 legacy。
2026-07-28要求 2026-07-28 修订版。对旧服务器连接会失败。

⚠️ 注意

对 legacy 的本地服务器做 auto 探测会多启动一个短命进程；如果服务器忽略未知请求，探测还可能一直等到启动超时。所以 auto 只给确实需要它的服务器用，不要全局铺开。

共享连接

一个 OpenCode 服务器可以同时打开很多目录，而每个目录默认都会连一遍它自己的每个 MCP 服务器。把 pool 设为 true，可以让配置相同服务器的目录们共享一条连接和一份工具列表：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "cloudflare": {
        "type": "remote",
        "url": "https://mcp.cloudflare.com/mcp",
        "pool": true,
      },
    },
  },
}
  • 只有 2026-07-28 修订版上的连接才会共享。设置了 pool 后，未写 protocol 意味着 auto。以旧修订版应答的服务器、或被设为 legacy 的服务器，仍然每个目录一条连接。
  • 目录间共享连接要求所有会影响连接的东西都一致：远程服务器的 URL、请求头、OAuth 设置和登录账号；本地服务器的命令、工作目录和环境变量。timeout 和 protocol 也必须一致。服务器名称不必相同，但登录信息按名称存储，所以 OAuth 服务器只在同名下才会共享。
  • 本地服务器只在本机目录之间共享，不跨工作区。想跨项目共享需要固定 cwd（如 "~"）；没有固定的话它会在每个项目目录里各跑一份，OpenCode 会记录一条警告。
  • 共享连接没有 roots（根目录限定）。工具请求输入时，请求会出现在调用它的那个目录里。
  • 最后一个使用它的目录关闭或断开服务器时，连接随之关闭。

工具命名

OpenCode 把工具命名为 <server>_<tool>，字母、数字、_、- 以外的字符一律替换成 _：

text
server: context 7
tool:   resolve.library/id
name:   context_7_resolve_library_id

MCP 提示词变成名为 <server>:<prompt> 的命令，做同样的规范化。例如：

text
/context_7:find_docs

命令文本按顺序填入提示词的参数。用空格分隔，含空格的值加引号：

text
/context_7:find_docs react "server components"

选服务器名称时挑短的，并确保规范化后仍然唯一。在默认的 Code Mode 下，工具按规范化后的服务器名分组：

text
tools.context_7.resolve_library_id(...)

权限

Code Mode 是默认方式。当服务器的工具必须留在提供商的原生工具列表里时，把 codemode 设为 false：

opencode.jsonc
{
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "codemode": false,
      },
    },
  },
}

用权限动作可以在不断开服务器的情况下隐藏或拒绝工具。匹配规范化后的 <server>_<tool> 名称：

opencode.jsonc
{
  "permissions": [
    {
      "action": "context7_*",
      "resource": "*",
      "effect": "deny",
    },
  ],
}

资源

智能体通过两个内置工具读取 MCP 资源：list_mcp_resources 和 read_mcp_resource。用这些权限动作控制它们：

动作资源
opencode_list_mcp_resources服务器名称。
opencode_read_mcp_resource<server>:<uri>

比如，允许从 docs 服务器读取所有资源：

opencode.jsonc
{
  "permissions": [
    {
      "action": "opencode_read_mcp_resource",
      "resource": "docs:*",
      "effect": "allow",
    },
  ],
}

服务器指令

当服务器在初始化时返回指令（instructions），OpenCode 会把它们加进系统提示词：

text
<mcp_instructions>
  <server name="sentry">
    Search for an existing issue before creating a new one.
  </server>
</mcp_instructions>

对使用 Code Mode 的服务器，OpenCode 会额外加一行，说明智能体可以在哪里找到该服务器的工具。

当智能体的权限拒绝了某服务器的所有工具时，该服务器的指令会被省略。当权限拒绝了 execute 时，服务器的工具改为直接列出，指令保留但去掉 Code Mode 那一行。

输入请求

服务器可以在调用过程中通过 MCP elicitation 请求输入。OpenCode 把请求显示为表单；URL 类请求则显示为一个链接：

text
sentry is requesting input

关掉表单即取消请求。

上下文

代表会话发起的调用，OpenCode 会在 CallToolRequest.params._meta["ai.opencode/sessionID"] 里带上会话 ID。这适用于直接工具和 Code Mode，stdio 与 Streamable HTTP 皆可：

json
{
  "method": "tools/call",
  "params": {
    "name": "lookup",
    "arguments": { "query": "example" },
    "_meta": { "ai.opencode/sessionID": "ses_..." }
  }
}

这个 ID 是请求元数据，不是工具参数，所以不会出现在模型可见的 schema 里。把它当作一个不透明的关联值：

规则行为
身份它标识的是发起调用的 OpenCode 会话，不是 MCP 传输层会话。
存在性没有会话上下文的调用里它可能不存在。
安全不要单独用它做认证或授权。
隐私远程服务器收到的是原始 ID，可能会记录或保留它。

管理

在任何项目里列出服务器和它们当前的连接状态：

bash
opencode mcp list

在 OpenCode 里用 /mcps 查看、连接、断开或认证服务器。用 CLI 添加服务器和管理 OAuth 凭证：

bash
opencode mcp add sentry --url https://mcp.sentry.dev/mcp
opencode mcp auth sentry
opencode mcp logout sentry

不带名称运行 opencode mcp auth，可以从支持 OAuth 的服务器里挑选：

bash
opencode mcp auth

要移除服务器，把它的条目从当初添加它的项目或全局配置里删掉：

opencode.jsonc
{
  "mcp": {
    "servers": {},
  },
}

💡 扩展

在 /mcps 里断开一个服务器不会改动配置文件——那只是本次会话的状态。OAuth 客户端设置、超时、工作目录，以及「保留配置但保持断开」这类持久需求，都要直接编辑配置：

opencode.jsonc
{
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
        "disabled": true,
      },
    },
  },
}
