服务器插件

插件的服务器（server）部分运行在 OpenCode 服务器进程里。它修改 OpenCode 的行为、添加新功能：工具、钩子（hook）、集成、命令和 agents。插件包如何组织、加载与发布见插件总览。

.opencode/plugins/example/index.tsTypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})

🧠 通俗理解

服务器部分是插件的「大脑」：它跑在 OpenCode 的服务端进程里，离所有核心资源（会话、模型、工具、MCP、VCS）最近。TUI 和 GUI 插件只负责「长得好看」，真正改行为、加工具的活都归它。你在插件里写的 ctx 对象，本质上是插了一根管子直通 OpenCode 服务器。

生命周期

setup 在插件加载时运行。它可以返回一个清理函数，这个函数会在插件卸载时执行。

TypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})

上下文（Context）

插件上下文本质上就是一个 OpenCode 服务器客户端。它的读取（read）与操作（action）方法和客户端使用完全相同的入参和返回值。在此基础上，它额外提供一批仅插件可用的方法：转换（transform）、运行时钩子、重新加载（reload）、注册（registration）以及插件选项。

TypeScript
setup(ctx) {
  console.log(ctx.app.version)
}

ctx.location 描述当前插件实例被加载的位置。它包含 directory、可选的 workspaceID，以及项目元数据 project（含 id、directory、canonical）。该对象在 Promise 插件和 Effect 插件中都可用。注意：这是插件实例自身的位置，不是它能访问的每个会话、或它收到的每个事件所在的位置。

TypeScript
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}

⚠️ 注意

配置里的 options 是任意 JSON 值，OpenCode 不会校验字段——写错了名字插件不会报错，只是读到 undefined。所以示例里才写成 ctx.options.strict === true 这种显式布尔比较，而不是真值判断，避免 undefined 被误当作 true。

转换（Transforms）

转换是对 OpenCode 领域状态的同步编辑，同一领域内后面的转换建立在前面注册的基础之上。诸如 ctx.model.list() 这类注册表读取操作，会反映到目前为止的所有注册结果——包括插件 setup 期间；启动时的批处理只是合并更新通知，绝不会延迟读取返回的内容。资源状态类 API 仍然报告的是正在运行资源的状态：一个定义已注册，不代表它的连接或其它资源工作已经完成。

数据源通过 ctx.provider.transform 提供提供商（provider）和不可变的模型定义：

plugins/models/index.tsTypeScript
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})

任何一次注册、删除或 reload() 都会把注册表标记为「已变更」；下一次读取时会按注册顺序把所有仍生效的转换重放到一份全新值上来重建注册表。因此转换要写得便宜且可重复。你之前读取到的值永远不会被后续重建修改。

在提供商转换和可用性解析完成之后，OpenCode 会物化（materialize）当前激活提供商的模型，并按顺序重放所有模型转换。模型策略因此可以检查完整的候选集合，包括刚刷新出来的数据源：

plugins/model-budget/index.tsTypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})

转换回调里捕获的输入不会被自动监听。要在同步回调之前加载外部数据，然后在这些输入变化后调用 reload()。下面例子里 loadFromSource() 返回 { info: Provider.Info, models: readonly Model.Info[] } 形式的条目：

plugins/models/index.tsTypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})

提供商的变化会让整个「激活模型」结果失效，所以上面那个输出价格策略依然会过滤刷新后的模型。如果只有模型转换捕获的输入变了，用 ctx.model.reload() 即可。

🧠 通俗理解

把转换想象成往一条流水线上排队盖章：editor 是盖章的章，每次读取结果相当于把流水线从第一个章到最后一个章完整重跑一遍得出成品。所以你的转换函数不能依赖「只跑一次」的状态，必须能反复执行并得出同样结果（幂等）；而真正被监听的外部数据是不存在的——想响应变化，只能自己调 reload() 重新排队。

TypeScript

  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-5-5", (model) => {
    model.name = "Team Sonnet"

  editor.remove("legacy-provider")
})

Models（模型）

读取可用模型和默认选择：

TypeScript
const models = await ctx.model.list()

模型转换编辑的是整个激活提供商候选集合。在所有转换结束之前，被禁用的候选也保持可编辑；update 只能在可用提供商下新增模型：

TypeScript
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-5-5")
  editor.remove("anthropic", "legacy-model")
})

await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()

Permissions（权限）

在执行动作之前请求权限。assert 会按会话的权限规则求值（包括已保存的批准记录），当某条规则的结果是 ask 时向用户弹出询问，动作被允许后一次完成解析：

TypeScript
execute: async (input, context) => {
  await ctx.permission.assert({
    sessionID: context.sessionID,
    agent: context.agent,
    source: { type: "tool", messageID: context.messageID, id: context.id },
    action: "deploy",
    resources: [input.environment],
    save: [input.environment],
  })
  return { content: await deploy(input.environment) }
}
  • action 和 resources 会与规则匹配。任何 deny 都会阻止动作；否则任何 ask 会触发询问。
  • save 列出当用户选择「总是允许」时要存储的模式（pattern）。
  • agent 决定应用谁的规则，默认取会话的 agent；source 把这次询问挂到一次工具调用上。
  • metadata 给权限询问和 evaluate 钩子传递额外细节。

deny 规则或「带反馈的拒绝」会以携带原因的 Tool.Error 抛出，模型能看到它并继续工作；普通拒绝则直接结束当前步骤。让这些错误自然向上传播，而不要作为工具输出返回。

Tools（工具）

在所有转换完成后、且不在转换回调之内时，读取当前已注册的工具。每个工具的 id 里包含其生效名称（effective name）：

用一个同步转换注册、更新、移除工具（Promise 插件同样支持）。注册或重新加载之前先加载外部数据。后一次有效注册会覆盖同名生效工具：

TypeScript
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})

Promise 工具执行器会收到 context.signal。把它传给可取消的工作（比如 fetch），这样停止会话时底层操作也会被停止：

execute: async ({ url }, context) => {
  const response = await fetch(url, { signal: context.signal })

}

自由格式工具输入（Freeform tool input）

只有一个必需字符串字段的直接工具，可以让模型不加 JSON 包装直接写这个字符串。把 freeform 设为 { type: "text" }、{ type: "regex", pattern } 或 { type: "lark", grammar }：

TypeScript
editor.add({
  name: "ticket",
  description: "Look up a ticket by ID",
  options: { codemode: false },
  input: Schema.Struct({ id: Schema.String }),
  freeform: { type: "regex", pattern: "OPS-[0-9]+" },
  execute: async ({ id }) => ({ content: await lookup(id) }),
})

如果所选模型的 API 在 models.dev 上登记了 regex，模型就能直接写 OPS-42。否则 Core 只会省略 freeform 这一项：模型仍然有 ticket 工具，只是用 {"id":"OPS-42"} 来调用。格式列表缺失或为空意味着不支持自由格式。无论哪种情况，执行器收到的都是 { id }。

在 Code Mode（codemode: true）中，自由格式工具直接收字符串，如 await tools.ticket("OPS-42")；await tools.ticket({ id: "OPS-42" }) 也可以。

在回调捕获的源数据变化后调用 reload()。重新加载会按原顺序重放仍在生效的转换，但不会重跑插件 setup：

TypeScript
await ctx.tool.reload()

用 list() 和 get() 检查编辑器中当前的工具。工具的 id 里包含生效名称，get() 在该 ID 不存在时返回 undefined。update 和 remove 都用生效工具名（含命名空间，如上面的 acme_greeting）。命名空间里的点号和工具名中的不支持字符都会变成 _。缺失的名字会被忽略；创建工具必须用 add 传入完整定义。更新会保留名称与命名空间。要替换 schema 或选项就整体赋新值，而不要去改嵌套值。非法更新会被记录日志，并保持之前的定义不变：

TypeScript
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})

更新和移除会与新增按顺序一起重放，包括 MCP 目录刷新之后。销毁（dispose）注册会移除对应的变更，并基于剩余转换重建，从而露出被它覆盖的更早定义。销毁是幂等的；卸载插件也会销毁其所有注册：

TypeScript
await registration.dispose()

每次模型请求捕获的是一份稳定、可执行的工具快照。之后的转换、重载和销毁影响的是未来的快照，不会改动已经捕获的定义、Code Mode 命名空间描述或执行器。闭包引用可变插件数据的执行器仍会观察到数据变化；如果某个值必须与该定义绑定，就在转换内先捕获住它。

用普通插件生命周期注册一个本地工作树（worktree）策略。本例中的实现模块自己负责选项校验，以及后端的 create、remove、list 操作：

  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})

通过 plugins 加载插件，公共目标目录单独配置：

  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
  • 添加一个策略就自动选中它。最后一个生效注册获胜；不需要策略选择配置。
  • 销毁其注册或卸载插件会恢复上一个实现，最终回落到内置的 Git 策略。
  • reload() 在捕获的输入变化后重放转换；它不会重跑插件 setup。
  • 创建失败不会通过 Git 重试。即使默认策略变化，已存在的工作树仍保留其记录的属主。
  • 策略只管理本地目录。远程工作区的供给（provisioning）不属于该接口。

操作（Operations）

插件上下文暴露与客户端相同的项目级工作树操作。每个操作都需要 projectID。list 只读取已保存的清单（包括同一项目已知的检出），它不会加载配置、启动插件或发现文件系统变化：

TypeScript
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })

create 从项目保存的 canonical 目录加载配置与插件，并使用它们选中的策略。它接受可选的父级 directory、源 from、起始 branch 和 name。源默认取规范检出；from 覆盖值必须属于该项目。选择源不会改变配置根目录。所提供的起始 ref 必须被所选策略支持——例如 Rift 的原生快照操作就没有 ref 选择选项。

create 和 refresh 会等待规范检出的插件激活。在此检出插件 setup 期间发起的调用能看到目前为止的注册，并且不会等待它们自身被激活。

remove 加载规范配置并激活其插件，然后使用工作树记录的策略而不是当前选中的默认值。记录的属主不可用会报错。工作树的目标位置可以在别处：

TypeScript
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})

属主缺失会导致移除失败，而不会回退到 Git。策略可以抛出 new Worktree.OperationError({ message: "Uncommitted changes", forceRequired: true })（从 @opencode/plugin 导入 Worktree）来请求强制确认，而不必依赖 Core 或 Git 的错误。

refresh 加载规范配置，并让所有可用策略在已知检出根目录间寻找工作树。它会合并结果、保留记录的属主，并清理缺失的目录。某个发现源失败只记日志，其它源继续。已存在的目录即使没有任何可用策略报告也会保持已保存状态。可以观察 worktree.updated 事件并再次调用 list 来读取变化后的清单：

TypeScript
await ctx.worktree.refresh({ projectID })

钩子（Hooks）

钩子拦截正在发生的操作。在所属领域上注册钩子，不再需要时销毁返回的注册即可：

TypeScript
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()

多个插件可以注册同一个钩子。OpenCode 按插件顺序执行它们，因此后面的钩子能看到前面钩子做出的修改。

Sessions（会话钩子）

会话钩子拦截提示收件（prompt admission）、模型调用、原生 HTTP 和重试。

分叉（Forks）

fork 钩子在 OpenCode 复制完历史之后、分叉调用返回之前运行。sessionID 标识新会话：

TypeScript
await ctx.session.hook("fork", ({ sessionID }) => console.log(sessionID))

提示收件（Prompt admission）

在附件与技能解析、以及持久化收件箱收件之前，拦截到来的用户提示：

TypeScript
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})

钩子收到的是一个自有、可变的草稿：

  • prompt 包含 text、files、放在 agents 里的 agent 提及，以及选中的 skills。
  • metadata 包含应用定义的收件元数据。
  • delivery 默认是 "steer"，可以改为 "queue"。
  • 会话 ID 和消息 ID 是只读的；钩子不能改投收件目的地。

钩子添加的文件和技能走正常的解析与校验路径。重写文本时，要同步更新或删除不再匹配的附件 mention 偏移量。Agent 提及不会切换会话的激活 agent。

提示钩子在这些条件下运行：

  • 钩子在会话的位置插件就绪后按注册顺序运行。
  • 通过 session.prompt 提交的命令会触发钩子。
  • 合成消息、shell 消息、压缩控制和移动控制不会触发。
  • 钩子在收件时运行一次，而不是每次模型调用前。
  • 无法按提供商限定作用域，因为模型解析发生在收件之后。

钩子的编辑会成为持久化用户输入的权威版本。如果准备阶段失败或被中断，OpenCode 不会收下这条提示。

保持提示钩子重试安全。它们不是恰好一次（exactly-once）的副作用边界：

  • 重试一个已经 pending 或已投递的 ID，会直接返回原始收件，不会重跑钩子。
  • 并发提交可能让钩子跑不止一次，但只有第一次成功收件获胜。
  • 提示钩子只做输入转换，不提供类型化的拒绝 API。

模型请求（Model requests）

在模型派发前一刻，修改组装好的系统指令、消息、工具或请求选项。会话发出的每种请求都有各自的钩子，插件因此可以把智能体主循环和辅助请求区别对待：

  • context——用于智能体循环，包括工具驱动的续跑。
  • compaction——用于检查点摘要。messages 是正被总结的对话记录；OpenCode 在钩子运行之后附加它自己的摘要提示。设置 result 可以自己记录压缩结果并跳过模型调用；它接受的字段与一条完成的压缩消息相同。
  • generate——用于一次性的 ctx.session.generate 调用。
  • title——用于标题生成。它没有 agent 和 tools。设置 result 可以自己提供标题。
TypeScript
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})

改动只影响即将发出的那次模型调用，不会写入持久化历史或配置。想对所有请求生效的钩子，必须每种都注册一遍。

context、compaction、generate 钩子里的消息携带其存储消息的 metadata（只读，例如某个 prompt 钩子设置的值）。它不会发给模型。

承载 OpenCode 指令的 system 部分还会在 metadata.experimental.instructions 里以 { key, text } 的形式列出每个来源，比如 core/date 或 core/environment，钩子借此区分来源。这个列表是一份副本：修改该部分的 text 不会同步它。这是实验性行为，可能变化。

请求覆盖遵循以下规则：

  • options 每次模型调用都从空开始；不包含已解析的模型设置。
  • 类型化键是生成设置；其它键会作为提供商选项传给所选协议。
  • 钩子按注册顺序运行，后面的钩子能看到前面钩子的覆盖。
  • 请求覆盖的优先级高于模型默认值，模型默认值又高于路由默认值。
  • 提供商选项对象递归合并；数组和标量值则直接替换先前的值。
  • 删除某个覆盖或把它设为 undefined 会回落到已配置的默认值，而不是删除默认值。
  • 原生 HTTP body 覆盖在协议降级（lowering）之后生效，可以覆盖最终字段。

提供商选项（Provider options）

提供商选项用的是所选协议的语义选项名，而不是原始 HTTP body 字段。把特定提供商的设置限定到匹配的提供商上。例如 OpenAI Responses 用 reasoningEffort：

TypeScript
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)

生成选项取决于所选协议和模型：

  • maxTokens 是语义上的输出 token 上限。
  • Gemini 支持 topK；OpenAI Responses 不暴露它。

模型解析（Model resolve）

实验性。每当会话为一次请求解析模型时运行，发生在为该请求构建任何内容之前。model 初始为所选模型；修改它即可让本次请求改用同一提供商的另一个模型，包括对模型选择器隐藏的模型。会话自身保持所选模型；请求和助手消息使用新模型。kind 说明是哪种请求在解析，路由器因此可以跳过标题生成、或在压缩后重新路由。来自其它提供商的模型会按「不可用」失败：

TypeScript
await ctx.session.hook(
  "experimental.model.resolve",
  (event) => {
    if (event.model.id === "auto" && event.kind !== "title")
      event.model = { providerID: event.model.providerID, id: pick(event.sessionID) }
  },
  { providerID: "acme" },
)

模型请求钩子（Model request）

修改模型请求设置，并可选地把钩子限定到某个提供商。事件携带的 kind 与下面的 HTTP 钩子相同：

TypeScript
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)

原生 HTTP（Native HTTP）

修改原生提供商请求或响应。它们的 body 是一次性流（one-shot stream）；读取之前要先 clone 或整体替换。

两个钩子都会对会话发出的每个请求运行。event.kind 标明是哪条流程发出的："primary" 是智能体循环，"compaction" 是检查点摘要，"title" 是标题生成，"generate" 是一次性 ctx.session.generate 调用。区分辅助请求请用它，而不要用 agent ID：

TypeScript
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})

原生 WebSocket（实验性）

通过 WebSocket 流式输出的提供商，每个会话只开一条连接并在多次请求间复用，所以 http.request 和 http.response 永远看不到那些流量。experimental.ws.handshake 钩子在一次模型调用中、连接选定之前运行一次。它携带与 HTTP 钩子相同的 sessionID、agent、model、kind，外加连接的 url 和 headers。修改 url 或 headers 就会改变请求使用的 socket，因此轮换的 bearer token 会导致重开连接。

HTTP 钩子仍然会针对每个 HTTP 请求运行，包括 WebSocket 路由回退发出的那个请求：

TypeScript
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)

experimental.ws.send 和 experimental.ws.receive 暴露的是帧本身，相当于编辑 HTTP 请求/响应 body 的 WebSocket 版。send 在提供商驱动构造完出站帧之后、写入之前运行；receive 在每个入站帧被驱动观察到之前运行。两者都把帧作为字符串携带，钩子返回时发送 frame 里当前的内容。

OpenCode 不校验重写后的帧。驱动是从提供商的回复里追踪状态的，所以改变协议含义的重写和重写 HTTP body 一样，都是插件自己的责任：

TypeScript
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})

这些钩子是实验性的，名称或结构可能变化。

重试策略（Retry policy）

覆盖某个提供商失败时的重试决策，或替换它的毫秒级延迟。钩子在 OpenCode 对失败分类并提出自身策略之后、任何重试被调度之前运行。它不会暴露 OpenCode 内部如何执行下一次尝试：

TypeScript
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})

重试钩子可以修改 OpenCode 的初始 decision——把一次终态失败变成可重试，或者否决一个提议的重试。

重试决策遵循以下规则：

  • 多个钩子按注册顺序运行，后面的钩子看到的是当前决策。
  • 内置的最大尝试次数仍是硬性上限。
  • attempt 是正在评估的物理尝试次数。初始请求是 1，所以第一次重试是 2。
  • 非法延迟（NaN、无穷、负值）回落到计算出的延迟。
  • 上下文溢出的恢复是另一条路径，因为它是压缩对话而不是重试同一请求。

Permissions（权限钩子）

在已配置规则求值之后、动作真正执行或权限询问发布之前，复核权限决策：

TypeScript
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-5-5" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})

权限钩子遵循以下规则：

  • 钩子对 allow 和 ask 决策都会运行。
  • 已显式配置的 deny 是终局，不会调用钩子。
  • 钩子可以把 effect 改成 allow、ask 或 deny。
  • message 会出现在升级后的权限询问里，或成为拒绝原因。

同时支持 V1

一个插件可以在同一个包入口同时支持 V1 和 V2。默认导出一个对象，同时带上 V1 的 server() 函数和 V2 的 setup() 函数：

src/index.tsTypeScript
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
  • V1 调用 server() 并使用返回的钩子。
  • V2 读取默认导出的 id 和 setup()（Effect 插件则是 effect()），忽略 server()。
  • 两套实现各自走各自的 API；共享一个导出并不会把 V1 钩子翻译成 V2 钩子。
  • 把 Plugin.define(...) 展开进导出对象，让 V2 定义与 server() 分开做类型检查。

对象形式的 V1 从 OpenCode 1.18.29 开始受支持。更老的 V1 版本可能期望函数导出；请用你打算支持的最老 V1 版本和 V2 分别测试已安装的包。

💡 扩展

「双格式导出」是官方给出的过渡方案：V2 的 Plugin.define({...}) 是一个普通对象，所以用展开运算符 ... 并上 V1 的 server() 就能一个文件兼容两代。迁移期团队建议：先用双格式发一版，观察 V1 用户升级情况，再发布纯 V2 版本删掉 server()。完整迁移步骤见插件迁移。
