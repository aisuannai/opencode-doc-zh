API · 模型

模型列表 API 有两类：Console 列表返回工作区能用的全部模型（含已接入的自定义提供商），推理列表则按 OpenAI 的格式返回公开的 OpenCode Models 和 Go 目录。

列表返回内容是否需要 Key
/console/api/v1/models调用方能用的每一个提供商和模型，并套用工作区的修改。必需
/inference/v1/modelsOpenCode Models。不带 key 时返回所有公开模型；带 key 时返回其工作区能用的模型。可选
/inference/go/v1/modelsGo 订阅的模型，格式与上者相同。可选

🧠 通俗理解

怎么选？如果你在写一个「跟 OpenCode 客户端一样」的工具——希望用户看到的模型选项和 OpenCode 里完全一致（连他自己接入的 OpenAI、Anthropic 连接都在内），就用 Console 列表。如果你只是想查查「OpenCode 平台目前有哪些公开模型」，或者手上还没有 key 只想看看公开目录，就用推理列表，它免认证也能调。

Console 模型列表

GET https://opencode.ai/console/api/v1/models 返回调用方能用的每一个提供商，以及每个提供商之下它能调用的模型。

bash
curl --fail-with-body "https://opencode.ai/console/api/v1/models" \
  --header "Authorization: Bearer oc_sk_..."

任何工作区成员都可以调用：凭浏览器会话、OpenCode 登录、个人 API key，或带有 Models › Read 权限的服务账号 key。它使用与 OpenCode 配置文件里 Console 生成的部分相同的规则，因此返回的列表与 OpenCode 里 /models 命令显示的内容一致。响应永不缓存（Cache-Control: private, no-store）。

提供商（Providers）

响应是一个以提供商 ID 为键的对象，这个 ID 就是 OpenCode 所使用的 ID：

提供商 ID提供商
opencodeOpenCode Models，从工作区额度（credits）扣费。
opencode-goGo 订阅的模型。只有订阅了 Go 才会出现。
console-<connection slug>工作区添加的连接（connection），例如 console-openai、console-anthropic 或 console-aws-bedrock。

每个提供商都有 id、name 和 models 字段。name 是 OpenCode 界面里显示的名字，通常是「工作区名 + 提供商名」。models 是一个以模型 ID 为键的对象。

字段（Fields）

每个模型都是 models.dev 的 v2 条目，再套用工作区的修改，所以字段就是 models.dev 发布的那些。被停用的模型、以及 models.dev 标记为已弃用（deprecated）的模型不会出现在列表里。

字段含义
type模型类型。目前只列出 chat；决策、语音、图像模型未来可能会加入。
id发请求时使用的模型 ID。它同时也是 models 里的键。
name显示名称。
limitcontext 是上下文窗口；input 在模型设有输入上限时限制单次请求的输入；output 限制响应长度。
cost每 100 万 token 的美元价格：text.input.price、text.input.cache.read、text.input.cache.write 和 text.output.price。0 表示免费；缺少缓存字段表示该模型没有缓存定价。部分模型还带 cost.multipliers，表示在指定时段价格上浮。
capabilities模型能做什么，比如工具调用和推理力度（reasoning effort）。
modalities接受的输入类型（如 text、image/png、application/pdf）和输出类型。
api调用该模型用的 Console URL 和 SDK。见下文「模型 API」。

模型 API（Model API）

api 字段有一个条目，键为模型所讲的协议：chat-completions 对应 OpenAI Chat Completions，responses 对应 OpenAI Responses，messages 对应 Anthropic Messages，generate-content 对应 Gemini。内容是该协议在 models.dev 的条目，只是把厂商的 URL 换成了 Console 的，并删去其余协议。

字段含义
base_url该模型请求发往的地址。OpenCode Models 用 https://opencode.ai/inference/...，Go 用 https://opencode.ai/inference/go/...，自定义连接用它的 Console API URL：https://opencode.ai/inference/custom/<connection_id>。
sdk.aisdk该协议对应的 AI SDK 包，与模型端点表中的相同。
sdk.opencodeaiOpenCode 加载的配套提供商模块。

你自己接入的连接上的模型，其 api 长这样。按 Providers API 的说明，把协议路径（如 /chat/completions 或 /responses）拼在 base_url 后面即可：

json自定义连接的 api 字段
"api": {
  "responses": {
    "base_url": "https://opencode.ai/inference/custom/conn_...",
    "sdk": {
      "aisdk": "@ai-sdk/openai",
      "opencodeai": "@opencode/ai/providers/openai/responses"
    }
  }
}

推理模型列表（Inference model lists）

GET https://opencode.ai/inference/v1/models 列出 OpenCode Models，GET https://opencode.ai/inference/go/v1/models 列出 Go 模型。两者都返回 OpenAI 的列表格式：

bash无需认证
curl https://opencode.ai/inference/v1/models

截取到一个模型及其常见字段的精简版：

json响应示例（精简）
{
  "object": "list",
  "data": [
    {
      "id": "claude-sonnet-5-5",
      "object": "model",
      "created": 1795006281,
      "owned_by": "opencode",
      "name": "Claude Sonnet 5.5",
      "type": "chat",
      "limit": { "context": 1000000, "output": 128000 },
      "cost": {
        "text": {
          "input": { "price": 2, "cache": { "read": 0.1, "write": 2.5 } },
          "output": { "price": 10 }
        }
      }
    }
  ]
}

不带 key 时，列表包含所有公开模型；带 key 时，只包含该 key 所属工作区能用的模型——因此服务账号 key 需要 Models › Read 权限。key 通过 Authorization: Bearer 或 x-api-key 传入。只列出 chat 类型的模型；私有模型和已弃用模型不会出现。

每个条目先给出 OpenAI 的 id、object、created、owned_by，然后是与 Console 列表相同的 models.dev 字段：name、type、limit、cost、capabilities、modalities、api、family、release_date 等等。与 Console 列表不同的是，推理列表不包含工作区接入的自定义连接。如果 models.dev 的数据暂时不可用，条目仍会返回，但只有 OpenAI 的字段，且 name 等于 ID。

💡 扩展

每个 Go 模型还多一个 go 字段，描述订阅相关的规则：monthly_usage（各套餐的每月用量上限）、training（是否用你的请求做训练）、zdr（是否完全不保留你的数据，Zero Data Retention）、limited_regions（是否在某些国家/地区不可用）。写面向 Go 用户的工具时可以用这些字段做合规提示。

错误码

状态码含义
401未提供凭证，或 key 已过期/被吊销。
403该 key 无权列出模型。服务账号 key 和受限 key 需要 Models › Read 权限。
