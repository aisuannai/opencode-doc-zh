TUI 主题

OpenCode 自带大量明暗两套的内置主题：可以在设置里直接选，也可以调出自己的配色。本页讲如何选择、安装、在插件里使用，以及如何从零创建一个主题。

选择主题

按 Ctrl+P，选择 Open settings，再打开 Theme。默认主题是 opencode。

也可以在全局 CLI 设置里直接写：

~/.config/opencode/cli.json
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}

不想打开设置的话，运行 /themes 也能随时换主题。

系统配色

当 OpenCode 能读到终端调色板时，主题选择器里会出现 system 主题。它从终端的前景色、背景色和 ANSI 调色板推导出整套颜色。

主题名 system 表示使用从终端提取的颜色；mode 设为 system 则表示跟随终端的明暗外观。

模式（Mode）

用 system 跟随终端外观，或把主题锁定为亮色 / 暗色：

模式行为
system跟随终端检测到的亮色或暗色外观。
dark始终使用该主题的暗色配色。
light始终使用该主题的亮色配色。

它对应 CLI 配置中 theme 里的 mode 字段。如果自定义主题只提供了一种模式，当请求另一种模式时 OpenCode 会使用已有的那种。

添加主题

要添加你下载或别人发给你的主题，把它的 JSON 文件复制进全局主题目录：

bash
cp theme.json ~/.config/opencode/themes/

也可以把主题放进项目的 .opencode/themes 目录，让它只在那个项目里可用。

文件名就是主题名。例如 my-theme.json 会显示为 my-theme。添加文件后重启 OpenCode，再运行 /themes 选择它。

⚠️ 注意

OpenCode 只读 .json 文件——把主题存成 .jsonc 或 .txt 是不会被识别的。同名主题有就近覆盖规则：离当前目录更近的主题会替换全局目录或父目录里的同名主题。改完文件别忘了重启，热重载对主题文件不生效。

在插件中使用主题

TUI 插件通过 context.theme 读取解析后的颜色，通过 context.themeMode 读取当前模式。使用语义 token（semantic token），插件就能自动跟随用户选择的主题：

tsxTUI 插件组件内部
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}

公开的 TUI 插件 API 不注册主题。想添加自定义主题定义，请使用上文目录里的 JSON 文件。

创建主题

推荐使用官方的主题工具来创建或编辑主题：它直观地展示主题结构，改起来方便，也支持定义自定义颜色。下文的解释仅作参考。

一个主题把共享的语义 token 与各模式专属的调色板分开：

部分用途
base所有模式共享的完整 token 树。
light、dark该模式的完整色相（hue）调色板，以及可选的 token 覆盖。

每个主题都必须提供完整的 base，并至少定义 light 或 dark 之一。模式从文件自己的 base 继承——不从内置 OpenCode 主题继承，模式之间也不互相继承。

🧠 通俗理解

把主题文件想成一张「双层设计图」：base 是设计规范（「正文文字用中性灰、边框要柔和」），light 和 dark 是同一规范下的两张实物渲染稿——亮色稿里墨水是深色，暗色稿里墨水是浅色，但「哪里该是正文色、哪里该是边框」的骨架完全一致。改规范一处，两种模式一起变；只想暗色特殊处理，就在 dark 里单独覆盖。

下面的示例只展示与各概念相关的部分。定制前请先用主题编辑器生成完整文件。

结构

两种模式都用的颜色放进 base，需要时再在 light 或 dark 里覆盖：

theme.json（节选）
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}

完整的 base 提供每个语义 token；每种模式提供全部必需的色相，并可以覆盖 base token 树的任意部分。

颜色与引用

颜色可以是十六进制值、"transparent"，或对主题内另一个颜色的引用：

base 或模式内部
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}

色相（Hues）

色相是九级色阶。每种模式要定义八个基础色相和三个别名：

类别取值
基础色相gray、red、orange、yellow、green、cyan、blue、purple
别名accent、interactive、neutral
色阶100、200、300、400、500、600、700、800、900

基础色相要定义全部九级，或者把一个别名直接指向另一个色相：

light 或 dark 内部
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}

色阶的方向跟随模式的对比方向：亮色主题从 100（深）渐变到 900（浅）；暗色主题从 100（浅）渐变到 900（深）。

base 里的 categorical 数组设定用于区分 agent 和其它重复项的色相顺序：

base 内部
{
  "categorical": ["accent", "purple", "green", "blue"]
}

语义 token

语义 token 给 UI 角色分配颜色。组件使用这些角色，而不是直接挑颜色。

组用途
text正文、次要、弱化、动作、表单字段和反馈文字。faint 默认等于 muted。
background基础底色、抬升表面、动作、表单字段和反馈填充。
border、scrollbar边框和滚动条颜色。
diff新增、删除、上下文、高亮和行号颜色。
syntax源码高亮。
markdownMarkdown 元素。

例如 text.muted 控制次要文字，background.raised 定义逐级抬升的表面：

base 内部
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}

语法（syntax）键有：comment、keyword、function、variable、string、number、type、operator、punctuation。

Markdown 键有：text、heading、link、linkText、code、blockQuote、emphasis、strong、horizontalRule、listItem、listEnumeration、image、imageText、codeBlock。

动作与状态

动作有 primary、secondary、destructive 三种变体。动作和表单字段使用 base 加可选的交互状态：

base 或模式内部
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}

状态键有 $hovered、$focused、$pressed、$selected 和 $disabled。未指定的状态直接使用该动作或表单字段的 base 颜色。

对话框表面

面板、对话框、菜单和 toast 从 background.raised 中选取深度。对话框还可以用 @dialog 额外覆盖语义 token：

base 或模式内部
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}

TUI 在应用 @dialog 之后会重新解析引用，所以引用 $background.base 的 token 会跟随对话框的背景色。上下文动作的 base 成为其未指定状态的回退值；显式的状态覆盖依然优先。

💡 扩展

「语义 token + 色相引用」这套体系的核心价值是解耦：组件永远只说「给我 text.muted」，至于 muted 到底是浅灰还是深灰，由主题和模式决定。所以给 OpenCode 做一个新主题时，不需要理解任何界面的内部实现，只要把八个基础色相铺满九级、再把 base token 树填好，整界面的观感就成型了。想参考成品可以直接读内置主题的 JSON 文件。
