快照

快照（Snapshots）让你把最近的对话和文件改动一起撤销，用来对刚刚完成的工作「反悔重做」。但它只是便利工具，不是备份——重要的工作请照常提交 Git 或做备份。

工作流（Workflow）

对某个回复不满意时，运行 /undo。OpenCode 会暂存（stage）一次回滚、恢复受影响的文件，并把被移除的那条 prompt 放回输入框，让你修改：

TUI 命令
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.

提交修改后的 prompt 时，暂存的回滚会一并生效。提交之前，随时可以运行 /redo 取消回滚，恢复到 /undo 之前的对话和文件状态：

TUI 命令
/redo

终端界面还有默认快捷键：

动作命令快捷键
暂存上一条消息的回滚/undo<leader>u
取消已暂存的回滚/redo<leader>r

也可以选中更早的一条消息，选择 Revert，把回滚点暂存到那个位置。

捕获（Capture）

每个模型步骤中，OpenCode 会在调用模型之前立即尝试拍一次快照，并在该步骤达到一次记录的成功或失败时再拍一次。assistant 消息会记录这两次快照之间哪些路径发生了变化：

text时序示意
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts

捕获是尽力而为（best effort）。如果任何一侧快照不可用，对话照常继续，但那一步可能没有可供恢复的文件改动记录。

覆盖范围（Scope）

快照覆盖 Git worktree 中会话的活动目录。比如会话在 packages/app 中打开，就只捕获 packages/app 之下的符合条件的文件，仓库其它位置的改动不在内：

内容是否捕获示例
活动目录内被 Git 跟踪的文件是packages/app/src/app.tsx
未被忽略的未跟踪文件，每个不超过 2 MiB是packages/app/notes.txt
被 Git 忽略的文件否packages/app/dist/app.js
超过 2 MiB 的单个未跟踪文件否packages/app/debug.log
活动目录之外的文件否packages/server/src/index.ts
Git 元数据和其它副作用否提交、分支、数据库、进程

⚠️ 注意

文件系统快照需要一个 Git 仓库。在 Git 仓库之外，/undo 仍然可以回滚对话历史，但无法恢复文件。

恢复（Restore）

回滚只恢复「所选对话边界之后、归属于 assistant 步骤」的那些路径。每个路径回到第一个被撤销步骤之前的状态；如果某个文件是这些步骤新建的、当时并不存在，就把它删除：

时间线src/api.tssrc/new.ts
所选边界版本 A不存在
之后的 assistant 步骤版本 B被创建
回滚之后版本 A被删除

不属于这些步骤的路径不会被碰。受影响路径上的当前未保存修改可能被覆盖，所以继续工作前先看一下恢复摘要和 git diff：

sh
git diff --stat
git diff

存储（Storage）

OpenCode 把快照存储在本地：数据目录下一个独立的内部 Git 对象数据库。快照捕获不会创建提交、移动分支，也不会有意改动你仓库的索引：

sh捕获后你的仓库仍是普通的脏工作区
# Your repository remains an ordinary dirty worktree after capture.
git status --short

快照对象可能包含被跟踪文件和符合条件的未跟踪文件的完整内容。请把 OpenCode 数据目录当作敏感的本地数据对待。

设置（Settings）

快照默认启用。在配置里把 snapshots 设为 false 可以停止今后的文件系统捕获：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}

禁用快照不会删除已存储的快照。对话回滚仍然可用，但没有捕获的文件系统状态就无法恢复相关的文件改动了。

安全性（Safety）

快照是便利工具，不是事务，也不是备份：

  • shell 命令可能改变服务、进程、网络资源、数据库、Git 状态、被忽略的输出或活动目录之外的文件。恢复快照不会撤销这些效果。
  • 被中断或失败的工作，可能在捕获失败或没有可用快照对时留下改动。
  • 恢复受影响路径会覆盖其当前内容。取消一次已暂存的回滚也可能覆盖更晚的编辑。
  • 会话运行期间 OpenCode 会拒绝回滚操作，但外部编辑器和命令仍可能在捕获和恢复之间改动工作区。
  • 提交一次回滚只是把消息从当前对话视图中移除，并不会从持久化的会话历史或已有的快照存储中删除。它不是安全擦除。

💡 扩展

在一个有未提交改动的脏工作区里使用 /undo 之前，先把重要工作提交或备份。一句话记住快照的定位：它负责「智能体刚刚改的文件 + 刚才那句 prompt」，Git 负责「一切真正重要的东西」。两者互补，不能互相替代。
