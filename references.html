References

Reference（引用）让 OpenCode 能以具名方式访问当前项目之外的目录。在 opencode.json / opencode.jsonc 里定义一个引用，需要时在客户端里附加它的别名（alias）即可。

🧠 通俗理解

OpenCode 默认只在「当前项目」里干活，但你的资料往往散落在别处——另一个仓库的文档、隔壁的设计系统、公司内网 GitLab 上的 SDK 源码。Reference 就是给这些外部目录起个「花名」并登记在册：先在配置里声明 docs → ../product-docs，之后只要跟 AI 说「看看 docs」，它就知道去哪找。相当于给智能体发了一张「跨项目通行证」。

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and terminology",
    },
  },
}

附加 docs 之后，让智能体去查看相关路径即可：

text
Read the attached docs reference and summarize api/authentication.md.

适合用 Reference 的场景：文档、共享库、示例代码，或来自另一个仓库的源码。

本地目录

本地目录用 path 字段：

opencode.jsonc
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when working with components or design tokens",
    },
  },
}

路径的解析规则：

  • 相对路径从配置文件所在目录开始解析。
  • 支持绝对路径。
  • 支持家目录相对路径，如 ~/docs。

如果不需要其它字段，可以直接用字符串简写：

opencode.jsonc
{
  "references": {
    "docs": "../docs",
    "shared": "~/work/shared",
  },
}

⚠️ 注意

字符串简写只有在以 .、/ 或 ~ 开头时才被视为本地路径。要写 ./docs 而不是 docs——裸写的 docs 会被当成一个 Git 仓库（GitHub 上的 owner/repo 简写），结果完全不 同。

Git 仓库

远程 Git 仓库用 repository 字段：

opencode.jsonc
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
    "internal-sdk": {
      "repository": "git@gitlab.example.com:platform/sdk.git",
      "branch": "release/v2",
    },
  },
}

支持以下远程形式：

  • GitHub 的 owner/repo 简写
  • Git URL
  • host/path 形式
  • SCP 风格的 remote 写法

不支持本地的 file: 仓库。

用字符串简写时，会跟踪远程仓库的默认分支：

opencode.jsonc
{
  "references": {
    "effect": "Effect-TS/effect",
    "sdk": "gitlab.com/platform/sdk",
  },
}

不写 branch 时，OpenCode 会检出并刷新远程的默认分支。分支名可以包含字母、数字、/、_、.、-，但不能以 - 开头，也不能包含 ..。

opencode.jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "release/v2.1",
    },
  },
}

存储位置

OpenCode 会把每个远程地址规范化，并按「一个远程 + 一个分支 = 一份检出」存放在全局数据目录下。不指定分支时，路径结构是：

text
opencode/repos/<host>/<repository-path>

在典型的 Linux 环境里，Effect-TS/effect 存放在：

text
~/.local/share/opencode/repos/github.com/Effect-TS/effect

如果指定了分支，路径会追加一个编码后的 @<branch> 后缀：

text
~/.local/share/opencode/repos/github.com/Effect-TS/effect@main

刷新机制

缺失的仓库会被异步克隆。已存在的检出则会在后台检查：引用加载或重载时、以及新用户提示被允许进入其 Location 之后。

text
Prompt admitted → refresh check starts in background → agent continues

一份检出在满足以下条件时才需要刷新：上次刷新尝试距今至少 24 小时，或者从未尝试过。刷新会拉取远端并重置到配置的分支（或远程默认分支）。

text
Last attempt: 25 hours ago → eligible
Last attempt: 2 hours ago  → skipped

刷新遵循这些规则：

  • 时间戳跨服务重启持久保存。
  • 使用同一份检出的 Location 共享同一个时间戳。
  • 失败的尝试会被记录，同样受 24 小时限流约束。
  • Location 未使用时，不会有周期性轮询。
  • 某个引用克隆或刷新失败，不影响其它引用加载。

提示词不会等待克隆或刷新完成。附件里可能是旧内容，即使之后工具读文件时已经看到了更新后的检出；新引用也可能在它的检出就绪之前就已出现。

text
Attachment created → cached content
Background refresh completes → later tool read sees newer content

⚠️ 注意

缓存的检出是共享的，智能体正在使用时也可能被后台刷新。不要直接去编辑缓存目录里的文件——刷新会把它们重置掉，你的改动会丢。

使用引导

description 字段告诉智能体这个引用什么时候相关。带 description 的引用会连同别名和解析出的路径一起出现在智能体的指令（instructions）里。

opencode.jsonc
{
  "references": {
    "docs": {
      "path": "../docs",
      "description": "Use for product behavior and terminology",
    },
  },
}

没写 description 的引用对客户端仍然可用，但不会被自动推荐：

opencode.jsonc
{
  "references": {
    "archive": {
      "path": "../archive",
    },
  },
}

可见性

把 hidden 设为 true，可以把某个引用从交互式客户端的选择器里隐藏：

opencode.jsonc
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal service behavior",
      "hidden": true,
    },
  },
}

hidden 只影响交互界面的可见性。该引用仍然会出现在 Reference API 中，并且如果它有 description，也仍会出现在智能体指令里。

使用方式

客户端通过根别名（root alias）附加一个引用。附件里包含该根目录直接子级文件和目录的非递归列表。

text
Attached alias: docs
Ask: Inspect docs/guides/deployment.md and explain the deployment steps.

需要根目录之下的具体内容时，直接让智能体查看具体路径即可。

💡 扩展

「附加引用」给出的只是一层目录清单，不是整个目录的内容快照——这是为了控制上下文占用。把它当作一张「地图」：AI 看到顶层结构后，再用读文件工具钻进感兴趣的文件。所以提示词里最好直接点名，比如「看看 docs/guides/deployment.md」，比含糊地说「了解 docs」效率高得多。

权限

Reference 不会授予额外的工具权限。访问当前 Location 之外的路径仍然遵守正常的工具规则和 external_directory 权限；要编辑还需要相应的编辑权限。

text
Read ../product-docs/api.md

只有当当前权限允许这次外部读取时，这个请求才会成功。

🧠 通俗理解

Reference 是「登记处」，不是「通行证」：登记一个外部目录只是让 AI 知道它在哪、叫什么，真要读它时仍然要走权限门卫（external_directory）那一关。想放开读取范围，去 权限一章配置。

字段一览

字段本地Git说明
path必填否本地目录路径
repository否必填远程 Git 仓库
branch否可选要拉取并检出的分支
description可选可选说明智能体何时应使用它
hidden可选可选从交互式客户端选择器中隐藏

一个完整的 Git 条目可以用上所有与 Git 兼容的字段：

opencode.jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "main",
      "description": "Use for SDK implementation details",
      "hidden": false,
    },
  },
}

别名规则

别名不能为空，也不能包含 /、\、空白字符、反引号或逗号。

text
Valid:   docs
Invalid: product docs
Invalid: docs/api
