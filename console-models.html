模型

OpenCode Console 提供一批经过 OpenCode 团队测试和验证的模型。登录、充值、拿到 API key，就能在 OpenCode 或其他编码智能体里使用它们。

🧠 通俗理解

在 OpenCode 眼里，Console 就是一个普通的模型提供商（Provider）——和你接 OpenAI、Anthropic 的方式一模一样，只是这个「提供商」背后站着 OpenCode 官方，帮你把各家模型都筛好、调好。它完全可选，你随时可以换用任何别的提供商；如果想要按月订阅、用量打包的模式，看 OpenCode Go。

工作原理

  1. 登录控制台，填写账单信息、充值额度，然后复制你的 API key。
  2. 在 TUI 里运行 /connect，选择 OpenCode 按量付费（pay-as-you-go）提供商，粘贴你的 API key。
OpenCode 命令
/connect
  1. 运行 /models 查看可用模型并选择一个。
OpenCode 命令
/models

计费方式为按请求付费，你可以随时给账户充值额度（credits）。

Jev

Jev 是 TypeSafe AI 出品的 System One 模型，专为快速、结构化的决策而生。它不生成文本，而是把一个 state（状态描述）拿去对照一组带类型的问题进行评估，直接返回你的代码可以直接使用的取值和概率。它支持是非题（noul）、选择题（choice）和评分题（score）。

使用你的 OpenCode Console API key 调用 https://opencode.ai/inference/systemone/v1/systemone 端点。下面这个例子判断一条客服请求是否紧急：

bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.13",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'

一次请求可以同时问多个问题。Jev 会并行评估它们，并把每个答案放在对应的问题 ID 下返回：

bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.13",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'

把 jev-1.13 换成 jev-1.13-free 即可使用限时免费版本。问题类型和响应字段的详细说明见 TypeSafe AI 文档。

🧠 通俗理解

普通大模型回答「是不是紧急」会给你一段话，你还得自己解析；Jev 这类「决策模型」则像一台判断机：你投喂一段情况描述（state），它直接吐出「是/否 + 置信概率」「选项 + 概率分布」这种程序能直接消费的结果。做路由、分流、质检这类自动化决策时，它比对话模型更快、更省、更稳定。

GPT 6 Luna Decision 与 Gemini Decision 1

gpt-6-luna-decision 和 gemini-decision-1 在同一个端点上接受与 Jev 相同的 System One 请求格式。可以在 state 里以聊天式分段（part）的形式传入图片、音频、视频和 PDF（image_url、input_audio、video_url、file）。GPT 6 Luna Decision 接受文本和图片；Gemini Decision 1 还额外接受音频、视频和 PDF。

bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'

图像模型

gpt-image-2.5-sunburst、gemini-nano-banana-2.1 和 grok-imagine-image-2.0 用于生成和编辑图片。它们不是对话模型，因此永远不会出现在 /models 和 models 端点里，opencode/<model-id> 也选不中它们。要用它们，直接拿 Console key 调各自的原生 API；或者设置 experimental.image_generate.model（例如 opencode/gpt-image-2.5-sunburst），让 OpenCode 的 experimental_image_generate 工具自动调用图像模型。

bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'

Google 模型使用其原生的 contents 和 generationConfig 参数，xAI 使用其原生选项如 resolution 和 quality。OpenAI Images 和 xAI Images 还支持在 /images/edits 上进行图片编辑。

面向团队

可以通过工作区与团队共享 Console 模型。所有者（Owner）和管理员（Admin）可以邀请成员、在 Models 标签页里选择启用哪些模型、设置预算，以及连接自己的提供商。

背景

市面上可用的模型很多，但真正适合当编码智能体的只有少数几个。提供商之间在配置、性能和质量上也差异很大，所以同一个模型经过 OpenRouter 这类网关访问时，表现可能都不一样。

🧠 通俗理解

OpenCode 团队测试了一批与 OpenCode 配合良好的模型和提供商，而不是把全市场模型一股脑塞给你。换句话说，这份目录是「预筛选 + 基准测试」的产物，不是简单转发。

为构建这份模型目录，我们：

  1. 测试了一批精选模型，并与模型团队沟通最佳运行方式。
  2. 与提供商合作，确保模型被正确地提供（served）。
  3. 对每个「模型/提供商」组合做基准测试，得出一份我们真心愿意推荐的名单。

Console 本质上是一个 AI 网关（gateway），让你能够访问这些模型。

设计目标

我们打造 Console 是为了：

  1. 基准测试：为编码智能体筛选最好的模型和提供商。
  2. 最高质量：提供高质量选项，不降级性能、不偷偷路由到更便宜的提供商。
  3. 传递降价：按成本价销售，只在覆盖支付手续费时加价。
  4. 零锁定：Console 可以搭配任何编码智能体使用；OpenCode 也可以搭配任何其他提供商使用。
