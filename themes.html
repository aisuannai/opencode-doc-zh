主题

主题属于终端客户端（TUI）。在 TUI 里按 Ctrl+P 打开设置切换，或者直接写进 CLI 全局配置。也可以自己写一份 JSON 主题文件，深度定制每种颜色。

在终端界面（TUI）里按 Ctrl+P，选择 Open settings，再打开 Theme 即可选择主题。也可以直接在全局 CLI 配置里设置：

~/.config/opencode/cli.jsonJSON
{
  "theme": {
    "name": "tokyonight",
    "mode": "system"
  }
}

⚠️ 注意

主题属于终端客户端，所以主题选择要写在 cli.json 里，不要写进 opencode.json。配置位置和其它终端设置见 TUI 设置。

模式（mode）

用 system 跟随终端外观，或者把主题锁定在某个模式：

~/.config/opencode/cli.jsonJSON
{
  "theme": {
    "name": "opencode",
    "mode": "dark"
  }
}
取值行为
system跟随终端的浅色 / 深色模式。
dark始终使用深色主题。
light始终使用浅色主题。

如果自定义主题只提供了一种模式，当请求另一种模式时 OpenCode 会使用仅有的那种。

内置主题

按名称选择内置主题：

~/.config/opencode/cli.jsonJSON
{
  "theme": {
    "name": "catppuccin"
  }
}

可用主题包括：

  • aura、ayu、carbonfox、cobalt2、cursor、dracula、everforest、flexoki
  • catppuccin、catppuccin-frappe、catppuccin-macchiato
  • github、gruvbox、kanagawa、material、matrix、mercury、monokai、nightowl、nord
  • one-dark、opencode、orng、lucent-orng、osaka-jade、palenight、rosepine
  • solarized、synthwave84、tokyonight、vercel、vesper、zenburn

当 OpenCode 能读取你的终端调色板时，还有一个 system 主题可用。

主题文件

想创建一个名为 ocean 的全局主题，用主题工具在全局主题目录里生成一份完整文件。它的相关结构大致如下：

~/.config/opencode/themes/ocean.json节选
{
  "base": {
    "text": {
      "base": "#d8f3ff"
    }
  },
  "dark": {
    "hue": {
      "accent": "$hue.cyan"
    }
  }
}

然后在设置里选 ocean，或在 cli.json 里把 theme.name 设为 ocean。文件名去掉 .json 后缀就是主题名。

范围目录
全局~/.config/opencode/themes/
项目项目树中的 .opencode/themes/

OpenCode 只读取 .json 文件。离当前目录更近的主题会替换同名的全局或父级主题。

文件格式

每个 V2 主题都要声明一棵完整的 base token 树，以及至少一个 light 或 dark 色相调色板。各模式只从本文件自己的 base 继承——不会从内置 OpenCode 主题继承，也不会在模式之间互相继承。定制前请先用主题工具生成一份完整的 base。

💡 扩展

下面的示例只展示与每个概念相关的片段，不是完整的主题文件。直接拿去用会报错——完整文件必须包含整棵 base 树。

themes/ocean.json骨架示例
{
  "base": {
    "text": {
      "base": "#16324f"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": { "base": "#d8f3ff" }
  }
}

颜色写法

可以使用十六进制颜色、transparent，或对另一个主题颜色的引用：

themes/ocean.jsonJSON
{
  "base": {
    "text": {
      "base": "#d8f3ff",
      "muted": "$hue.neutral.400"
    },
    "background": {
      "base": "transparent"
    }
  }
}

十六进制值可以用 3、4、6 或 8 位。引用以 $ 开头；色相引用的格式是 $hue.<name>.<step>。

色相（Hues）

覆盖一个色相别名（alias），就能一次性改变一整族相关颜色：

themes/ocean.jsonJSON
{
  "base": {
    "categorical": ["accent", "purple", "green"]
  },
  "dark": {
    "hue": {
      "accent": "$hue.cyan",
      "interactive": "$hue.blue"
    }
  }
}
种类取值
基础色（Base）gray、red、orange、yellow、green、cyan、blue、purple
别名（Alias）accent、interactive、neutral
档位（Step）100、200、300、400、500、600、700、800、900

色相档位的方向跟随模式的对比方向：浅色主题从 100（深）到 900（浅），深色主题从 100（浅）到 900（深）。

categorical 设置用来区分智能体和其它重复项的一组有序色相。它必须至少包含一个基础色相或别名。

🧠 通俗理解

把色相体系想成颜料管：8 支基础颜料（gray 到 purple），每支有 100–900 九个深浅档；而 accent、interactive、neutral 是三支「贴了标签的颜料」——界面上的强调色、可点击色、中性色全都引用它们。你只要把标签纸换到别的颜料管上（如 accent: "$hue.cyan"），整个界面的强调色就一起换掉了，不用逐个改几十处颜色。

交互状态（States）

用状态键改变交互颜色。未指定的状态会取最靠近的基础值：

themes/ocean.jsonJSON
{
  "base": {
    "text": {
      "action": {
        "primary": {
          "base": "$hue.interactive.400",
          "$hovered": "$hue.interactive.300",
          "$disabled": "$hue.neutral.600"
        }
      }
    }
  }
}
分组取值
动作（Actions）primary、secondary、destructive
状态（States）$hovered、$focused、$pressed、$selected、$disabled

表单字段使用同样的状态键，直接写在 text.formfield 或 background.formfield 之下。

Token 组（Tokens）

完整的 base 包含所有 token 组。模式在提供完整色相调色板之后，可以覆盖它的任何部分：

themes/ocean.jsonJSON
{
  "base": {
    "border": {
      "base": "$hue.neutral.700"
    },
    "syntax": {
      "comment": "$hue.neutral.500",
      "keyword": "$hue.accent.400"
    },
    "diff": {
      "text": {
        "added": "$hue.green.400",
        "removed": "$hue.red.400"
      }
    }
  }
}
组用途
text基础、次要、弱化文本；动作、表单字段和反馈文本
background基础、表面、动作、表单字段和反馈填充
border边框
scrollbar滚动条
diff新增、删除、上下文、高亮和行号颜色
syntax源码高亮
markdownMarkdown 元素

语法高亮的键有 comment、keyword、function、variable、string、number、type、operator、punctuation。Markdown 的键有 text、heading、link、linkText、code、blockQuote、emphasis、strong、horizontalRule、listItem、listEnumeration、image、imageText、codeBlock。

浮起表面（Raised surfaces）

面板、对话框、菜单和 toast 从 background.raised 中选取自己的层次深度。对话框额外支持一个上下文相关的 @dialog 表面。TUI 在应用 @dialog 之后会重新解析调色板，所以引用 $background.base 的 token 会跟随对话框背景：

themes/ocean.jsonJSON
{
  "base": {
    "background": {
      "base": "#071521",
      "raised": {
        "base": "#0c1f2e",
        "high": "#102a3c",
        "max": "#16364b"
      }
    },
    "@dialog": {
      "background": {
        "base": "$background.raised.base"
      }
    }
  }
}

@dialog 接受与 base 模式相同的 token 组。动作在上下文中的 base 也会成为其未指定状态的回退值；显式覆盖的状态仍然优先。
