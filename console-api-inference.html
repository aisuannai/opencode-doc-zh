API · 推理

Console 推理服务在 https://opencode.ai/inference 上提供 OpenAI、Anthropic、Gemini 三种兼容 API。向与该模型 API 家族匹配的端点发送 JSON POST 请求即可。

bash最小可运行示例
curl -X POST "https://opencode.ai/inference/openai/v1/chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'

🧠 通俗理解

这里的核心思路是「协议适配，而非另起炉灶」：你不需要学一套 OpenCode 专属的调用格式。如果你的代码本来就用 OpenAI SDK，把 base_url 换成 https://opencode.ai/inference/openai/v1 就能跑；本来用 Anthropic 或 Gemini 的也一样。唯一要做的认证就是把 token 换成 OpenCode 的 API key。一个模型只会通过其中一种 API 家族对外服务——用错协议会拿不到响应，所以先查清楚它属于哪一族。

认证（Authentication）

把 <token> 替换为在 Console 中创建的个人 API key 或服务账号 key。付费模型必须带这个 header。免费档的 chat 模型只能从 OpenCode 客户端内部使用：其它客户端即使带上了 API key，也会收到 HTTP 403。想从其它客户端调用，请使用付费模型或 Go 订阅。

text
Authorization: Bearer <token>

端点（Endpoints）

API路径
OpenAI Chat Completions/inference/openai/v1/chat/completions
OpenAI Responses/inference/openai/v1/responses
Anthropic Messages/inference/anthropic/v1/messages
Gemini/inference/google/v1beta/models/<model>:generateContent

每个模型只由一种 API 家族服务。查阅模型端点表，或者直接拉取实时列表：

bash
curl https://opencode.ai/inference/v1/models

模型列表 API 一文解释了响应里每个字段的含义，以及包含你已接入提供商的 Console 列表。

OpenAI Chat Completions

开源模型（如 kimi-k3、glm-5.3、minimax-m3）以及免费模型使用 Chat Completions API：

bash
curl -X POST "https://opencode.ai/inference/openai/v1/chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glm-5.3",
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'

OpenAI Responses

GPT 系列模型使用 Responses API：

bash
curl -X POST "https://opencode.ai/inference/openai/v1/responses" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-6.1-sol",
    "input": "Say hi"
  }'

Anthropic Messages

Claude 和 Qwen 系列模型使用 Messages API。注意 max_tokens 是必填项：

bash
curl -X POST "https://opencode.ai/inference/anthropic/v1/messages" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-5-5",
    "max_tokens": 1024,
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'

⚠️ 注意

两类最常见的踩坑：一是对 Claude/Qwen 模型忘记带 max_tokens，请求会直接报错——这是 Anthropic 协议的硬性要求；二是对 GPT 模型误用了 Chat Completions 而不是 Responses（或反之）。如果不确定手里的模型属于哪一端，先 curl https://opencode.ai/inference/v1/models 查一下，或者对着 OpenCode 里的模型端点表核对。

Gemini

Gemini 模型把模型名和方法名都放在路径里。把 :generateContent 换成 :streamGenerateContent 即可流式接收响应：

bash
curl -X POST "https://opencode.ai/inference/google/v1beta/models/gemini-4-argon:generateContent" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{ "parts": [{ "text": "Say hi" }] }]
  }'

费用（Cost）

每个响应都会报告这次请求花了你多少钱，位置就在该 API 原本返回用量信息的旁边：OpenAI 和 Anthropic 放在 usage 里，Gemini 放在 usageMetadata 里。流式响应则在携带最终用量的那个事件上报告：Chat Completions 在带 stream_options.include_usage 的最终 usage chunk 上，Responses 在 response.completed 上，Messages 在 message_delta 上，Gemini 在最后一个 chunk 上。

jsonusage 中的费用字段
"usage": {
  "prompt_tokens": 1200,
  "completion_tokens": 300,
  "cost": 0.00412,
  "opencode": {
    "billing_source": "balance",
    "list_cost": 0.00412,
    "tokens": { "input": 1200, "output": 300, "reasoning": 120, "cache_read": 8000, "cache_write_5m": 0, "cache_write_1h": 0 }
  }
}
字段含义
cost从你的余额扣除的美元金额。免费模型为 0；限额内的 Go 用量也为 0。如果用的是你自己的提供商 key，则是对提供商将收取金额的估算值（除非提供商自己上报）；模型没有定价时此字段缺省。
opencode.billing_source计费来源：free（免费）、balance（余额）、go、go-plus，或 byok（你自己的提供商 key）。
opencode.list_cost按模型标价计算的美元金额，包含高峰时段和长上下文加价。
opencode.estimated当 cost 是按模型标价估算、而非 OpenCode 实际扣费时为 true。仅在使用自己的提供商 key 时出现。
opencode.allowance仅 Go 订阅：本次请求消耗了多少用量额度，以套餐每月限额的美元数计。
opencode.tokens你实际被计费的 token。input 不含缓存读和缓存写；output 包含 reasoning（推理 token）。

图像生成在响应上报告同样的字段；流式场景下，每张完成的图像也会带上至今累计的费用。费用在响应结束时即已确定，早于你的余额或 Go 用量的实际更新。如果余额或 Go 额度在请求中途用尽，你被扣的金额只会低于报告值，绝不会高于它。

💡 扩展

opencode.tokens 里的 cache_read / cache_write_5m / cache_write_1h 对控制成本很有用：读缓存远比写缓存便宜，写缓存又分 5 分钟和 1 小时两档 TTL。如果你在做长对话或多轮 agent，观察这几个字段的分布，就能判断是不是在反复为相同前缀支付缓存写入费——必要时调整请求节奏或缓存策略，能省下不少钱。
