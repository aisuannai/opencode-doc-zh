配置

在项目里创建 opencode.jsonc 即可配置 OpenCode。建议加上 schema 让编辑器自动校验，然后只写你需要的选项。

🧠 通俗理解

配置文件就是 OpenCode 的「总控制台」：默认用哪个模型、允许它执行哪些命令、启用哪些 MCP 服务器——所有开关都集中在这一个 JSON 里。它支持多层覆盖：机器级 → 用户级 → 项目级，一层比一层具体，就像浏览器设置的「系统默认 → 用户偏好 → 站点例外」。

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}

也可以让 OpenCode 替你更新这个文件。

格式

OpenCode 支持 JSON 和 JSONC。想要注释或尾逗号就用 JSONC：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-5-5",
}

配置位置

把机器级的托管设置放进系统配置目录：

平台目录
macOS/Library/Application Support/opencode
Linux/etc/opencode
Windows%ProgramData%\opencode

系统目录的用法与全局目录相同。除了 opencode.json(c)，它还会为机器上的每个用户加载 agents/、commands/、skills/ 和 plugins/：

text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md

在 macOS 上，OpenCode 还会读取 MDM 工具为 ai.opencode.managed 域下发的托管偏好。用户级的 profile 会取代机器级的那份：

text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist

托管设置的优先级最高，用户和项目都无法覆盖它设置的值，且托管偏好压过系统目录。仅靠设置本身拦不住用户添加提供商、MCP 服务器、智能体或插件；要强制限制，请在托管配置里使用 策略。

想对每个项目都生效的用户级设置放全局配置：

text
~/.config/opencode/opencode.json(c)

项目级设置放以下任一位置：

text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)

OpenCode 从当前目录向上搜索到文件系统根。它先把最远目录到最近目录的直接 opencode.json(c) 依次合并，然后按同样顺序合并 .opencode 目录里的文件。也就是说，每个被发现的 .opencode 配置都会覆盖所有直接配置。除非你确实需要这种行为，否则一棵目录树里最好统一用一种形式。

例如，从 /home/user/projects/acme/packages/web 启动 OpenCode：

text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/

OpenCode 按从低到高的优先级应用这些文件：

text
1. ~/.config/opencode/opencode.json
2. /home/user/projects/acme/opencode.json
3. /home/user/projects/acme/packages/web/opencode.json
4. /etc/opencode/opencode.json

包级配置覆盖仓库配置里匹配的设置，仓库配置覆盖全局配置，系统配置覆盖以上全部。不冲突的设置都会保留。全局和项目文件里的策略按相反顺序求值，而系统级策略压过所有策略。

⚠️ 注意

.opencode/ 目录里的配置永远压过同目录树上的直接 opencode.json(c)。团队里常见的坑：A 在根目录用直接文件、B 把同一份配置放进 .opencode/，结果 B 的「顺手一改」悄悄盖掉了根目录设置。约定统一格式能省掉这类「为什么我的配置不生效」的排查时间。

Schema

OpenCode 的完整配置 schema 在 opencode.ai/config.json。

在配置文件里加上 $schema 字段，就能在支持 JSON Schema 的编辑器里获得校验和自动补全：

opencode.json
{
  "$schema": "https://opencode.ai/config.json"
}

把 schema 当作可用字段、可接受值和嵌套结构的权威来源。

Shell

设置终端和 shell 工具使用的 shell：

opencode.jsonc
{
  "shell": "/bin/zsh",
}

模型

用 provider/model 格式设置默认模型。根级默认目前不保留 #variant；智能体和命令里的模型引用可以选变体。

opencode.jsonc
{
  "model": "anthropic/claude-sonnet-5-5",
}

模型选择和本地模型见 模型一章。

默认智能体

选择会话未显式指定时使用的主智能体：

opencode.jsonc
{
  "default_agent": "build",
}

内置与自定义智能体见 Agents一章。

更新

从全局配置控制更新检查。把 update 设为 "disable" 跳过检查、"notify" 在安装前提示可用更新、"auto" 自动安装。省略时默认 "notify"。

自动安装不会重启正在运行的服务器；重启它才能启用已安装的更新。项目级设置会被忽略。

opencode.jsonc
{
  "update": "notify",
}

用户名

设置一个用户名。OpenCode 接受该字段，但不会在对话里显示它：

opencode.jsonc
{
  "username": "alice",
}

权限

定义有序规则，在智能体对匹配资源使用工具之前执行 allow、deny 或 ask：

opencode.jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}

规则匹配与可用动作见 权限一章。

策略

允许或禁用一个提供商、对权限检查做硬拒绝，或封禁 MCP 服务器、技能、插件——用有序语句表达，更宽范围的配置可以覆盖它们：

opencode.jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}

匹配、跨配置文件的优先级和 Console 托管策略见 策略一章。

智能体

覆盖内置智能体，或定义有专属模型、指令、模式和权限的专用智能体：

opencode.jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}

全部智能体选项和基于文件的智能体见 Agents一章。

快照

启用或禁用撤销（undo）和回退（revert)行为使用的文件系统快照：

opencode.jsonc
{
  "snapshots": false,
}

撤销与重做行为见 快照一章。

文件监视

忽略不应触发文件系统更新的文件和目录：

opencode.jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}

格式化器

在 write、edit 或 patch 工具改动文件后进行格式化。把 formatter 设为 true 启用可用的内置格式化器：

opencode.jsonc
{
  "formatter": true,
}

内置与自定义格式化器见 格式化器一章。

媒体

控制 read 工具加载的超大图片在发送给模型之前如何缩放或拒绝：

opencode.jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}

图片处理与限制见 附件一章。

工具输出

设置工具结果保留的最大行数和字节数：

opencode.jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}

网页搜索

选择 OpenCode 的网页搜索方式。用 "random" 自动选择一个可用提供商：

opencode.jsonc
{
  "websearch": {
    "provider": "random",
  },
}

提供商、凭证、选择、速率限制和禁用搜索见 网页搜索一章。

MCP

配置本地和远程的 MCP 服务器。全局的 mcp.timeout 作用于配置文件里定义的服务器；每个服务器自己的 timeout 覆盖它：

opencode.jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}

远程服务器、OAuth、环境变量和超时见 MCP 服务器一章。

上下文压缩

控制自动上下文压缩，以及它保留多少近期上下文：

opencode.jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": "15%",
  },
}

buffer 是自动压缩启动前，模型上下文窗口中保持空闲的比例。

本地摘要仍是默认。想对自动和手动压缩都启用原生的提供商压缩，用提供商或模型策略选择：

opencode.jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}

模型设置覆盖提供商设置。自动压缩使用所选模型的可用输入预算。提供商检查点把近期用户消息保持在同一个 compaction.keep.tokens 预算内（本地摘要用它保留尾部）。顶层 compaction.auto: false 会停止新的自动压缩，但不会丢弃已安装的检查点。预算与溢出恢复见 上下文压缩一章。

会话预热

用周期性的临时请求让最近活跃的模型会话保持「温热」。预热默认关闭；设为 true 即在每个模型的缓存即将过期前预热，最长 30 分钟：

opencode.jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "auto",
    "duration": "30 minutes",
  },
}

提供商或模型的 settings.cache.warming 会覆盖它，settings.cache.ttl 设置提供商保存缓存的时长。请求行为、自定义和成本考量见 会话预热一章；cache.ttl 见 模型的缓存寿命一节。

技能

添加 OpenCode 应搜索智能体技能（Skill）的目录或 URL：

opencode.jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}

技能结构和 .opencode/skills/ 下的自动发现见 Skills一章。

命令

把可复用的斜杠命令定义为具名提示词模板：

opencode.jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}

参数、模型、智能体和基于文件的命令见 自定义命令一章。

指令文件

声明额外的指令文件、glob 或 HTTP(S) URL。OpenCode 会把它们与发现的 AGENTS.md 一起加载：

opencode.jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}

项目指令与 AGENTS.md 见 指令文件一章。

References

让本地目录或 Git 仓库以具名方式作为辅助上下文可用：

opencode.jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}

简写、可见性与路径解析见 References一章。

Worktree

设置新本地 worktree 的父目录。OpenCode 会在其后追加请求的或生成的 worktree 名称：

opencode.jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}

相对路径以项目保存的规范检出（canonical checkout）为基准解析。全局和项目配置都适用；绝对路径按原样使用，~/ 从用户家目录解析。

例如，这份全局配置会把新 worktree 放到各项目自己的 .lane/trees/ 目录下：

opencode.jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}

不设置时，创建使用服务器数据目录下的 worktree/<项目 ID 前 6 位>。Worktree 的创建和刷新从项目保存的规范检出加载配置——即使其它克隆与它共享项目 ID 也一样。修改这个设置不会移动已有的 worktree。

Git 是内置默认。注册了策略的服务器插件会在其插件运行时里自动成为默认。项目操作使用规范检出的运行时。策略专属选项属于那个插件，而不是 worktree 配置对象。

插件

从包或本地插件目录加载插件。插件接受选项时用对象形式：

opencode.jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}

插件加载与配置见 插件一章。

Providers

配置提供商，添加或覆盖它们的模型、请求设置、请求头和模型变体：

opencode.jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol-custom": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}

提供商的 settings.transport: "websocket" 选择其会话 WebSocket。

凭证、自定义端点、提供商包、WebSocket 传输和模型配置见 Providers一章。

变量

配置文件里可以用变量替换引用环境变量和文件内容。引用写在 JSON 字符串里。

环境变量

用 {env:VARIABLE_NAME} 替换环境变量：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "{env:OPENCODE_MODEL}",
  "providers": {
    "anthropic": {
      "settings": {
        "apiKey": "{env:ANTHROPIC_API_KEY}",
      },
    },
  },
}

环境变量未设置时会替换为空字符串。

文件内容

用 {file:path/to/file} 替换文件内容：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": {
        "apiKey": "{file:~/.secrets/openai-key}",
      },
    },
  },
}

文件路径可以是：

  • 相对配置文件目录
  • 绝对路径，或以 ~/ 开头指向家目录

文件不存在时替换为空字符串。

典型用途：

  • 把 API key 这类敏感数据放在单独的文件里。
  • 在多个配置文件之间共享公共配置片段。

⚠️ 注意

别把 API key 明文写进 opencode.json 然后提交到仓库——配置文件通常会进版本库。用 {env:KEY} 引用环境变量，或 {file:...} 指向 ~/.secrets/ 下不被版本控制跟踪的文件。变量未设置或文件缺失时只会替换成空字符串，不会报错，所以要留意「配置看起来正常但实际没生效」的情况。

实验性设置

⚠️ 注意

实验性设置可能在任何版本中更改、损坏或被移除，且不会另行通知。不要在稳定工作流里依赖它们。

所有实验性设置都在 experimental 键下：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "todo": true,
    "subagent_depth": 2,
    "image_generate": { "model": "openai/gpt-image-2" },
    "location_idle_timeout": "4 hours",
  },
}

待办清单

把 todo 设为 true，给智能体一个 todowrite 工具来跟踪多步骤工作。默认 false。

子智能体深度

subagent_depth 设置子智能体能再启动多少层子智能体。默认 1，即子智能体不能再启动子智能体。

图片生成

image_generate 设置 内置工具里 experimental_image_generate 工具的默认模型，格式为 providerID/modelID，可选 #variant。当该模型不可用或处理不了请求时，OpenCode 会自动挑选另一个图片模型：

opencode.jsonc
{
  "experimental": {
    "image_generate": {
      "model": "openai/gpt-image-2",
    },
  },
}

位置空闲超时

location_idle_timeout 控制一个项目位置在多久没有会话活动后，OpenCode 会卸载其服务。接受如 "2 hours" 的时长，默认 "60 minutes"。运行中的会话和后台任务会让位置保持加载。设为 false 则永不卸载空闲位置。项目配置可以覆盖全局值：

opencode.jsonc
{
  "experimental": {
    "location_idle_timeout": false,
  },
}

已弃用的策略键

experimental.policies 已弃用。请改用顶层的 policies。旧键仍然有效，并合并进 policies。
