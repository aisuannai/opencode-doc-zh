客户端 (JS)

@opencode/client 是 OpenCode HTTP API 的 TypeScript 客户端。当你的应用通过网络连接一台 OpenCode 服务器时用它。它的原生类型和方法与 API 参考从同一份契约生成。插件 RPC 类型则来自导入的 RPC 定义。

🧠 通俗理解

TUI 和桌面应用内部用的就是这同一个客户端。也就是说：你用 @opencode/client 能做到的事，和官方界面能做到的事是同一集合——创建会话、发提示词、订阅事件、调用插件 RPC。把它想成「OpenCode 服务器的一副官方手套」，你套上它就能从任何 JS 应用里操作 OpenCode。

安装

sh
bun add @opencode/client

创建客户端

用服务器 URL 创建客户端，然后调用按 API 资源分组的方法：

TypeScript
import { OpenCode } from "@opencode/client"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const session = await client.session.create({
  location: { directory: "/workspace" },
})

await client.session.prompt({
  sessionID: session.id,
  text: "Review the current changes",
})

请求头与请求（Headers and requests）

把默认的认证或应用请求头通过 headers 传给 OpenCode.make。也可以提供自定义的 fetch 实现。每个操作都接受请求选项作为最后一个参数，用于 AbortSignal 或单次请求的请求头。事件订阅是例外：它们只接受订阅方本地的取消，并使用基础客户端的请求头：

TypeScript
const client = OpenCode.make({
  baseUrl: "https://opencode.example.com",
  headers: {
    authorization: `Bearer ${process.env.OPENCODE_TOKEN}`,
  },
})

await client.session.list(undefined, {
  signal: AbortSignal.timeout(10_000),
})

流式事件（Stream events）

流式端点返回异步可迭代对象：

TypeScript
for await (const event of client.event.subscribe()) {
  console.log(event.type)
}

原生和 RPC 事件订阅者在每个客户端上共享一条惰性连接。创建客户端、句柄或可迭代对象都不会打开事件连接；开始消费时才打开。中断迭代或中止一个订阅者只会结束那个迭代器。最后一个订阅者离开时关闭连接。共享源会等待活跃订阅者逐个接收事件；消费者要做慢活之前请先自己缓冲。

订阅是「活性」的（live-only）：没有重放，也没有自动重连。源故障会结束当前订阅；恢复后请重新订阅。后到的原生订阅者会收到当前的 server.connected 标记，而不是过去的业务事件。

传 types 可以只接收部分事件类型。事件类型随之收窄，且 server.connected 总会到达，这样被过滤的订阅者仍然知道何时该重新同步。过滤发生在共享连接上、客户端内部：

TypeScript
for await (const event of client.event.subscribe({ types: ["config.updated"] })) {
  // event.type 是 "config.updated" | "server.connected"
}

插件 RPC（Plugin RPC）

导入插件的共享契约并传给 client.rpc：

TypeScript
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const acme = client.rpc(Acme)
const result = await acme.search(
  { query: "hello" },
  { location: { directory: "/workspace" }, signal: AbortSignal.timeout(10_000) },
)

const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})

第二个可选的方法参数持有 location、signal 和 headers，与插件定义的输入分开。省略 location 时遵循原生请求的默认值：先是基础 location 请求头，然后是服务器的工作目录。构造子客户端时不会选中任何 location。

方法从定义推断参数和结果类型。Schema 解析属于契约边界的事：调用方发送可接受的输入表示，处理器收到的是解析后的值。Promise 客户端接受 Standard Schema 或纯 JSON Schema 定义，不在本地运行 schema 解析器：服务器返回的是已经解析并转换过的输出。Effect Schema 定义需要 Effect 客户端（见 Effect 客户端）。

已声明的方法错误像其它 Promise 客户端端点的错误一样 reject，捕获到的错误不带类型。通用 HTTP RPC 错误包装被类型化子客户端剥掉了。保留的 rpc.* 框架失败仍是普通 RPC 失败，而不相关的认证、传输和协议错误保持它们正常的客户端表示。

RPC 订阅使用本地名，并接收该 RPC 来自所有位置的事件。检查必需的 event.location 来过滤它们。events.subscribe 与原生异步可迭代 API 一致：

TypeScript
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}

events.on 是同一个源之上的便捷包装。它返回取消订阅函数；异步回调按顺序依次 await。回调或源故障会被记录并结束该监听器。原生和类型化订阅收到同样的、正常的 rpc.<rpcID>.<event> 信封，事件数据是直接的对象。活性订阅不重放错过的事件。

前提是服务器插件已被配置并实现了该 RPC；导入定义并不等于注册它。定义与注册 API 见 插件 RPC。任何 HTTP 客户端也可以直接调用通用的 POST /api/rpc/{rpcID}/{method} 路由，body 为 { "input": ... }，返回 { "output": ... }。省略的 input/output 字段表示没有值。

本地后台服务（Local background service）

客户端的主入口是浏览器兼容的，不包含本地进程管理。在 Node 应用里，从 @opencode/client/service 导入原生的 Promise 服务 API：

  • Service.discover() 返回一个健康的已注册端点，不启动进程。
  • Service.ensure() 返回一个兼容的服务，需要时启动一个。
  • Service.stop() 停止确切的那个已注册服务实例。
  • Service.headers(endpoint) 为客户端生成认证请求头。
TypeScript
import { OpenCode } from "@opencode/client"
import { Service } from "@opencode/client/service"

const endpoint = await Service.ensure()
const client = OpenCode.make({
  baseUrl: endpoint.url,
  headers: Service.headers(endpoint),
})

const info = await client.server.info()

Service.ensure() 接受可选的注册文件、版本、服务命令和 onStart 回调。version 接受精确值或兼容性谓词：

TypeScript
const endpoint = await Service.ensure({
  file: "/var/run/opencode/service.json",
  version: (version) => version.startsWith("2."),
  command: ["opencode", "serve", "--service"],
  onStart(reason, previousVersion) {
    console.log(reason, previousVersion)
  },
})

省略这些选项时，使用标准注册路径和 opencode serve --service 命令。

💡 扩展

选型速查：已有 OpenCode 在跑（比如用户开着 TUI/桌面）→ 直接 OpenCode.make({ baseUrl }) 连上去；你的应用要自己拉起一个本地 OpenCode → 用 Service.ensure()，它发现可复用的就复用，没有才启动；全在浏览器里 → 主入口天然兼容。服务器端超时统一用 AbortSignal.timeout() 控制即可，事件订阅的取消要靠中断迭代本身。
