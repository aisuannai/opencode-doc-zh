TUI 插件

在 opencode.json(c) 里配置、且暴露了 TUI 组件的插件，会被 CLI 自动加载。想学习如何开发插件，见构建插件一章。不需要把同一个包再写进 cli.json——CLI 从所连接的 OpenCode 服务器获取激活的插件列表，所以即使服务器在远程也一样生效。

🧠 通俗理解

插件分两种加载来源：opencode.json 里的插件跟着服务器走（哪怕服务器在远程机器上，TUI 也能拿到它们的组件）；cli.json 里的插件则只在本地终端运行，即使 CLI 连的是远程服务器也保持活跃。前者像公司统一配发的工牌，后者像你自己的私人物品——各管各的，互不冲突。

CLI 专属插件

用 cli.json 配置仅限 CLI 使用的插件。这些插件在终端里本地运行：

cli.json
{
  "plugins": [
    "opencode.example",
    "opencode.example@1.0.0",
    "@example/opencode-tui",
    "@example/opencode-tui@1.0.0",
    "./plugins/status",
    "../plugins/status",
    "/home/user/plugins/status",
    "file:///home/user/plugins/status"
  ]
}

条目按顺序处理。在 ID 或通配符前加 - 可以禁用匹配的插件：

cli.json
{
  "plugins": ["*", "-opencode.notifications", "-team.*"]
}

用对象形式可以给插件传选项：

cli.json
{
  "plugins": [
    {
      "package": "@example/opencode-tui",
      "options": {
        "compact": true
      }
    }
  ]
}

本地发现

OpenCode 还会在全局配置目录和项目的 .opencode 目录下自动发现插件。每个插件使用与已发布包相同的目录结构，服务器和 TUI 入口放在一起：

插件发现路径
<global-config>/plugins/status/index.ts
<global-config>/plugins/status/tui.ts
<project>/.opencode/plugins/status/index.ts
<project>/.opencode/plugins/status/tui.ts

被发现的插件可以直接 import "@opencode/plugin/tui"，OpenCode 会在运行时解析这个包。示例见构建 TUI 插件。

💡 扩展

「自动发现」意味着本地开发的插件甚至不用注册：在项目的 .opencode/plugins/ 下建好目录、写好 index.ts 和 tui.ts，重启 OpenCode 就会生效。这非常适合快速迭代自己的状态栏小组件——配合 opencode plugin list 可以确认它确实被加载了。
