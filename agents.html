Agents

智能体（Agent）= 系统提示词 + 模型偏好 + 权限 + 显示信息的打包配置。写一个 Markdown 文件就能创建一个可复用的智能体，比如一个只读的代码审查员。

下面这个例子添加了一个只读的 reviewer 智能体，主智能体可以在代码审查时调用它：

.opencode/agents/reviewer.mdMarkdown
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-5-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.

然后让主智能体使用它：

text
Use the reviewer subagent to review my current changes.

🧠 通俗理解

把智能体想成公司里的一个「岗位说明书」：上面写清楚这个人（模型）是谁、负责什么（系统提示词）、能不能动某些东西（权限）、用哪台机器干活（模型偏好）。主智能体是「项目经理」，遇到需要专人的活就按岗位说明书把人拉进来干一段，干完汇报，上下文互不污染。

存放位置

Markdown 智能体可以全局保存（对所有项目生效），也可以放在项目内部：

text两种位置
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md

OpenCode 会从当前目录逐级向上查找项目的 .opencode 目录，一直到项目根。嵌套路径会成为智能体 ID 的一部分：

text路径 → ID
.opencode/agents/team/reviewer.md  →  team/reviewer

两种格式

Markdown

Markdown 格式的 frontmatter 接受与 agents 配置项相同的字段。Markdown 正文部分会成为该智能体的 system 系统提示词：

.opencode/agents/explainer.mdMarkdown
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.

⚠️ 注意

V1 版本的 frontmatter 字段已被弃用。仍在使用这些旧字段的文件如何被读取，见 从 V1 迁移 的「Agent 文件」一节。新写的智能体请直接用 V2 字段。

JSONC

也可以在任意 OpenCode 配置文件的 agents 键下定义智能体：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}

默认智能体

设置会话未主动选择时使用的主智能体：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}

指定的默认值必须真实存在、可见，并且支持 primary 用途。否则 OpenCode 会退回使用 build，再不行就用第一个可见且支持 primary 的智能体。修改这个设置不会替换已有会话上保存的智能体。

模式（mode）

根据智能体应该在哪里运行来设置 mode：

jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
模式行为
primary作为会话的主智能体运行。新建自定义智能体时这是默认值。
subagent只能通过 subagent 工具在子会话中运行。
all既可以当主智能体，也可以当子智能体。

子智能体（subagent）在自己的子会话中以全新上下文运行。它们总是在后台运行：父会话会在子会话空闲时收到一份报告，之后每完成一轮工作都会再收到一次。父智能体的 subagent 权限决定它能启动哪些子智能体；子智能体则使用自己配置的权限。

jsonc限制可启动的子智能体
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}

内置智能体

OpenCode 自带以下可见智能体：

智能体模式用途
Build（build）primary默认的编码智能体。默认允许使用工具和访问工作区之外的资源；读取敏感的环境变量文件时会请求批准。
Plan（plan）primary只探索和规划，不修改普通项目文件。被要求时可以写 OpenCode 的 plan 文件，shell 命令仍受权限控制。
General（general）subagent处理调研和多步骤工作，工具访问范围广，但不能再启动更多子智能体。
Explore（explore）subagent搜索和阅读代码或网页资源，不修改文件。

使用与内置智能体相同的 ID 即可覆盖它：

jsonc覆盖内置 build
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}

隐藏的 compaction、title 和 summary 智能体负责维护性工作，不能被直接选中。V2 没有内置的 scout 智能体。

合并规则

智能体定义按配置顺序合并。靠后的标量值替换靠前的值，请求映射（map）按键合并，权限规则则追加：

jsonc权限是追加的
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}

全局 permissions 会先于智能体专属规则生效，所以后面的智能体规则可以对其进行细化收窄。

全部选项

description（描述）

description 说明智能体的用途。子智能体一定要写，因为 OpenCode 会把它展示给负责挑选智能体的模型：

yaml
description: Reviews database migrations for safety

mode（模式）

mode 接受 primary、subagent 或 all。新建自定义智能体省略时默认为 primary：

yaml
mode: all

model（模型）

model 使用 provider/model 格式，可以加可选的 #variant：

yaml
model: anthropic/claude-sonnet-5-5#high

JSON 配置也接受展开形式：

jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-5-5",
        "variant": "high",
      },
    },
  },
}
  • 子智能体使用自己配置的模型；未配置时继承父会话的模型。
  • 会话单独保存自己选定的模型。按 ID 选择主智能体不会改变这个模型。

system（系统提示词）

system 设置智能体的系统提示词。非空值会替换该智能体所用的提供商基础提示词：

jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}

项目指令、skills、references 等其它指令来源仍会附加。在 Markdown 智能体里，把这段文字写在文档正文中，不要写 system frontmatter 字段。

permissions（权限）

permissions 是一个按顺序匹配的规则列表：

jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
字段含义
action工具或权限动作。支持通配符。
resource路径、命令、智能体 ID 或该动作匹配的其它值。支持通配符。
effectallow、ask 或 deny。

最后一条匹配的规则胜出，所以宽泛规则要放在前面，例外放在后面。常见动作包括：

动作覆盖范围
shellshell 命令
edit编辑、写入、补丁类工具
subagent子智能体
read、glob、grep本地探索类工具
webfetch、websearch网页类工具
skillSkill 加载

对于 read、edit 和 external_directory 的资源值，OpenCode 会展开 ~ 和 $HOME：

jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }

shell 资源保持原始命令文本，不做这些展开。

steps（步数上限）

steps 设置模型步数的最大值（正整数）：

yaml
steps: 8

到最后一步时，OpenCode 会移除工具并要求模型用文字总结。新的用户输入会重置这个额度。

hidden（隐藏）

hidden 把智能体从常规列表、交互式发现和子智能体目录中移除：

yaml
hidden: true

⚠️ 注意

hidden 控制的是可见性，不是安全。想限制智能体能做什么，请用 permissions。

color（颜色）

color 用六位十六进制值设置智能体在界面上的颜色：

yaml
color: "#ff6b6b"

disabled（禁用）

disabled 在配置加载到该处时移除一个内置或自定义智能体：

jsonc禁用内置 plan
{
  "agents": {
    "plan": { "disabled": true },
  },
}

request（请求定制）

request 接受针对单个智能体的请求头和 JSON body 覆盖：

jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}

⚠️ 注意

V2 会话运行器目前只是保留了这些值，还没有把它们随模型请求一起发送。想让请求定制立即生效，请配置在 provider、model 或 model variant 上。

💡 扩展

新的 V2 智能体配置中不要再使用旧的顶层字段，如 temperature、top_p、prompt、permission、tools、disable、maxSteps——这些都是 V1 时代的遗留写法，V2 已经用新的分层结构（request、permissions、steps 等）取代了它们。
