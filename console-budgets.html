预算

预算（Budgets）通过策略（policies）为每月支出设置上限。所有者（Owner）和管理员（Admin）在 Controls 页管理它们。

🧠 通俗理解

预算就像给整个团队、每个成员、每台自动化机器人各办一张「月度消费卡」：卡里预存了本月的额度上限，刷爆了就统统拒付（HTTP 429），等下月 1 号自动「充值」。它防的是两件事——某个同事半夜让模型疯狂跑长任务把公司账单刷爆，以及自动化脚本失控烧钱。额度可粗（整个工作区一张卡）可细（按标签、按具体成员、按服务账号发卡）。

预算层级

策略受众适用于
整个工作区（Entire workspace）所有成员和服务账号的总支出
所有成员（All members）每位成员各一份，或全组共享一份
带某标签的成员（Members tagged with）拥有所选标签的成员
这些成员（These members）指定的具体成员
所有服务账号（All service accounts）每个服务账号各一份，或共享一份
这些服务账号（These service accounts）指定的具体服务账号

一个请求必须落在每一层适用的预算之内。更大的额度永远不会覆盖更小的那个。如果完全没有预算，支出是不设上限的。

工作区预算

工作区预算一旦触顶，会对所有人阻断请求。

  1. 打开 Controls，点击 Add policy。
  2. 选择 Entire workspace，添加一条 Budget 规则。
  3. 输入以美元计的月度上限，点击 Save。

成员预算

在策略中选择 All members，可以给每位成员各发一份月度额度，或让全组共享一份。选择具体成员或标签，可以只覆盖一个小群体。

给某个人单独设预算：

  1. 在 Settings › Members 中打开该成员。
  2. 点击 Create budget policy，构建器会带着这个人打开。
  3. 输入金额，点击 Save。

他的成员页面会列出适用的策略。如果同时还有一条全员预算也覆盖到他，两道上限同时生效。

服务账号预算

在 Controls 中选择 All service accounts 或 These service accounts，添加一条 Budget 规则，并设置单人额度或共享的月度额度。该策略覆盖这些账号名下的每一个 key。

金额与重置

  • 金额以美元计，最多两位小数。
  • 预算在每月 1 日 00:00 UTC 重置。
  • $0 预算会阻断所有计入预算的支出。
  • 新增或修改预算时，当月已记录的支出会被计入——额度不会因此清零重来。

⚠️ 注意

「月中加预算不清零」这一点很容易误解：假如 15 号才建了一条 $50 的全员预算，而团队这半个月已经花了 $60，那这条预算立刻就把所有人拦住了，不是「从今天起再给 $50」。给存量团队上预算前，先去 Activity › Usage 看看本月已经花了多少。

什么会计入预算

默认情况下，预算覆盖全部支出（All spend）。你也可以把范围缩小到所选模型；此时只有这些模型计入，且可以选择整组共享一份额度，或每个模型单独一份。

支出是否计入预算
Console 付费模型计入
自有提供商上设置了价格的模型计入，按配置的价格
网页搜索计入，仅限全支出（all-spend）预算
免费模型不计入
Go 计划内的用量不计入
用额度支付的 Go 超额用量计入

💡 扩展

注意「计划内 Go 用量不计入」和「Go 超额用量计入」的分界：Go 订阅相当于「先包月、后计费」，包月部分花了多少都不吃预算；但一旦开了 Extra Usage 走按量扣款，这部分又回到预算管控之内。想在预算上完全精确控成本，就把 Go 超额功能关掉。

触达预算之后

新请求会以 HTTP 429 失败，直到预算重置，或有所有者/管理员调高上限。响应会表明这是一次策略预算失败，但不会点名是哪个预算。在 Activity › Logs 中打开该请求，即可看到拦截它的策略。

text错误信息
Upstream request failed: Policy budget exceeded

预算在请求开始时检查。已经开始的请求会跑完，所以最终支出可能略微超出上限。

追踪支出

每位成员都能在 Activity 页看到自己的支出和上限。打开 My usage 进入 Activity › Overview，其中包括预算详情和重置日期。

所有者和管理员可以从支出图表打开 Activity › Usage。它按天、按模型、按人细分成本，Export usage 按钮可以下载最近 7、30 或 90 天的每日汇总 CSV。
