自定义命令

把常用的 prompt 模板变成一个斜杠命令：写一个 Markdown 文件，就有 /review 可用了。支持参数占位、嵌 shell 命令、指定智能体和模型、后台运行。

创建 .opencode/commands/review.md，就能把一段 prompt 变成 /review：

.opencode/commands/review.mdMarkdown
Review $ARGUMENTS for bugs and missing tests.

在 TUI 里带着目标运行它：

TUI 命令
/review src/auth.ts

OpenCode 会把 Review src/auth.ts for bugs and missing tests. 作为用户 prompt 提交。

Markdown 命令

全局命令放在 ~/.config/opencode/commands/，项目命令放在 .opencode/commands/：

text两种位置
~/.config/opencode/commands/review.md
.opencode/commands/review.md

只发现 .md 文件。嵌套路径会成为带 / 分隔符的命令名：

.opencode/commands/team/review.mdMarkdown
Review $ARGUMENTS using the team's checklist.

用 /team/review src/auth.ts 运行嵌套命令。旧版单数目录 command/ 也会被发现，但新文件请用 commands/。

命令需要元数据时加上 YAML frontmatter。裁剪后的 Markdown 正文始终是 prompt 模板：

.opencode/commands/review.mdMarkdown
---
description: Review code for correctness
agent: plan
model: anthropic/claude-sonnet-5-5#high
---

Review $ARGUMENTS. Report bugs first.

JSON 命令

在任意 OpenCode JSON 或 JSONC 配置文件的 commands 键下定义命令。每个命令必须有 template：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "commands": {
    "review": {
      "description": "Review code for correctness",
      "template": "Review $ARGUMENTS. Report bugs first.",
    },
  },
}

字段（Fields）

Markdown frontmatter 和 JSON 条目接受相同的字段，区别是 Markdown 的 template 来自文件正文。

字段必填行为
template仅 JSON 必填prompt 模板。
description否在命令列表和发现机制中显示的文字。
agent否命令运行时选用的智能体。
model否模型覆盖，格式为 provider/model 或 provider/model#variant。
subagent否true 在后台子会话中运行；false 强制在当前会话运行。
subtask否subagent 的弃用别名。

例如，这个 JSON 命令设置了当前所有可选字段：

opencode.jsoncJSONC
{
  "commands": {
    "audit": {
      "template": "Audit $ARGUMENTS.",
      "description": "Audit a package",
      "agent": "general",
      "model": "anthropic/claude-sonnet-5-5#high",
      "subagent": true,
    },
  },
}

⚠️ 注意

不要把 template 写进 Markdown frontmatter——正文本身就是模板。frontmatter 里再写 template 是无效的。

参数（Arguments）

用 $ARGUMENTS 表示用户输入的完整参数字符串，原样保留：

.opencode/commands/component.mdMarkdown
Create a typed React component named $ARGUMENTS.

运行 /component Account Settings 时，占位符变成 Account Settings。

位置参数（Positions）

用 $1、$2 等编号表示解析出的位置参数。单引号或双引号可以给多个词分组，引号本身会被去掉：

.opencode/commands/check.mdMarkdown
Check $1. Focus on $2.

运行 /check src/auth.ts "error handling" 时，$1 是 src/auth.ts，$2 是 error handling。

编号最大的占位符会吃掉它对应的参数以及之后的所有内容。缺失的位置会变成空字符串：

.opencode/commands/compare.mdMarkdown
Compare $1 with $2.

运行 /compare api stable branch 时，OpenCode 提交 Compare api with stable branch.

回退（Fallback）

模板里没有 $ARGUMENTS 也没有位置占位符时，OpenCode 会把非空参数附加在模板之后的空行上：

.opencode/commands/explain.mdMarkdown
Explain this code clearly.

运行 /explain src/cache.ts 时，prompt 变成：

text展开结果
Explain this code clearly.

src/cache.ts

内嵌 Shell

用 ! 加反引号包裹一条 shell 命令，它的输出会在 prompt 提交前被插入：

.opencode/commands/review-diff.mdMarkdown
Review this diff:

!`git diff --stat && git diff`

OpenCode 在当前项目位置用配置好的 shell 逐个运行这些代码块，并把合并后的输出插进去。参数占位符会先被展开：

.opencode/commands/history.mdMarkdown
Summarize these commits:

!`git log --oneline -$1`

运行 /history 5 时，shell 收到的是 git log --oneline -5。不要把不可信的参数放进 shell 代码块。

⚠️ 注意

Shell 代码块在 OpenCode 展开命令时就会运行，不经过智能体的工具权限流程。只使用来自可信来源的命令。

附件（Attachments）

存储的模板不会展开 @path，它保持为普通 prompt 文本：

.opencode/commands/readme.mdMarkdown
Review @README.md.

想附加文件，请在调用命令时通过输入框（composer）添加。OpenCode 提交展开后的 prompt 时会保留这些输入框附件。

执行（Execution）

命令在提交一条持久的用户 prompt 之前，会先展开参数和 shell 代码块。默认在当前会话中运行：

.opencode/commands/plan.mdMarkdown
---
agent: plan
---

Plan $ARGUMENTS.

运行 /plan migration 会先把当前会话切换到 plan 智能体，再提交 prompt。

模型选择遵循以下规则：

  1. 命令的 model 覆盖所有其它模型设置。
  2. 否则，所选命令智能体配置的模型覆盖调用时激活的模型。
  3. 否则，保持当前会话的模型。

例如，这个命令同时指定了智能体和显式模型：

.opencode/commands/design.mdMarkdown
---
agent: plan
model: openai/gpt-6.1-sol#high
---

Design $ARGUMENTS.

后台运行（Background）

设置 subagent: true 可以让命令在后台子会话中运行：

.opencode/commands/audit.mdMarkdown
---
description: Audit changes
agent: general
subagent: true
---

Audit $ARGUMENTS for bugs and missing tests.

父会话保持可用，并保留自己的智能体和模型。子会话结束时，OpenCode 会把子会话的结果或失败信息发回给父会话。

取值行为
true总是用子会话，即使所选智能体是 mode: primary。
false总是用当前会话，即使所选智能体是 mode: subagent。
省略只有所选智能体是 mode: subagent 时才用子会话。

子会话的模型依次取：命令的模型 → 所选智能体的模型 → 父会话的模型。旧的 subtask 仍被接受；两个字段同时存在时 subagent 优先：

yaml
subagent: false
subtask: true

因为 subagent 优先，这个例子会在当前会话中运行。

加载与覆盖（Loading）

Markdown 和 JSON 命令共用一个注册表。靠后的来源会替换同名的更早命令：

text优先级示例
~/.config/opencode/commands/review.md   # Lower priority
.opencode/commands/review.md           # Replaces the global command

项目来源优先于全局来源，离当前目录更近的项目来源优先于祖先目录来源。自定义定义还可以替换先前的内置命令。OpenCode 会自动重新加载命令文件和配置的变更：

.opencode/commands/review.mdMarkdown
Review only the staged changes: !`git diff --cached`

💡 扩展

保存这个文件后，/review 立刻更新，无需重启 OpenCode。配合 shell 内嵌块，你可以把「只审查暂存区改动」这类日常流程固化成一键命令，团队还可以把 .opencode/commands/ 提交进仓库，让所有成员共享同一套命令。
