Console 概览

OpenCode Console 是一个可选的在线服务，无论你是独自使用还是团队协作，它都能给 OpenCode 带来一堆额外能力。这一页先给你一张全景图。

🧠 通俗理解

把 OpenCode 本体想象成一台功能完整的「终端电脑」，Console 就是它的「云控制台」：模型额度、团队成员、用量预算、统一策略这些需要跨设备、跨人协作的东西，都集中放在云端管理。CLI 在你电脑上干活，Console 在云端管账、管人、管规矩——两者通过登录打通，缺了谁都不影响另一边单独工作。

Console 能做什么

Console 提供的能力包括：

  • 工作区（Workspaces）——与你的团队共享访问权限
  • 推理（Inference）——同时覆盖专有模型和开源模型
  • 提供商（Providers）——通过 Console 网关接入你自己的提供商账号
  • 用量追踪与预算（Budget）管控
  • 向全团队下发策略（Policies），统一控制 OpenCode 的行为
  • 网页搜索
  • Harnesses——让 Claude Code、Codex 等其他智能体也能用上 Console 的模型
  • OpenCode Go、Go Plus、Go Teams——每月 10 美元、40 美元、20 美元/成员的订阅方案，获得开源模型的使用权

💡 扩展

「Harness」在官方语境里指承载 OpenCode 模型的其他智能体外壳——比如 Claude Code、Codex、Raycast 等。你在 Claude Code 里填上 Console 的接入信息，就能让 Claude Code 背后跑的是 Console 提供的模型。细节见 Harnesses 一章。

快速上手

用 Console 不需要先组建团队。每个账号注册后自带一个 Personal（个人） 工作区，里面只有你一个成员。

  1. 登录 Console。
  2. 订阅 Go，或充值额度，或连接一个提供商——三选一即可。
  3. 在 OpenCode 里运行 /connect 并选择工作区。
  4. （可选）邀请你的团队加入。
OpenCode 命令在 TUI 中执行
/connect

⚠️ 注意

/connect 是在 OpenCode 终端界面里输入的斜杠命令，不是在浏览器地址栏或系统终端里执行。连上之后，OpenCode 的请求会走 Console 的网关并按你选择的方案计费；如果只想用自己的 API key，走 提供商 页面的自助接入方式即可。

策略（Policies）

在 Console 的 Policies 页面里配置的「提供商（Providers）规则」和「工具（Tools）规则」，会应用到每一个连接到该工作区的 OpenCode 客户端上。这些规则以策略语句（policy statements）的形式下发，优先级高于成员自己的用户级和项目级配置，并在约一分钟内生效。托管偏好设置（managed preferences）和系统配置文件仍然高于工作区策略；优先级排序详见 precedence 一节。

🧠 通俗理解

策略就像公司的「行政命令」：你在自己电脑上的配置文件是个人决定，但只要连上了团队工作区，云端下发的规则就压在你的个人配置之上。对管理员来说，这意味着改一处（Console 页面）就能约束全团队的 OpenCode 行为——比如禁止某类工具、限定可用提供商——而不用挨个去改每个人的配置文件。
