TUI 插件

TUI 插件为终端界面扩展命令、路由、插槽（slot）、Markdown 渲染器、通知和本地状态。TUI 插件是插件包的 ./tui 部分，通常与服务器部分并列。

src/tui.tsxTypeScript · TSX
import { Plugin } from "@opencode/plugin/tui"

export default Plugin.define({
  id: "acme.cli",
  setup(context) {
    context.ui.toast.show({ message: "TUI plugin loaded", variant: "success" })
  },
})

直接导入 @opencode/plugin/tui 即可。OpenCode 在运行时解析这个导入，所以本地 TUI 插件不需要指向 OpenCode 源码目录的绝对路径。

上下文（Context）

setup 会收到配置、应用元数据、当前位置、OpenCode 客户端、缓存数据、主题 token、OpenTUI 渲染器，以及下面介绍的 UI API：

TypeScript
setup(context) {
  const compact = context.options.compact === true
  const location = context.location ?? context.data.location.default()
  const version = context.app.version
  const channel = context.app.channel
  const client = context.client
  const renderer = context.renderer
  const theme = context.theme
}

返回一个清理函数，用于释放插件拥有的资源：

TypeScript
setup(context) {
  const stop = context.data.on("session.execution.succeeded", () => {})
  return () => stop()
}

客户端（Client）

context.client 是生成的 OpenCode 客户端，可以调用所连的服务器——包括远程服务器：

TypeScript
const response = await context.client.plugin.list({
  location: context.location ?? context.data.location.default(),
})
const plugins = response.data

事件（Events）

用 data.on 监听单个类型化事件，用 data.listen 监听所有服务器事件；两者都返回取消订阅函数：

TypeScript
const stopPermission = context.data.on("permission.asked", (event) => {
  context.ui.toast.show({ message: `Permission ${event.data.id}` })
})
const stopAll = context.data.listen(({ details }) => console.log(details.type))

return () => {
  stopPermission()
  stopAll()
}

主题与渲染器

在 OpenTUI 元素里使用语义化主题 token；把 context.renderer 传给依赖渲染器的辅助函数：

TSX
const Status = () => <text fg={context.theme.text.base}>Ready</text>
const renderer = context.renderer

渲染器绘制的 OpenTUI 资源需要 context.renderer.nativeScene 作为属主（owner）。例如 <markdown> 和 <code> 需要一个 SyntaxStyle。要在渲染器空闲时、即绘制该资源的最后一帧之后销毁资源：

TSX
import { SyntaxStyle } from "@opentui/core"

const style = SyntaxStyle.fromStyles({ default: { fg: context.theme.text.base } }, context.renderer.nativeScene)
context.ui.slot({ append: "home.footer", render: () => <markdown content="Ready" syntaxStyle={style} /> })
return () => context.renderer.idle().then(() => style.destroy())

要读取可渲染对象的布局样式，用 Yoga Node getter 同名的方法调用，例如 box.getPadding(Yoga.Edge.Bottom) 或 box.getMaxWidth()。宿主（host）可渲染对象不属于插件 API，其结构和样式在任意版本都可能变化。

为 OpenTUI 0.5 编写的插件

OpenCode 用它自带的 OpenTUI 运行插件。自 OpenTUI 0.6 起：

  • SyntaxStyle.create()、SyntaxStyle.fromStyles()、SyntaxStyle.fromTheme()、TextBuffer.create()、EditBuffer.create() 的最后一个参数是属主；OptimizedBuffer.create() 则放在 owner 选项里。传 context.renderer.nativeScene。OpenTUI 0.5 会忽略这个多余参数，所以插件仍能在旧版 OpenCode 上运行。
  • 来自 @opencode/theme/tui 的 generateSyntax() 把属主作为第二个参数：generateSyntax(context.theme, context.renderer.nativeScene)。旧版 @opencode/theme 构建样式时不带属主，所以也要更新这个包。
  • getLayoutNode() 已被移除。在 OpenTUI 0.6.5 及以上，把 getLayoutNode().getMaxWidth() 等样式 getter 替换为可渲染对象上的同名方法。把 getComputedLayout() 等计算位置/尺寸的 getter 替换为 getLayout()，把 markDirty() 替换为 invalidateIntrinsicSize()。计算出的 padding、margin、border 没有替代品；getPadding(edge) 只读取为该边设置的 padding。要恢复 getter 报告为未设置（Unit.Undefined）的样式，把该属性赋值为 undefined（OpenTUI 0.6.6 及以上）。

OpenTUI 0.6.0 发布说明列出了所有变化。

⚠️ 注意

如果你的 TUI 插件是在 OpenTUI 0.5 时代写的，升级 OpenCode 后最可能踩的坑就是 getLayoutNode() 被移除和资源缺属主（渲染错乱或崩溃）。官方刻意让带属主参数的新调用在 0.5 上向后兼容（忽略多余参数），所以推荐的写法是「新 API + 属主参数」，一份代码同时兼容新旧两代。

命令与键位映射

在一个响应式键位层（keymap layer）里注册面板（palette）、斜杠（slash）和键盘命令：

TypeScript
context.keymap.layer(() => ({
  mode: "global",
  priority: 10,
  commands: [
    {
      id: "acme.status",
      title: "Show Acme status",
      group: "Acme",
      bind: "ctrl+g",
      palette: true,
      slash: { name: "acme", aliases: ["status"], arguments: true },
      enabled: () => true,
      suggested: true,
      run: async (input) => context.ui.toast.show({ message: input ?? "Ready" }),
    },
  ],
  bindings: ["acme.status"],
}))

在 setup 里调用 layer（包括 await 之后），或在组件里调用。每个层会在以下情形中最早发生的一个时被移除：

  • 插件被禁用、重新加载，或 setup 失败。
  • 创建它的组件或响应式计算（比如插槽、路由或对话框）被销毁。

层工厂必须是纯函数。OpenCode 先不带依赖追踪地求值一次，用于校验初始命令形状，然后再响应式求值。初始命令形状错误（例如面板命令没有 ID）会从 layer() 抛出。绑定解析错误由 OpenTUI 处理；后续响应式更新的错误走 Solid 的错误处理：

TypeScript
async setup(context) {
  const settings = await loadSettings()
  context.keymap.layer(() => ({
    mode: "global",
    commands: [{ id: "acme.sync", title: "Sync Acme", palette: true, run: () => sync(settings) }],
  }))
}

一个层可以指向一个 OpenTUI 可渲染对象，并且命令里返回 false 可以继续键盘派发：

TypeScript
context.keymap.layer(() => ({
  target: () => panel,
  commands: [{ bind: "escape", run: (_input, event) => (event ? false : undefined) }],
}))

还可以派发命令、检查快捷键与命令状态、或推入一个临时输入模式：

TypeScript
context.keymap.dispatch("acme.status", "verbose")
const shortcuts = context.keymap.shortcuts("acme.status")
const commands = context.keymap.commands()
const pending = context.keymap.pending()
const active = context.keymap.active()
const currentMode = context.keymap.mode.current()
const popMode = context.keymap.mode.push("acme-search")
popMode()

存储（Storage）

持久化存储在重启后保留 JSON，并在多个 TUI 实例间同步：

TypeScript
const [settings, updateSettings] = context.storage.store("settings", {
  initial: { compact: false },
})
await updateSettings((draft) => {
  draft.compact = true
})

内存存储在插件重新加载后仍存活，但 TUI 退出时会被丢弃：

TypeScript
const [state, updateState] = context.storage.memory("state", {
  initial: { count: 0 },
})
updateState((draft) => {
  draft.count++
})

🧠 通俗理解

TUI 插件有两块存储，区别一句话就能记住：storage.store 写的是硬盘（重启还在、跨窗口同步），storage.memory 写的是内存（重载插件还在，关掉终端就没）。用户偏好放前者，临时 UI 状态（比如「面板展开了几次」）放后者。

选择器搜索（Select search）

传 search 可以接管匹配和结果排序。它对每个查询都会执行——包括空查询，且只收到启用的选项。结果按返回顺序列出，每个分类内联显示：

TypeScript
const project = await context.ui.dialog.select({
  title: "Projects",
  options: [
    { title: "Alpha", value: "alpha", category: "Recent" },
    { title: "Beta", value: "beta", category: "Pinned" },
  ],
  search: (query, options) =>
    options
      .filter((option) => option.title.toLowerCase().includes(query.toLowerCase()))
      .toSorted((left, right) => right.title.localeCompare(left.title)),
})

选择器动作（Select actions）

动作（action）出现在页脚，可通过键盘绑定、点击、或 Tab 聚焦后按 Enter 触发。默认会收到当前选中值，并且没有选中时不可用。不需要选中的动作用 selection: "none"：

TypeScript
await context.ui.dialog.select({
  title: "Projects",
  options: [{ title: "Alpha", value: "alpha" }],
  actions: [
    { bind: "ctrl+o", title: "Inspect", onTrigger: (value) => context.ui.toast.show({ message: value }) },
    { bind: "ctrl+a", title: "Close", side: "right", selection: "none", onTrigger: () => context.ui.dialog.clear() },
  ],
})
  • 动作不会关闭对话框，也不会结算（settle）这个 Promise。
  • 按 Enter 或点击选项会以选中值 resolve。
  • 按 Escape、调用 clear() 或展示另一个对话框会以 undefined resolve。
  • 不要绑定 ctrl+n 或 ctrl+p。对话框保留它们用于导航，且自身的绑定优先。

自定义 JSX 对话框可以设置尺寸并自行关闭：

TSX
context.ui.dialog.set({ size: "large", centered: true })
context.ui.dialog.show(
  () => (
    <box>
      <text>Acme</text>
    </box>
  ),
  () => console.log("closed"),
)
context.ui.dialog.clear()

Toast 支持 title、message、variant 和 duration：

TypeScript
context.ui.toast.show({
  title: "Acme",
  message: "Saved",
  variant: "success",
  duration: 3000,
})

模型（Model）

读取提示词当前选中的模型并改变其变体（variant）。在 Solid 计算里读取时，current() 和 variant.list() 是响应式的。variant 为 undefined 表示模型默认：

TypeScript
const selected = context.ui.model.current()
const variants = context.ui.model.variant.list()
context.ui.model.variant.set("high")
context.ui.model.variant.set(undefined)

未选中模型或模型没有该变体时，variant.set 返回 false。可以把它绑到命令上来替换内置的变体轮换（variant cycle），例如跳过模型默认：

TypeScript
context.keymap.layer(() => ({
  commands: [
    {
      id: "acme.variant.cycle",
      title: "Cycle variants",
      bind: "tab",
      run() {
        const variants = context.ui.model.variant.list()
        if (variants.length === 0) return
        const index = variants.indexOf(context.ui.model.current()?.variant ?? "")
        context.ui.model.variant.set(variants[(index + 1) % variants.length])
      },
    },
  ],
}))

插槽（Slots）

插槽可以在 app、home.footer、home.footer.status、prompt.footer、prompt.footer.status、prompt.footer.file、session.composer.top、sidebar.content 或 sidebar.footer 处插入或替换 JSX：

TSX
return context.ui.slot({
  append: "sidebar.content",
  render: ({ sessionID }) => <text>{context.data.session.get(sessionID)?.title}</text>,
})

用 prepend、append、before、after 或 replace 指定位置：

TSX
context.ui.slot({ prepend: "home.footer", render: () => <text>Before footer content</text> })
context.ui.slot({ append: "home.footer", render: () => <text>After footer content</text> })
context.ui.slot({ before: "home.footer", render: () => <text>Before footer slot</text> })
context.ui.slot({ after: "home.footer", render: () => <text>After footer slot</text> })
context.ui.slot({ replace: "home.footer", render: () => <text>New footer</text> })

用 home.footer.status 可以往内置页脚行添加内容而不替换它。状态贡献出现在 OpenCode 健康指示器之后、版本号之前：

TSX
context.ui.slot({ append: "home.footer.status", render: () => <text>SYNCED</text> })

会话面板（Session panels）

向 session.panel 注册一个贡献（contribution），然后用命令打开面板。宿主负责尺寸、焦点和全屏呈现；插件只负责面板内容。选中的面板名会作为 panel.name 传给每个贡献，由各贡献自行决定是否渲染：

TSX
import { Show } from "solid-js"

context.ui.slot({
  append: "session.panel",
  render: (panel) => (
    <Show when={panel.name === "acme.review"}>
      <ReviewPanel panel={panel} />
    </Show>
  ),
})

context.ui.slot({
  append: "app",
  render: () => {
    context.keymap.layer(() => ({
      mode: "global",
      commands: [
        {
          id: "acme.review",
          title: "Open review",
          slash: { name: "review" },
          run: () => {
            context.ui.panel.open("acme.review")
          },
        },
      ],
    }))
    return null
  },
})
  • 在会话之外打开会返回 false。
  • 这是一个普通插槽：五种放置方式和既有的替换顺序规则都适用。
  • 想让多个贡献可独立选中并存，用 append；replace 仍然会整体接管插槽。
  • 名字是共享的选中值，不是注册声明。用带插件前缀的名字（如 acme.review）避免撞名。打开一个没有匹配渲染器的名字会让插槽留空。
  • 切换呈现方式会保留已挂载的贡献；关闭面板会销毁它们；禁用插件会通过正常的插槽清理移除其贡献。
  • 面板的键盘层和输入模式只在面板持有输入时生效。

插槽会收到响应式的 name、sessionID、width、presentation、focused 属性，外加 focus、close、toggleFullscreen 动作。宿主会让窄终端始终全屏；空间不足以放侧面板时 toggleFullscreen 无效：

TSX
import type { PanelInput } from "@opencode/plugin/tui/context"
import { usePlugin } from "@opencode/plugin/tui"

function ReviewPanel(props: { panel: PanelInput }) {
  const context = usePlugin()
  context.keymap.layer(() => ({
    commands: [
      {
        id: "acme.review.fullscreen",
        bind: "f",
        run: props.panel.toggleFullscreen,
      },
    ],
  }))
  return <text>Reviewing {props.panel.sessionID}</text>
}

你可以初始就请求全屏呈现、检查自己的活动面板、或在不影响其它插件面板的情况下关闭它：

TypeScript
context.ui.panel.open("acme.review", { presentation: "fullscreen" })
const current = context.ui.panel.current()
context.ui.panel.close()

  id: "acme.server",

纯 TUI 的包配置在 cli.json 里，这样它在连接远程服务器时也能保持激活：

💡 扩展

TUI 插件运行在你的终端进程里，用的是 OpenTUI + Solid 这套「终端里的 React」技术栈——所以 JSX、响应式信号、组件生命周期这些心智模型可以直接搬过来。唯一要记住的差异：渲染目标是字符网格而不是 DOM，样式是语义 token（context.theme.text.base）而不是 CSS。想给团队做状态面板、自定义 slash 命令或审查界面，这层 API 已经足够。
