账单

Console 对任何规模的团队都免费，没有按座位收费。你只为用量付费，费用从覆盖整个工作区的预付额度（credits）中扣除。所有者（Owner）和管理员（Admin）在 Settings › Billing 管理账单。

🧠 通俗理解

Console 的收费模型是「先充值、后消费」的电话卡模式：整个工作区共用一个额度池，谁用谁扣。没有月费、没有人头费，团队再大也是免费用控制台，只付模型消耗的钱。通过自有提供商产生的用量则由该提供商直接向你收费，与 Console 无关。

添加支付方式

  1. 打开 Settings › Billing。
  2. 在 Payment methods 下点击 Add。
  3. 选择一种方式，完成 Stripe 的设置流程。

支持的支付方式：

  • Card（银行卡）
  • Link
  • Alipay（支付宝）
  • UPI
  • WeChat Pay（微信支付）

用 ⋯ › Make default 选择自动扣款时使用的默认支付方式。移除某个支付方式，可能会让依赖它的自动充值和 Go 续费停摆。

充值额度

  1. 在 Credits 下点击 Add credits。
  2. 选择 $10、$50 或 $100，或选 Other 自行输入金额。
  3. 选择支付方式，点击 Confirm and pay。

充值会额外加收 4.6% + $0.31 的手续费：例如买 $50 实际支付 $52.61，但入账的是完整的 $50。

自动充值（Auto-recharge）

自动充值会在余额不足时自动购买额度。

  1. 在 Auto-recharge 下点击 Add rule。
  2. 设置触发扣款的余额阈值和每次充入的金额。
  3. 点击 Save。

自动充值使用默认支付方式扣款，手续费包含在内。如果扣款失败，自动充值会关闭，直到你重新设置。

⚠️ 注意

自动充值是一次性开关，不是「失败了自动重试」：一次扣款失败它就直接停用，需要你手动重新配置。跑自动化任务的工作区尤其要留意——半夜余额见底又恰逢银行卡过期，任务就会断在 402 错误上。建议把触发阈值设得高一些，并保持默认支付方式有效。

查看余额

Activity 页的 Billing 卡片会为所有者和管理员显示余额，并可以打开 Settings › Billing。

工作区页头上的 Billing 按钮（或按 B 键）会打开一个抽屉，实时显示 Go 上限、额度和用量。所有者和管理员可以看到工作区的余额、用量和自动充值情况；成员只能看到自己的用量和上限。

额度用尽时

余额一旦归零，付费请求会以 HTTP 402 失败。余额永远不会变成负数。

text错误信息
Upstream request failed: Insufficient account funds

发票

每笔支付都会出现在 Invoices 下，带有状态，以及 Download invoice（下载发票）或 View receipt（查看收据）链接。

条目产生原因
Balance top-up（余额充值）手动充值额度
Automatic top-up（自动充值）自动充值触发
Go subscription（Go 订阅）订阅 Go、Go Plus 或 Go Teams
Go renewal（Go 续费）Go 的月度续费
Go Plus upgrade（升级 Go Plus）从 Go 升级到 Go Plus
Go Teams upgrade（升级 Go Teams）从 Go 或 Go Plus 升级到 Go Teams
Go Teams member（Go Teams 成员）成员加入 Go Teams 工作区
Monthly Usage（月度用量）发票账单（invoiced billing）

发票账单

签有额度协议（credit agreement）的工作区可以改为按月开票，而不必预购额度。请联系支持团队设置。

  • 用量消耗的是信用额度（credit limit），而不是预付余额。
  • 每月的发票在每月 1 日（UTC）开出，14 天后到期。
  • 未支付的发票上有 Pay now 按钮。
  • 触达信用额度上限或发票逾期时，请求会以 HTTP 402 失败。

💡 扩展

发票账单和预充值额度还有一个隐性差异：用额度支付 Go 订阅这条路对发票账单的工作区是关闭的（Go 页面有说明）。企业谈下来的月结模式主要覆盖模型用量，订阅类产品仍走信用卡自动扣款，签约前要和财务确认清楚。

Go

OpenCode Go 订阅使用同样的支付方式，并出现在同一份发票列表中。你也可以用额度支付 Go。在 Go 页面打开 Extra Usage，即可在触达 Go 上限后改用额度支付继续使用。
