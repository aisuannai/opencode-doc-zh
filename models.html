模型

会话里用 /models 选模型；配置文件里设默认模型；变体（variant）用来指定推理强度；本地 Ollama、LM Studio、vLLM 模型自动发现。这一页把模型相关的所有配置讲清楚。

在会话中用 /models 为当前会话选一个模型：

TUI 命令
/models

OpenCode 会列出来自 models.dev、提供商集成和你自己配置的模型。选择器只显示已启用、且其提供商在当前项目中可用的模型。提供商的连接见 Providers 一章。

选择模型

直接从 /models 里挑一个条目，不用去猜它的提供商或模型 ID。选择只作用于当前会话，不会改动你的配置文件：

text选择器中的条目
anthropic/claude-sonnet-5-5

模型的可用性是按项目区分的：

  • 模型必须是启用状态。
  • 它的提供商必须在当前项目中可用。
  • 另一个项目的凭据和配置不会自动带过来。

单次运行

用 --model 给一次命令行运行临时指定模型，而不改变配置的默认值：

bash
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"

智能体和自定义命令也可以各自指定模型。见 Agents 和 自定义命令。

默认模型

在 opencode.json 或 opencode.jsonc 里设置 model，作为新工作的默认模型：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}

当配置的模型已启用且其提供商可用时，它会成为模型目录里的默认项。否则 OpenCode 回退到最新的可用受支持模型。

  • 会话里已经选定的模型优先于配置的默认值。
  • 切换会话的模型不会改写配置文件。
  • 根级 model 目前只保留默认的提供商和模型，不保留变体。

配置文件的位置和优先级见 配置一章。

免费模型

在服务器进程上设置 OPENCODE_DISABLE_FREE_MODELS=1（或 true）可以隐藏 OpenCode 的免费模型：

bash
OPENCODE_DISABLE_FREE_MODELS=1 opencode serve

对于共享的后台服务器：

bash
opencode service set env OPENCODE_DISABLE_FREE_MODELS 1

「免费」指没有输入价格的 opencode 或 opencode-go 模型。隐藏后这些模型会从目录和默认值中消失；显式选择会报 Model unavailable 错误。未登录时，在你连接 OpenCode Console 账号或设置 OPENCODE_API_KEY 之前，opencode 提供商本身不存在；登录或设置密钥后会恢复它的付费模型。

变体（Variants）

变体是同一个模型的具名选项，通常用来表示推理力度（reasoning effort）或 token 预算。选择时在模型后面加 #variant，可用于单次运行、会话、智能体或命令：

bash
opencode run --model openai/gpt-6.1-sol#high "Review this migration plan"

变体名称来自所选模型当前的目录元数据。low、high、max 这类名字不是每个模型都有，写了一个不存在的变体会导致模型解析错误。

在模型的 variants 数组里可以定义新变体，或者用相同 ID 替换目录里的变体：

opencode.jsonc定义变体
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}

每个变体可以包含 settings、headers 和 body，其值在提供商和模型值之后应用。

想替换一个模型的推理变体，可以在 capabilities.reasoning 中按 models.dev v2 的格式描述它的推理控制项，OpenCode 会据此为该模型生成变体：

opencode.jsonc声明推理能力
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "capabilities": {
            "reasoning": {
              "supported": true,
              "effort": ["low", "medium", "high"],
            },
          },
        },
      },
    },
  },
}
字段用途
supported模型是否支持推理。设 false，或 true 但不带任何控制项，都不会生成变体。
toggle添加一个 none 变体，用于关闭推理。
effort提供哪些推理力度档位。default 表示保持提供商默认且不生成变体。
budget可选的思考 token min 和 max。设置了 effort 时被忽略。

variants 里列出的变体会叠加在由 capabilities.reasoning 生成的变体之上。

🧠 通俗理解

变体就像汽车的不同驾驶模式：同一台车（模型），「经济」（low）省 token 但想得浅，「运动」（high）想得深但更贵更慢。你在选择器里看到的 claude-sonnet-5-5#high 里的 #high，就是告诉这台车用运动模式跑这一趟。

选项（settings / headers / body）

提供商和模型条目可以用 settings、headers 和 body 定制请求：

opencode.jsoncJSONC
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
字段用途
settings提供商包的选项，如 baseURL 或 reasoningEffort。
headers附加的 HTTP 请求头。
body提供商专属的请求体字段。

OpenCode 先应用提供商的值，再应用模型的值，最后应用所选变体的值。

  • 嵌套的 settings 和 body 对象按键合并。
  • 靠后的数组和标量值替换靠前的值。
  • 请求头名称大小写不敏感地匹配。
  • 这些选项是提供商专属的，换一个提供商包可能会忽略或拒绝它们。

别名（Aliases）

用 modelID 可以给一个 API 模型起一个更友好的目录 ID：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-6.1-sol",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "freeform": ["text", "lark"],
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}

这里 openai/coding-default 是你选择时用的引用名，实际发送给提供商的是 gpt-6.1-sol。对于一个目录里原本不存在的模型，OpenCode 做如下假设：

  • 支持 JSON 工具调用；输入支持文本和图片；输出只有文本。除非 capabilities.freeform 列出了格式，否则不支持自由格式（freeform）的工具输入。
  • 上下文上限 200,000 token，输出上限 32,000 token。
  • 输入上限未指定。

OpenCode 认识 text、regex 和 lark 三种格式名。models.dev 上其它格式名会被忽略，但不会因此丢弃模型或其工具。如果目录模型前面架了一个拒绝 freeform 工具的代理，就把该模型的 capabilities.freeform 设为 []。

⚠️ 注意

上面这些是回退假设，不是探测到的真实能力。知道准确值时请显式设置 capabilities 和 limit——显式值会覆盖回退假设。给不存在的模型 ID 加 disabled: true 还能把它从可用目录中隐藏：

jsonc
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}

推理字段（Reasoning）

对于一个用自定义的 assistant 消息字段流式输出推理内容的 OpenAI 兼容模型，设置 compatibility.reasoningField：

opencode.jsoncJSONC
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}

OpenCode 认识 reasoning、reasoning_content 和 reasoning_text，也接受其它提供商专属的字符串。它会从这个字段读取流式推理内容，并在把历史 assistant 消息发回模型时还原该字段。相关的 requireReasoning 字段见下方「兼容性（Compatibility）」。

提示词缓存（Prompt caching）

OpenCode 会在已知需要的位置自动放置提示词缓存断点（breakpoint），比如 Anthropic。但当 Claude 模型通过 OpenAI 兼容代理（如 LiteLLM）提供服务时，OpenCode 无法察觉它们需要 Anthropic 风格的 cache_control 断点。给这些 Claude 模型设置 compatibility.cacheFormat：

opencode.jsoncLiteLLM 代理示例
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // 同一代理上的其它模型自动缓存，无需设置。
        "gpt-6.1-sol": {},
      },
    },
  },
}

设置后，OpenCode 会在最后一个工具定义、系统提示词和最新一条消息上标记 cache_control: { "type": "ephemeral" }，使用端点默认的五分钟缓存时长。阿里云 Model Studio 的模型用 "alibaba"——它们接受同样的标记，但会忽略工具定义上的标记。如果提供商下所有模型都接受同一种格式，可以直接在提供商上设 compatibility.cacheFormat。其它字段见下方「兼容性（Compatibility）」。

缓存时长

OpenCode 默认不发送缓存时长，各提供商用自己的默认值（如 Anthropic 是五分钟）。在提供商或模型上设置 settings.cache.ttl 可以指定不同的时长；模型设置优先于提供商设置。

opencode.jsoncJSONC
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "1h" } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "ttl": "5m" } } },
      },
    },
  },
}

ttl 的值是「数字 + 单位」，单位可以是 ms、s、m、h 或 d，如 "5m"、"1h" 或 "24h"。OpenCode 会原样发送，所以要用提供商接受的值：

API时长放在哪里
Anthropic Messages每个缓存标记上的 cache_control.ttl。Anthropic 接受 "5m" 和 "1h"。
Bedrock Converse每个 cachePoint 上的 ttl。只支持五分钟缓存的老 Claude 模型会忽略 "1h"。
OpenAI Chat 和 Responses"24h" 发送到 prompt_cache_retention；其它值发送到 prompt_cache_options.ttl。

不用标记就自动缓存的提供商（如 Gemini）会忽略它。更长的缓存时长写入成本通常更高：Anthropic 的一小时缓存写入按输入价格的 2 倍计费，五分钟则是 1.25 倍。

💡 扩展

会话预热（Warming）可以利用这个缓存时长，在 interval: "auto" 模式下掐着缓存过期前的时间点发请求，把缓存命中率拉满——这是长会话省钱的关键技巧。

兼容性（Compatibility）

compatibility 描述模型所经 API 的请求/响应怪癖，比如推理内容放在哪个字段、端点是否接受 prompt_cache_key。每个模型只通过一个 API 服务，某个字段只有当那个 API 会读取它时才生效，其余字段被忽略。

opencode.jsoncJSONC
{
  "providers": {
    "local": {
      "compatibility": { "streamUsage": false },
      "models": {
        "reasoner": {
          "compatibility": { "reasoningField": "reasoning_content", "maxTokensField": "max_tokens" },
        },
      },
    },
  },
}

提供商级 compatibility 作用于该提供商的所有模型；模型自己的 compatibility 逐字段覆盖它。OpenCode 先取 models.dev 为该模型 API 发布的值（reasoningField、maxTokensField、mediaInput），再叠加模型配置。未设置的字段保持提供商包的内置默认或自动检测。supportsThinkingBlockBinding 和 supportsEffortUpdates 只能设在模型上。

字段作用哪些 API 读取取值与默认
reasoningField承载推理内容的 assistant 消息字段。读取流式推理时最先检查它，回发历史推理时也用它。OpenAI Chat任意字段名，但不能是 role、content、refusal 或 tool_calls。未设置时用流里看到的字段，否则用 reasoning_content。
requireReasoning在每条历史 assistant 消息上都发送推理字段；没有推理内容时发送空字符串。OpenAI Chattrue 或 false。设置过 reasoningField 或模型是 DeepSeek 时默认 true，否则 false。
maxTokensField承载输出 token 上限的请求体字段。OpenAI Chatmax_completion_tokens 或 max_tokens。未设置时，对需要它的提供商（如 DeepSeek、Moonshot、Together AI、Z.AI、Cerebras）自动检测出 max_tokens，否则用 max_completion_tokens。
requireFinishReason把缺少 finish_reason 就结束的流视为「响应不完整」错误；false 则接受它为已完成。OpenAI Chattrue 或 false。默认 true。
requireAssistantAfterTool在工具结果和下一条用户消息之间插入一条 assistant 消息，用于拒绝该顺序的端点。OpenAI Chattrue 或 false。Mistral 系模型 ID 默认 true，否则 false。
supportsPromptCacheKey端点是否接受 prompt_cache_key 请求体字段。OpenAI Chat、OpenAI Responses、Mistraltrue 或 false。OpenAI Chat 只在 true 时发送该键（部分提供商包默认设为 true）。其它 API 默认发送，除非设为 false。
streamUsage通过 stream_options.include_usage 在流中请求 token 用量。OpenAI Chattrue 或 false。默认 true。
cacheFormat端点接受的提示词缓存标记语法。覆盖提供商的自动断点放置。alibaba 会跳过工具定义。所有带提示词缓存标记的 API，包括 OpenAI Chat、Anthropic Messages、Bedrock Converseanthropic 或 alibaba。未设置用提供商默认。见「提示词缓存」一节。
supportsThinkingBlockBinding让 API 对「先前上下文已变化」的思考块予以丢弃，而不是拒绝整个请求。Anthropic Messages、Bedrock Conversetrue 或 false。未设置时自动检测 Claude 5.1 及更高版本。
supportsEffortUpdates把推理力度的变更作为逐消息更新发送，从而保住提示词缓存；否则力度变更作用于整个请求。Anthropic Messages、OpenAI Responsestrue 或 false。未设置时自动检测 Claude Opus 5、Claude 5.1 及更高版本、GPT-6 及更高版本。
mediaInput决策请求中图片等媒体的位置。System Oneassets（图片从 state 引用）、state（内联在 state 里）或 root（顶层的 images、audio、videos 列表）。未设置用提供商默认。

本地模型

OpenCode 会自动在默认本地地址上发现 Ollama、LM Studio 和 vLLM 的模型。也可以手动配置任意 OpenAI 兼容服务器。

text自动发现的引用格式
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct

Ollama

Ollama 监听在 http://127.0.0.1:11434 时，用 ollama 提供商 ID 选择一个被发现的模型：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}

OpenCode 在后台刷新模型清单，并从 Ollama 读取上下文、视觉和工具调用能力。纯嵌入（embedding）模型会被排除。

主机或端口不同时，设置 Ollama 的 OpenAI 兼容 URL。发现机制仍走同一前缀下的原生 Ollama API：

opencode.jsonc自定义地址
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
  • 端点不需要 bearer 认证时省略 apiKey。
  • 用 "plugins": ["-opencode.provider.ollama"] 关闭自动发现。

LM Studio

LM Studio 服务器（无认证）运行在 http://127.0.0.1:1234 时，用 lmstudio 提供商 ID 选择被发现的模型：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}

OpenCode 在后台刷新清单，并从 LM Studio 读取上下文、视觉和工具调用能力。嵌入模型会被排除。

主机或端口不同时，设置 OpenAI 兼容 URL，模型仍然自动发现：

opencode.jsonc自定义地址
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
  • LM Studio 关闭了认证时省略 apiKey。
  • 用 "plugins": ["-opencode.provider.lmstudio"] 关闭自动发现。

vLLM

vLLM 监听在 http://127.0.0.1:8000 时，用 vllm 提供商 ID 选择被发现的模型：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}

OpenCode 会检查 /health，在后台刷新 /v1/models，把报告的 max_model_len 用作上下文上限，并且只纳入属于 vllm 的模型卡。

被发现的模型只声明文本输入输出，不声明视觉和工具能力。vLLM 需要用 --enable-auto-tool-choice、--tool-call-parser 等服务器参数开启工具调用，而发现机制不会报告这些。

端点不同或服务器带认证时，设置它的 OpenAI 兼容 URL：

opencode.jsonc自定义地址
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
  • 关闭认证时省略 apiKey。
  • 用 "plugins": ["-opencode.provider.vllm"] 关闭自动发现。
  • 支持带路径前缀的代理。例如 https://example.com/vllm/v1 会检查 /vllm/health 并发现 /vllm/v1/models。

其它兼容服务器

对于其它 OpenAI 兼容服务器，需要定义它的提供商包、端点和至少一个模型：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}

请如实填写服务器的真实模型名、上下文上限、输入输出类型和工具支持情况——OpenCode 无法检测自定义模型的回退假设是否准确。端点需要密钥时，在 settings 里加 apiKey，并用环境变量替换如 "apiKey": "{env:LOCAL_API_KEY}"；不要把密钥提交进仓库。

⚠️ 注意

密钥安全：{env:VAR} 语法让配置引用环境变量而不把真实密钥写进文件。但配置文件本身仍会被 git 跟踪——把 .env 加入 .gitignore，密钥只放环境里，这是最常见的泄漏源头。

引用格式（References）

模型选择器使用 provider/model 格式，可选加 #variant：

text合法示例
openai/gpt-6.1-sol
openai/gpt-6.1-sol#high
openrouter/anthropic/claude-sonnet-5.5#high
部分规则
提供商在第一个 / 处结束；不能包含 / 或 #。
模型可以包含更多 / 字符；不能包含 #。
变体如有，跟在 # 之后。
大小写提供商和模型 ID 区分大小写。

请用目录 ID，而不是提供商的显示名称。根级、智能体和命令的 model 字段都接受上面的字符串形式，或展开的对象形式：

jsonc展开形式
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-5.5",
  },
}

展开形式适合生成式或程序化配置。

注意事项（Caveats）

配置模型时记住这几条规则：

jsonc
{
