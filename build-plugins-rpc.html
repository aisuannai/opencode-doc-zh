RPC

插件可以暴露自定义方法和事件，让它们运行在服务器上，并能被其它插件或客户端调用。

🧠 通俗理解

RPC 是插件的「对外服务窗口」：服务器部分在 src/rpc.ts 里声明契约（有哪些方法、收什么参数、返回什么、可能报什么错、广播哪些事件），再在 setup 里实现它；之后无论是 HTTP 客户端、TUI 插件还是 GUI 插件，都拿着同一份契约来调用——类型检查两边都生效，就像调用本地函数一样。

定义（Define）

用 Rpc.define 列出 RPC 的方法、错误和事件：

src/rpc.tsTypeScript
import { Rpc } from "@opencode/plugin/rpc"

export const Acme = Rpc.define({
  id: "acme",
  methods: {
    search: {
      input: {
        type: "object",
        properties: { query: { type: "string" } },
        required: ["query"],
        additionalProperties: false,
      },
      output: {
        type: "object",
        properties: { text: { type: "string" } },
        required: ["text"],
        additionalProperties: false,
      },
      errors: {
        not_found: {
          type: "object",
          properties: { query: { type: "string" } },
          required: ["query"],
          additionalProperties: false,
        },
      },
    },
  },
  events: {
    updated: {
      schema: {
        type: "object",
        properties: {
          itemID: { type: "string" },
          text: { type: "string" },
        },
        required: ["itemID", "text"],
        additionalProperties: false,
      },
    },
  },
})

校验（Validation）

RPC 定义描述方法、事件和错误的输入输出形状。支持两种 schema 格式：

  • JSON Schema——简单，且无需额外依赖。
  • 任何符合 Standard Schema 的校验器：
    • Zod
    • Valibot
    • ArkType

输入与输出（Input and output）

每个方法可以为参数定义 input schema，为返回值定义 output schema。方法不接收或不返回值时，任一都可以省略：

TypeScript
search: {
  input: {
    type: "object",
    properties: { query: { type: "string" } },
    required: ["query"],
  },
  output: {
    type: "object",
    properties: { text: { type: "string" } },
    required: ["text"],
  },
}

JSON Schema 的值在 TypeScript 里是 unknown，所以使用前要先收窄类型。Standard Schema 则能直接推断输入输出类型。

错误（Errors）

给方法添加 errors 映射来声明预期失败。每个键会成为错误的 type，其 schema 定义错误的 data：

TypeScript
errors: {
  not_found: {
    type: "object",
    properties: { query: { type: "string" } },
    required: ["query"],
    additionalProperties: false,
  },
}

⚠️ 注意

以 rpc. 开头的错误名被 OpenCode 保留，自定义错误别用这个前缀。

事件（Events）

把事件添加到顶层的 events 映射。每个事件都有一个 schema，描述发给订阅者的数据。

事件数据必须是对象。没有数据时用空对象 schema：

TypeScript
events: {
  refreshed: {
    schema: { type: "object", additionalProperties: false },
  },
}

标量、数组、null 和 undefined 都不是合法的事件数据。

实现（Implement）

在 setup 里注册实现：

src/index.tsTypeScript
import { Plugin } from "@opencode/plugin"
import { Acme } from "./rpc.js"

export default Plugin.define({
  id: "acme-plugin",
  async setup(ctx) {
    const registration = await ctx.rpc.register(Acme, {
      search: async (input, context) => {
        const { query } = input as { query: string }
        const text = await findText(query, { signal: context.signal })
        if (!text) return context.error("not_found", "Result not found", { query })
        return { text }
      },
    })

    const acme = ctx.rpc(Acme)
    const result = await acme.search({ query: "hello" })

    await registration.events.emit("updated", { itemID: "item-1", text: "ready" })
  },
})

注册 RPC 之后，同一个插件就能通过 ctx.rpc(Acme) 调用它。

实现的第二个参数包含用于取消的 signal，以及用于声明错误的 context.error(...)。错误可以返回，也可以抛出。

一个插件可以注册多个 RPC。销毁注册即可移除。

调用（Call）

RPC 注册之后，可以通过 HTTP 或从另一个插件调用它。

HTTP

创建一个 OpenCode 客户端，然后用 client.rpc 为这个 RPC 创建子客户端：

TypeScript
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const acme = client.rpc(Acme)
const result = await acme.search({ query: "hello" })

插件（Plugin）

插件本来就有一个 OpenCode 客户端。例如 TUI 插件可以从 context.client 创建同样的 RPC 子客户端：

src/tui.tsTypeScript
import { Plugin } from "@opencode/plugin/tui"
import { Acme } from "opencode-acme-plugin/rpc"

export default Plugin.define({
  id: "acme-tui",
  async setup(context) {
    const acme = context.client.rpc(Acme)
    const result = await acme.search({ query: "hello" })
    console.log(result)
  },
})

GUI 插件则从 ctx.client 读取桌面应用自己那个服务器的客户端：

src/gui.tsxTypeScript · TSX
import { Command, Plugin } from "@opencode/plugin/gui"
import { Acme } from "opencode-acme-plugin/rpc"

export default Plugin.define({
  setup(ctx) {
    ctx.add(Command, {
      id: "search",
      title: "Search Acme",
      run: async () => {
        const result = await ctx.client.rpc(Acme).search({ query: "hello" })
        console.log(result)
      },
    })
  },
})

在使用处读取 ctx.client：服务器重启后它会变化。服务器不可达期间，每次调用都会 reject。

订阅（Subscribe）

用 events.on 注册回调，监听器不再需要时取消订阅：

TypeScript
const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})

unsubscribe()

要异步可迭代对象，用 events.subscribe("updated")：

TypeScript
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}

事件订阅是「活性」的（live only），断开连接的订阅者会错过事件：

  • 订阅时用本地名，比如 updated。
  • 收到的事件类型带前缀，比如 rpc.acme.updated。
  • 每个事件都包含 data 和 location。
  • 插件卸载会关闭它的订阅。

外部客户端会收到所有位置的事件，所以需要时检查 event.location。前提是服务器插件已被配置并正在运行。

💡 扩展

发布技巧：把 rpc.ts 单独作为包的 ./rpc 导出（见插件总览的 exports 示例）。这样其它插件和外部客户端可以只导入契约（拿到类型和 schema），而不必加载你的实现代码——这也是官方推荐在发布时单独导出 ./rpc 的原因。另外，在 Effect 生态里还有一套对应的 Effect RPC 写法。
