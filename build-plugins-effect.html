Effect 插件

@opencode/plugin/effect 是 OpenCode 插件 API 的 Effect 原生版本。它的上下文操作返回 Effect 或 Stream，回调返回 Effect，插件生命周期由 Scope 表示。

🧠 通俗理解

如果你已经用 Effect 写代码，这一页就是「换一套语法讲同一件事」：Promise 插件里的 await ctx.xxx()，在这里变成 yield* ctx.xxx()；setup 变成 effect；插件卸载时自动释放的东西，靠的是 Effect 的 Scope（作用域）而不是手动清理函数。功能、领域、能力与 Promise 插件完全一致。

OpenCode 在加载插件及其 node_modules 依赖时，会在运行时提供 effect（包括导出的 effect/* 子路径）和 @opencode/plugin。请把它们装成 peer/dev 依赖用于本地类型检查和测试，而不要打包进你的插件：

sh
bun add --peer @opencode/plugin effect@4.0.1

把 Effect 插件导出在 .opencode/plugins/ 下即可自动加载：

.opencode/plugins/concise/index.tsTypeScript
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})

已发布的包和 .opencode/plugins/ 之外的插件目录，使用与其它服务器插件相同的 plugins 配置：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",

    "./plugins/local-effect",

      "options": { "agent": "reviewer", "strict": true },

import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})

生命周期

effect 在插件加载时运行。插件重载或卸载时它的作用域会关闭，因此注册项、作用域内 fiber 和终结器（finalizer）会一起释放：

TypeScript
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})

后台工作用作用域内 fiber 来跑。清理期间插件作用域会中断该 fiber：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),

上下文（Context）

上下文暴露所连 OpenCode 服务器的 Effect 客户端，加上仅插件可用的转换（transform）、钩子（hook）、存储、重载和选项。它不暴露 OpenCode 的私有 Core 服务：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),

转换（Transforms）

转换通过一个编辑器（editor）同步编辑状态。OpenCode 在每个领域内按注册顺序应用转换。数据源先贡献提供商和不可变的模型定义；模型转换随后编辑激活提供商的候选集合。把注册 yield 住可以把它留在插件作用域内：

plugins/models-effect/index.tsTypeScript
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})

模型转换可以对完整的激活提供商候选集合执行策略：

plugins/model-budget-effect/index.tsTypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),

转换用到的外部状态变化时调用 reload。下面例子里 loadFromSource() 返回 { info: Provider.Info, models: readonly Model.Info[] } 条目；提供商重载还会让整个模型结果失效：

plugins/models-effect/index.tsTypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),

API

Agent

读取全部 agents，或按 ID 获取一个。客户端响应包含解析后的位置和 schema 数据：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),

转换或重载 agents：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),

Providers（提供商）

读取可用提供商，或按 ID 查看某个提供商的元数据：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),

提供商转换编辑提供商设置和数据源定义。编辑器读取包括未激活的提供商，并暴露不可变定义；models.update 编辑数据源模型的自有副本：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-5-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),

用 models.set 替换数据源清单，之后在其捕获的定义变化时重载：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),

要做按账号区分的发现，把用于加载清单的连接作为 sourceConnection 传入。OpenCode 会在选中另一个连接期间排除该提供商，直到你的插件发布刷新后的清单：

TypeScript
const connection = yield* ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield* loadInventory(connection)
yield* ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})

Schema：Provider.Info、Model.Info。

Models（模型）

读取可用模型和默认选择：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),

模型转换编辑整个激活提供商候选集合。所有转换结束之前被禁用的候选保持可编辑；update 只能在可用提供商下新增模型：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-5-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),

回调编辑原始模型覆盖。OpenCode 在提交结果时一次性合并提供商默认值；未变化的读取复用该结果。editor.provider 读取不可变的源定义（包括未激活模板），而不是模型转换的输出：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),

Commands（命令）

读取当前位置可用的命令：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),

当前命令转换是只增（add-only）的。执行器收到会话、提示词附件和投递模式：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),

Integrations（集成）

读取集成，并在存在时解析激活凭据：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),

用 key 连接，或通过所连 API 驱动一次 OAuth 尝试：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),

转换集成与认证方式。OAuth 方式回调是 Effect，可以获取作用域内的资源：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),

MCP

列出 MCP 服务器及其当前连接状态：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),

插件只能通过转换管理 MCP 服务器。用 editor.set 新增或替换服务器，editor.update 修改配置，editor.remove 移除。用 editor.list 和 editor.get 检查配置：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),

在转换里设 disabled: true 禁用服务器并断开连接；设 disabled: false 启用并允许 OpenCode 连接。OpenCode 按转换后的配置协调服务器生命周期。

转换用到的外部状态变化后调用 reload()，重新应用转换并协调服务器：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),

Tools（工具）

用 Effect Schema 注册类型化工具。执行器收到解码后的输入，返回包含类型化输出、展示内容或元数据的 Effect。

编辑器支持 add、update、remove。转换回调是同步的：不能返回 Effect 或 Promise。注册或重载之前先加载外部数据。OpenCode 会在新编辑器上按注册顺序重放活跃转换；同名生效工具，后一次有效注册覆盖前一次：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),

回调捕获的源数据变化后调用 yield* ctx.tool.reload()。重载按原顺序重放活跃转换，但不重跑插件 effect。

Effect 工具接受与 Promise 工具相同的自由格式输入声明。模型不支持该格式时，工具保留其正常的对象输入。

工具的 id 包含其生效名称，get() 在该 ID 不存在时返回 undefined。update 和 remove 用生效工具名（含命名空间，如上面的 acme_greeting）。命名空间里的点号和工具名中的不支持字符变成 _。缺失的名字被忽略；创建工具必须用 add 传完整定义。更新保留名称与命名空间。要替换 schema 或选项就整体赋新值，而不要改嵌套值。非法更新会被记录日志，并保持之前的定义不变：

TypeScript
yield* ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})

更新和移除与新增按顺序一起重放，包括 MCP 目录刷新之后。

transform 返回一个作用域注册。运行 yield* registration.dispose 移除其转换并基于剩余转换重建，露出被它覆盖的更早定义。销毁是幂等的；关闭插件作用域也会销毁其注册。

每次模型请求捕获一份工具快照。重载和销毁影响未来的快照，不影响已有请求已捕获的定义或执行器。闭包引用可变插件数据的执行器仍会观察到数据变化；值必须与定义绑定时，就在转换内捕获住它。

Schema：Tool.Content、Tool.TextContent、Tool.FileContent。

钩子（Hooks）

钩子拦截正在发生的操作。多个插件可以注册同一个钩子；OpenCode 按插件顺序执行它们，后面的钩子能看到前面钩子的修改。注册项在插件作用域内保持有效：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),

Sessions（会话钩子）

在模型派发前一刻修改组装好的系统指令、消息或工具。context 用于智能体循环；compaction、generate、title 用于那些辅助请求。compaction 和 title 接受一个跳过模型调用的 result：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),

context、compaction、generate 钩子里的消息携带其存储消息的 metadata（只读，例如某个 prompt 钩子设置的值）。它不会发给模型。

承载 OpenCode 指令的 system 部分还在 metadata.experimental.instructions 里以 { key, text } 列出每个来源，比如 core/date 或 core/environment，钩子借此区分来源。该列表是一份副本：修改该部分的 text 不会同步它。这是实验性行为，可能变化。

修改模型请求设置，并可选把钩子限定到一个提供商。事件携带的 kind 与下面的 HTTP 钩子相同：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),

修改原生提供商请求或响应。它们的 body 是一次性流；读取之前先 clone 或整体替换。两个钩子都会对会话发出的每个请求运行；event.kind 按发出流程为 "primary"、"compaction"、"title" 或 "generate"：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),

通过 WebSocket 流式输出的提供商每个会话复用一条连接，所以 HTTP 钩子看不到那些流量。实验性的 experimental.ws.handshake 钩子在一次模型调用中、连接选定之前运行一次，暴露连接的 url 和 headers；修改任一个都会重开 socket。WebSocket 路由回退发出的请求仍会走 HTTP 钩子：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),

experimental.ws.send 和 experimental.ws.receive 暴露帧本身：send 在提供商驱动构造完出站帧后运行；receive 在每个入站帧被驱动观察到之前运行。钩子返回时 frame 里是什么，什么就上线或到达驱动；OpenCode 不校验它：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),

覆盖某个提供商失败时的重试决策，或替换它的毫秒级延迟。钩子在 OpenCode 对失败分类并提出自身策略之后、任何重试被调度之前运行。它不暴露 OpenCode 内部如何执行下一次尝试：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),

初始 decision 是 OpenCode 的策略，所以钩子可以把一次通常的终态提供商失败变成可重试，或否决一个提议的重试。多个钩子按注册顺序运行，后面的钩子看到当前决策。内置最大尝试次数仍是硬上限。attempt 是被提议的物理尝试次数；初始请求是第 1 次，所以第一次重试是第 2 次。非法延迟（NaN、无穷、负值）回落到计算出的延迟。上下文溢出恢复仍是独立路径，因为它压缩对话而不是重试同一请求。

      event.tool === "write"
        ? Effect.fail(new Tool.Error({ message: "Writes are disabled" }))
        : Effect.logDebug("tool input", { tool: event.tool, input: event.input }),
    )
  }),

after 钩子可以检查或替换成功的结果与失败：

TypeScript
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.after", (event) => {
      if (event.status === "error") return Effect.logWarning("tool failed", { message: event.error.message })
      return Effect.sync(() => {
        event.result = { ...event.result, metadata: { observed: true } }
      })
    })
  }),

发布（Publish）

包插件使用与本地 Effect 插件相同的默认导出。从主入口导出 Effect 实现，并把 effect 声明为 peerDependency。在 devDependencies 下，固定 @opencode/plugin 使用的那个版本，让开发环境只装一份：

package.jsonJSON
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.1"
  },
  "devDependencies": {
    "effect": "4.0.1"
  }
}

OpenCode 会把 effect、导出的 effect/* 子路径和 @opencode/plugin（包括插件 node_modules 中依赖的导入）重定向到宿主的运行时实例，让 fiber、logger 和 Schema 解析器共享同一份运行时副本：

  • 不要把 effect 打包进发布产物。用打包器构建时，把 effect 和 effect/* 标记为 external。
  • 插件及其 node_modules 依赖永远针对宿主 OpenCode 版本的 effect 实例执行。使用与你目标 OpenCode 版本兼容的 effect API 和模块路径；基于其它 effect 大版本（如 Effect 3）构建的依赖也会拿到宿主的 effect，不受支持。
  • 只提供公开的 effect 子路径。导入 Effect 私有 internal 模块的插件会加载失败，错误信息会点名那个路径。
  • 编译后的 OpenCode 二进制不包含 Effect 的 HTTP API 文档页所需的 Scalar 和 Swagger UI 资源；从插件里伺服那些页面只会显示一条提示。

  id: "acme.published",
  effect: (ctx) =>

})

💡 扩展

「effect 必须外置」是 Effect 插件最重要的一条规则：宿主进程里已经跑着一份 effect 运行时，你的 bundle 如果自带一份，两边的 Schema、fiber、logger 就不是同一个实例，行为会莫名出错。这与 GUI 插件的共享模块规则一脉相承——宿主提供什么，你就从宿主拿什么。
