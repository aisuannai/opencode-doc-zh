SCIM

目录同步（Directory sync，SCIM 2.0）让你在身份提供商（IdP）里指派人员时自动把人加进工作区，取消指派时自动收回访问权。角色仍由 Console 管理。

🧠 通俗理解

如果说 SSO 解决的是「怎么进门」，SCIM 解决的就是「名单谁说了算」。开启后，你们 Okta / Entra ID 里把员工加进某个应用，Console 工作区就自动多一个成员；员工调岗、离职被取消指派，访问权立刻冻结。人事异动只需要在 IdP 一处操作，Console 自动跟上——这正是大公司青睐的「单一事实来源」模式。

https://opencode.ai/console/scim/v2

开始之前

  • 先为工作区配置好 SSO。
  • 验证员工登录所用的每一个邮箱域名。目录同步只会添加已验证域名下的人；其他人请从 Members 页手动邀请。

创建 Token

只有工作区所有者（Owner）可以配置目录同步，或创建、吊销其 token。

  1. 打开 Settings › Security，在 Directory sync 下点击 Set up。
  2. 复制 SCIM base URL 和 token。token 只显示一次，请存进密码管理器（secrets manager）。

你的身份提供商会在每个请求中携带该 token：

text请求头
Authorization: Bearer <token>

连接你的身份提供商

Okta

  1. 添加 SCIM 2.0 Test App (Header Auth) 应用。
  2. 设置 base URL，并在 API Token 中输入 Bearer 加上 token。
  3. 启用 Create Users、Update User Attributes 和 Deactivate Users。Import Groups 和密码同步保持关闭。

Microsoft Entra ID

  1. 在你的企业应用中打开 Provisioning，把模式设为 Automatic。
  2. 把 base URL 填为 Tenant URL，token 填为 Secret Token。
  3. 指派用户和组，然后开始预配（provisioning）。

其他提供商

使用一个支持请求头 token 认证的 SCIM 2.0 应用，指向上述 base URL。Console 支持 /Users 和 /Groups 端点。

先只指派一位测试人员。第一次请求之后，Directory sync 会显示 Connected to your identity provider。

同步内容

在身份提供商中的操作在 Console 中的效果
指派一个人以 Member 身份加入。已有成员保持原有角色。
更新姓名资料同步更新。
取消指派或停用访问被挂起，显示为 Deactivated。其创建的 API key 被吊销。
重新指派访问恢复。已吊销的 key 保持吊销状态。
删除从工作区移除。其账号和其他工作区不受影响。
  • 目录同步不会改动角色和邮箱地址。
  • 最后一位所有者不能被停用或删除。
  • 有 Go 订阅的工作区无法通过目录同步添加成员。

⚠️ 注意

两个容易踩的坑：其一，「重新指派」后被吊销的 key 不会复活——之前挂在他名下跑的自动化任务要重新发 key；其二，有 Go 订阅的工作区不能靠 SCIM 加人，因为 Go 是按座位计费的，加人要走 Members 的邀请/升级流程。

组（Groups）

把组推送过来即可给成员打标签，例如用 Okta 的 Push Groups 或 Entra 的组指派。推送组之前先指派组里的人。

text组 → 标签示意
Platform Admins  →  platform-admins

每个组都会用一个以该组命名的标签来标记它的成员。在 Settings › Security › Group tags 下，你可以重命名标签、把多个组指向同一个标签，或停止对某个组打标签。离开一个组会移除对应的标签。

轮换 Token

  1. 点击 New token，把它安装到你的身份提供商。
  2. 等到新 token 显示出最近使用时间（last use）。
  3. 吊销旧 token。

吊销 token 会阻止后续的更新，但不改变现有成员。删除 SSO 连接会吊销所有 token。

💡 扩展

「先装新 token → 等新 token 出现使用记录 → 再吊销旧的」是标准的零停机轮换顺序：中间有个新旧并存的窗口，保证切换瞬间没有断档。直接吊销旧的再慢慢装新的，IdP 的每次同步都会在这段空窗期报 401。

SSO 与目录同步

一旦工作区签发过 SCIM token，SSO 就不再自动添加成员。谁属于工作区由目录（directory）说了算——即使 token 后来被吊销也是如此。

🧠 通俗理解

这其实是「领导权交接」：没配 SCIM 前，登录即加入（SSO 管名单）；配了 SCIM 后，名单的权威永远交给目录，哪怕 SCIM 后来停了，Console 也不会自动退回「登录即加入」的宽松模式。这防止了「SCIM 停一下，被 IdP 移除的人又靠 SSO 自动混进来」的安全漏洞。
