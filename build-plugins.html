插件总览

插件（plugin）可以修改 OpenCode 的行为、添加新功能。一个插件就是一个 npm 包，里面可以包含服务器（server）部分、TUI 部分、GUI 部分，或它们的任意组合。

.opencode/plugins/example/index.tsTypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})

⚠️ 注意

已经在用 OpenCode 1 的老插件？本站插件 API 是 2.x 版本的新体系，请先按 插件迁移（V1 → V2）指南迁移，再按本页结构组织代码。

包的组成部分（Parts）

每个部分（part）都是包的一个导出（export）。所有部分的 SDK 都来自同一个依赖 @opencode/plugin。

package.jsonJSON
{
  "name": "opencode-acme-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./tui": "./src/tui.tsx",
    "./gui-experimental": "./dist/gui-experimental.cjs",
    "./rpc": "./src/rpc.ts"
  },
  "files": ["src", "dist"],
  "dependencies": {
    "@opencode/plugin": "latest"
  }
}

四种部分的分工：

部分导出路径运行位置 / 依赖子路径能力
服务器（Server）. 或 ./serverOpenCode 服务器内，@opencode/plugin添加工具、钩子（hook）、集成、命令和 agents。见服务器插件；Effect API 见 Effect 插件。
TUI./tui终端界面内，@opencode/plugin/tui见 TUI 插件。
GUI./gui-experimentalOpenCode Desktop，@opencode/plugin/gui它的 setup 在每个桌面窗口里运行，main 在桌面应用的主进程里运行。见 GUI 插件。
RPC./rpc类型化契约由服务器部分实现，其它部分和客户端调用。见 RPC。

🧠 通俗理解

把插件包想象成一家公司：服务器部分是「总部」，负责所有核心业务（工具、钩子、命令）；TUI 和 GUI 部分是两家「门店」，各自只关心自己界面上呈现什么；RPC 是公司内部的「对讲机协议」——总部定义并实现接口，门店和外部客户按同一份契约呼叫总部。所有门店共享一个依赖（@opencode/plugin），不需要各装一套。

几个关于 id 的规则：插件的 id 来自其服务器部分 Plugin.define 里的声明。如果包只有 GUI 部分而没有服务器部分，则取包名（本地目录则取目录名）作为 id。TUI 部分要自己声明 id；GUI 部分不声明，直接沿用插件的 id。

加载（Load）

放在 .opencode/plugins/ 目录下的插件会自动加载，就像上面那个本地示例一样。要加载已发布的 npm 包、或位于其它位置的插件目录，把它们加进 opencode.json(c) 的 plugins 字段：

opencode.jsoncJSONC
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
  • 一个条目加载全部部分。服务器加载插件的全部部分；TUI 会加载其服务器所加载插件的 TUI 部分；OpenCode Desktop 会加载你全局 opencode.json(c) 中插件的 GUI 部分。
  • 只有 TUI 部分的包，要放进 cli.json 而不是 opencode.json(c)。
  • 本地插件目录如果带有 package.json 的 name 和 exports 字段，就按它们加载各部分，行为和已发布包一样。没有这两个字段时，则按根目录下的文件名加载：server（缺省回退到 index）、tui、rpc，扩展名可以是 .ts、.tsx 或 .js；GUI 部分则是 gui-experimental.cjs（或 .js）。
  • 更多加载与配置选项见配置插件一章。

⚠️ 注意

「只有 TUI 部分的插件放 cli.json」这条容易搞反：opencode.json(c) 是项目/全局级配置，管的是有服务器部分的完整插件；而 cli.json 只管 TUI 界面层的扩展。如果你的插件带服务器部分（哪怕只是想让 RPC 生效），就应该放 opencode.json(c)。

发布（Publish）

已发布的插件就是一个带有上面那种 package.json 的 npm 包。它的各部分与本地插件使用相同的默认导出（default export）。

bash
npm publish
  • 当其它插件和客户端需要在不加载你实现的情况下导入你的 RPC 契约时，要单独导出 ./rpc。
  • 发布前要先构建 GUI bundle，并通过 files 字段把它包含进包里。见 GUI 插件 · 构建 bundle。
  • 使用的版本要与你目标支持的 OpenCode 版本兼容；安装后要用真正安装的包来测试，而不能只测工作区里软链（workspace-linked）的副本。当你采用更新的 API 契约时，要发布一个兼容的插件更新。

💡 扩展

最后一条是 npm 插件开发者的经典翻车点：开发时用 npm link 或 monorepo workspace 引用，一切正常；一发布，用户环境里解析依赖的方式不同就炸了。发布前用 npm pack + 在干净项目里 npm install ./xxx.tgz 做一轮「安装态测试」，能省掉大量售后问题。

延伸阅读

  • 服务器插件——在 OpenCode 服务器中添加工具、钩子、集成、命令和 agents。
  • TUI 插件——给终端界面添加命令、路由、插槽和 Markdown 渲染器。
  • GUI 插件——给 OpenCode Desktop 添加面板、命令、设置页和原生集成。
  • RPC——把服务器部分的类型化方法和事件暴露给其它部分和客户端。
