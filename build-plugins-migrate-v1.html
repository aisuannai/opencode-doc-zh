插件迁移（V1 → V2）

插件的配置可以被自动规范化，但插件的实现代码必须手动移植。V1 插件函数返回一个包含工具（tool）和钩子（hook）的对象；V2 插件默认导出一个带 id 和 setup(ctx) 的定义，setup 通过上下文注册钩子、转换、工具和订阅。

⚠️ 注意

V1 插件实现不会在 V2 里运行。只是挪一下文件位置、或改一下配置条目的名字，是不够的。

迁移插件配置

把 plugin 改名为 plugins。把「包 + 选项」的元组改成对象：

opencode.jsonc · V1 → V2JSONC
// V1
{
  "plugin": [
    "opencode-example-plugin",
    ["./plugin/local.ts", { "enabled": true }]
  ]
}

// V2
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugin/local",
      "options": { "enabled": true }
    }
  ]
}

V2 会同时从 .opencode/plugin/ 和 .opencode/plugins/ 发现本地插件；V2 的文件请使用 .opencode/plugins/。配置的本地路径必须指向目录。按上面的例子，要把移植后的实现挪到 ./plugin/local/index.ts；配置成 ./plugin/local.ts 的文件会被跳过并在日志里告警。挪动插件时，把辅助模块放在插件旁边。本地插件和包插件使用相同的实现 API。

替换入口（Entrypoint）

修改包的导入，把导出的插件函数换成 Plugin.define，并把初始化逻辑挪进 setup：

V1TypeScript
import type { Plugin } from "@opencode-ai/plugin"

export const ExamplePlugin: Plugin = async ({ directory, project, client }) => {
  await client.app.log({
    body: { service: "example", level: "info", message: `Loaded for ${project.id}` },
  })

  return {
    // V1 的工具和钩子
  }
}
V2TypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("last-project", ctx.location.project.id)
    console.log(`Loaded for ${ctx.location.directory}`)
  },
})

每个 V2 插件都需要一个稳定的 id。插件存储按这个 ID 划分作用域，这个 ID 也是插件在状态与诊断信息里的标识。已发布的插件应依赖与其目标 OpenCode 版本兼容的 @opencode/plugin 版本。

迁移上下文（Context）

V2 上下文既是 OpenCode 客户端，也是插件 API。大多数操作按领域（domain）分组，而不是挂在一个单独的 client 属性上：

V1V2
directoryctx.location.directory
projectctx.location.project
client领域方法，如 ctx.session、ctx.permission、ctx.agent
插件选项参数ctx.options
返回的 dispose() 钩子setup 返回的清理函数
返回的 event 钩子ctx.event.subscribe()
返回的 config、model 或 tool 变更某个领域的 transform(...)
$ Bun shell 辅助函数导入并管理你的插件所用进程 API

ctx.location 描述的是当前插件实例被加载的位置，不是插件可能观察到的每个会话或事件的位置。这个区别重要时，去读会话或事件数据。

上下文暴露的领域远多于上表所列，包括目录（catalogs）、命令、集成、MCP 服务器、引用、技能、存储、VCS、工作树和网页搜索。见完整的插件上下文。

在 setup 里注册钩子

V1 按字符串键返回钩子。V2 在拥有该操作的领域上注册每个钩子。回调收到一个可变的事件对象，而不是分开的 input 和 output 对象：

V1TypeScript
import type { Plugin } from "@opencode-ai/plugin"

export const GuardPlugin: Plugin = async () => ({
  "tool.execute.before": async (input, output) => {
    if (input.tool === "read" && output.args.filePath.includes(".env")) {
      throw new Error("Do not read .env files")
    }
  },
  "shell.env": async (_input, output) => {
    output.env.COMPANY_ENV = "development"
  },
})
V2TypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.guard",
  async setup(ctx) {
    await ctx.tool.hook("execute.before", (event) => {
      const input = event.input as { filePath?: string }
      if (event.tool === "read" && input.filePath?.includes(".env")) {
        throw new Error("Do not read .env files")
      }
    })

    await ctx.shell.hook("create.before", (event) => {
      event.env.COMPANY_ENV = "development"
    })
  },
})

注册在插件生命周期内保持有效，插件卸载时被销毁。只有当插件需要提前移除某个特定钩子或转换时，才保留返回的注册并用 registration.dispose()。

🧠 通俗理解

这张表是「目的地地图」而非「改名清单」。最大的语义变化在时机上：V2 的 prompt 钩子跑在提示词持久化收件之前，而 context 跑在智能体模型请求前一刻。如果一个转换要应用到每一种模型请求，就把 context、compaction、generate、title 分别注册一遍——V1 里一个钩子包打天下，V2 里各管一段。

并非每个实验性 V1 钩子都有直接的 V2 对应物。使用 experimental.compaction.autocontinue、experimental.provider.small_model 或 experimental.text.complete 的插件，请基于 V2 的 session、provider、model 和 event API 重新评估，而不是保留一个内部生命周期假设。

command.execute.before 也没有一对一的全局钩子。当插件拥有那个命令时，用 ctx.command.transform 注册命令。当真实意图是修改命令和其它提示来源提交的提示词时，用 prompt 钩子。

迁移请求钩子

V2 把提示收件、模型可见上下文、语义模型选项和原生 HTTP 分开了。选你的插件需要的最窄一层：

V1TypeScript
import type { Plugin } from "@opencode-ai/plugin"

export const RequestPlugin: Plugin = async () => ({
  "chat.params": async (_input, output) => {
    output.temperature = 0.2
    output.maxOutputTokens = 8_000
  },
  "chat.headers": async (_input, output) => {
    output.headers["x-plugin"] = "review"
  },
  "experimental.chat.system.transform": async (_input, output) => {
    output.system.push("Focus on correctness.")
  },
})
V2TypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "review-request",
  async setup(ctx) {
    await ctx.session.hook("context", (event) => {
      event.system.push({ type: "text", text: "Focus on correctness." })
      event.options.temperature = 0.2
      event.options.maxTokens = 8_000
    })

    await ctx.session.hook("model.request", (event) => {
      event.headers["x-plugin"] = "review"
    })
  },
})
  • 在 event.options 里使用语义化的提供商选项。
  • 模型请求头和原始请求设置用 model.request；只有插件需要原生提供商 HTTP 交换时才用 http.request 或 http.response。
  • 特定提供商的钩子可以把 { providerID: "..." } 作为 ctx.session.hook 的第三个参数传入。

迁移自定义工具

V1 返回一个用旧 tool() 辅助函数构建的 tool 映射。V2 通过同步的 ctx.tool.transform 编辑器注册工具定义。工具 schema 使用 JSON Schema，执行返回结构化内容：

V1TypeScript
import { tool } from "@opencode-ai/plugin"

export const ToolsPlugin = async () => ({
  tool: {
    greeting: tool({
      description: "Create a greeting",
      args: { name: tool.schema.string() },
      async execute(args) {
        return `Hello ${args.name}!`
      },
    }),
  },
})
V2TypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "greeting",
  async setup(ctx) {
    await ctx.tool.transform((editor) => {
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: {
          type: "object",
          properties: { name: { type: "string" } },
          required: ["name"],
          additionalProperties: false,
        },
        async execute(input) {
          return { content: `Hello ${(input as { name: string }).name}!` }
        },
      })
    })
  },
})

转换是可重放的状态编辑。保持回调同步、廉价、并且没有一次性副作用。注册之前加载外部数据，在回调里捕获它，数据变化时调用该领域的 reload()。后一个插件的转换能看到前面的修改，并可以更新、替换或移除它们。

同样的转换模式替代 V1 的 config 和 provider 钩子，但 V2 不再暴露一个可变的全局配置对象。把变更注册到拥有它的领域：ctx.agent、ctx.provider、ctx.model、ctx.command、ctx.integration、ctx.mcp、ctx.reference、ctx.skill、ctx.tool、ctx.vcs、ctx.websearch 或 ctx.worktree。认证方式属于集成；提供商转换贡献源定义和提供商设置，模型转换对完整的激活提供商模型集合施加限制和覆盖：

TypeScript
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
})

await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    if (!model.capabilities.tools) editor.remove(model.providerID, model.id)
  })
})

迁移事件与清理

V1 的 event 回调变成对公共服务器事件流的异步订阅。在 setup 返回的清理函数里中止它：

V2TypeScript
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "notifications",
  setup(ctx) {
    const controller = new AbortController()

    void (async () => {
      for await (const event of ctx.event.subscribe({ signal: controller.signal })) {
        if (event.type === "session.idle") console.log("Session completed")
      }
    })()

    return () => controller.abort()
  },
})

用清理函数管理定时器、子进程、socket 等插件拥有的资源。钩子和转换注册以插件为作用域，会被自动清理。

迁移选项与持久化状态

从 ctx.options 读选项。状态属于插件时，用 ctx.storage 而不是自己发明一个全局文件；它的 JSON 值是持久化的，且以插件为作用域：

TypeScript
const strict = ctx.options.strict === true
await ctx.storage.set("settings", { strict })
const settings = await ctx.storage.get("settings")

同一个包同时支持 V1 和 V2

一个包可以临时从同一个默认导出暴露两套实现。V1 调用 server()，V2 调用 setup()。两套 API 仍然分开；这种形态不会自动翻译钩子：

src/index.tsTypeScript
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}

V1 对象入口从 OpenCode 1.18.29 起受支持。如果你要支持更老的 V1 版本，请使用单独的包版本或入口，并测试你声称支持的最老版本。支持窗口结束后移除 V1 实现。

验证移植后的插件

对每个插件：

  1. 确认它的 ID 和来源出现在活跃插件列表里。
  2. 触发每一个已注册的钩子、转换、工具、命令和事件订阅。
  3. 通过重载或移除插件验证清理。
  4. 用一个干净的项目测试插件选项和持久化状态。
  5. 对已发布的包，测试真正安装的包，而不是只测工作区软链副本。
