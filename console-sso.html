SSO

单点登录（Single Sign-On，SSO）让工作区成员登录时统一走你们公司的身份提供商（Identity Provider，IdP）。所有者在 Settings › Security 里配置，每个工作区都自带这项功能。

🧠 通俗理解

没有 SSO 时，每个员工要为 OpenCode 单独记一套账号密码；有了 SSO，他们用公司已有的账号体系（Okta、Entra ID 等）一键登录，密码策略、两步验证、离职停用全都沿用公司现成的那套。对 IT 部门来说，这就是「把 OpenCode 纳入统一的门禁系统」，而不是多看管一扇散养的侧门。

协议支持的提供商
OpenID ConnectGoogle Workspace、Microsoft Entra ID、Okta、Auth0、Ping Identity，或任何 OIDC 提供商
SAML 2.0Google Workspace、Microsoft Entra ID、Okta，或任何 SAML 提供商

每个工作区只能有一个 SSO 连接。

配置 OIDC

  1. 打开 Settings › Security，点击 Configure SSO，选择 OpenID Connect 和你的提供商。
  2. 按页面显示的步骤在你的提供商处创建一个应用，作用域（scopes）为 openid、email、profile。
  3. 填写 Issuer URL（或你的租户/域名），加上 Client ID、Client Secret 和一个显示名称，然后点击 Save。
  4. 把连接页面里的 Callback URL 复制到你的提供商的允许重定向 URI 列表中。
textCallback URL
https://opencode.ai/console/auth/sso/ssoconn_.../callback

保存时 Console 会检查 issuer 是否可达。连接保存成功后，SSO 立即生效。

配置 SAML

  1. 打开 Settings › Security，点击 Configure SSO，选择 SAML 2.0 和你的提供商。
  2. 把 ACS URL 和 SP Entity ID 填入你的提供商。自定义提供商也可以改用 SP Metadata URL，或下载 XML。
  3. 通过 URL、上传 XML 或粘贴的方式添加你提供商的元数据（metadata）。也可以手工填写 IdP Entity ID、IdP SSO URL 和 IdP Certificate。
  4. 检查各项详情，点击 Activate SSO。
textSAML 配置值
ACS URL:       https://opencode.ai/console/auth/sso/ssoconn_.../callback
SP Entity ID:  https://opencode.ai/console/auth/sso/ssoconn_.../metadata

你的提供商必须对 response 或 assertion 签名，并把用户邮箱作为 email 属性或 NameID 发送。

验证邮箱域名

用已验证域名下的邮箱登录控制台的人，会被引导到你们的身份提供商。SSO 生效后，在 Email domains 下点击 Add domain，输入你的域名，并发布页面上显示的 TXT 记录：

textDNS 记录
Name:   _opencode-console-challenge.example.com
Type:   TXT
Value:  oc-verify=...

记录发布后点击 Verify Domain。DNS 变更的传播可能需要一段时间。每个域名只能属于一个工作区。

SSO 强制执行

工作区启用 SSO 后，管理员和成员必须通过 SSO 登录才能打开工作区，Console 会自动把他们重定向过去。用 /connect 连接 OpenCode 同样遵守这条规则。

所有者仍可以不走 SSO 登录——这样即使提供商配置出错，也不会把工作区的设置整个锁死。

💡 扩展

「Owner 可绕过 SSO」是典型的防呆后门：万一 IdP 那边改了证书、域名过期或配置手滑，普通成员全被挡在门外，但至少 Owner 还能进来把 SSO 关掉或修好。这也是为什么 Owner 账号建议绑定一个不依赖公司域名的个人邮箱并妥善保管。

自动加入（Automatic membership）

已验证域名下的人第一次通过 SSO 登录时，会以 Member 身份加入工作区。以下情况不会自动加入：

  • 他有一条待处理邀请。此时会改用那份邀请处理。
  • 工作区启用了目录同步（directory sync），成员身份由它决定。
  • 工作区有 Go 订阅。

发给 SSO 工作区的邀请，受邀者打开链接时会被引导到你们的身份提供商。

已有账号

如果某人已经用同一个邮箱注册过 Console 账号，他会在 SSO 流程中再次登录，并通过 Link account 确认关联。邀请流程不会跳过这一步确认。在已验证域名的工作区上由 SCIM 供应的账号仍可以自动关联。

编辑或删除

点击连接上的 Edit 可以修改详情。把密钥（secret）或证书留空即表示保留当前值。要在 OIDC 和 SAML 之间切换，需删除现有连接后重新创建。

在 ⋯ › Delete... 中删除连接。成员会退回到他们其他的登录方式，目录同步随之停止（其 token 被吊销）。邮箱域名的验证记录会保留。

⚠️ 注意

删除 SSO 连接不只是「关个开关」：如果工作区同时开了目录同步，同步会立刻停止且 token 被吊销，之后成员名单只能手动管理。切换 OIDC↔SAML 也要删除重建，过程中的时间窗内成员可能暂时进不了工作区，建议在低峰期操作。
