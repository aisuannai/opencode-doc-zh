会话预热

会话预热（Session Warming）在你停下思考的间隙，定期向模型发轻量请求，以保住提供商侧的提示词缓存（prompt cache）或其它短时效状态。默认关闭。

🧠 通俗理解

很多模型提供商对「重复前缀」的请求给缓存折扣：同样的系统提示 + 对话历史第二次发过去时便宜得多——前提是缓存没过期。但你思考、开会、吃饭的半小时里不发请求，缓存就凉了，回来后第一条消息要重新全价计费。预热就像咖啡馆店员每隔几分钟往你的杯子里续一口热水，让这杯「缓存拿铁」一直保持温度，你回来接着喝就还是折扣价。

启用

在任意 OpenCode 配置文件里启用预热：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "warming": true,
}

在这个配置下，OpenCode 会在最近活跃的会话的提示词缓存恰好过期之前预热：按模型 cache.ttl 的 90%，没有该设置时每 4 分钟一次。它一直持续到距最近一次非预热请求已过 30 分钟。

选项

用对象形式可以修改预热提示词、空闲间隔或活跃窗口：

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "5 minutes",
    "duration": "1 hour",
  },
}
字段默认值用途
prompt保活指令作为临时用户消息附加到每次预热请求。默认的指令让模型什么都不做、不用任何工具、只回复 OK。
interval"auto"距下一次预热请求的空闲时间。"auto" 用模型 cache.ttl 的 90%，没有则 4 分钟。
duration"30 minutes"预热窗口，从最近一次非预热模型请求算起。

省略的对象字段保持默认值。比如这里只改间隔：

opencode.jsonc
{
  "warming": {
    "interval": "2 minutes",
  },
}

自动间隔

默认 interval 为 "auto"，会在每个模型的提示词缓存即将过期时预热。OpenCode 用模型 cache.ttl 设置的 90%，所以 "5m" 的缓存每 4.5 分钟预热一次。没有 cache.ttl 的模型每 4 分钟预热一次。

opencode.jsonc
{
  "warming": { "duration": "2 hours" },
  "providers": {
    "anthropic": { "settings": { "cache": { "ttl": "1h" } } },
  },
}

比 duration 更长寿的缓存（比如 "1h" 配 30 分钟默认窗口）不会被预热，反正它本来就能活过整个预热窗口。OpenCode 会每会话记录一次这种情况。想预热它就把 duration 调大。

按提供商和模型设置

在提供商或模型上设置 settings.cache.warming，可以只预热它的会话，或给它们单独的节奏。它的取值与顶层 warming 相同（prompt 除外），并覆盖顶层设置；模型设置又覆盖提供商设置。

opencode.jsonc
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "5m", "warming": true } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "warming": false } } },
      },
    },
  },
}

这个例子里 Anthropic 的会话每 4.5 分钟预热一次，Claude Haiku 5.5 除外，其它提供商不预热。对象形式里省略的字段来自顶层 warming，再往上是默认值。无效的设置会记录警告并回退到顶层 warming。

时长写法

interval 和 duration 接受时长字符串。两者都必须解析为大于零的有限值，且 interval 必须短于 duration；否则 OpenCode 跳过预热并记录警告：

opencode.jsonc
{
  "warming": {
    "interval": "30 seconds",
    "duration": "1 hour",
  },
}

时机

预热从顶层会话里某次非预热模型请求之后开始。子智能体（subagent）会话不预热。每个间隔从「最近一次请求或预热请求发出时」起算，而不是从响应结束起算——因为提供商的缓存寿命从请求抵达它那一刻开始。预热请求不会延长活跃窗口：

text
00:00  normal model request sent
00:01  response finishes
00:04  warming request
00:08  warming request
00:30  warming stops

任何新的非预热模型活动（包括压缩 compaction）都会重置两个计时器。显式设置的间隔如果大于等于 duration，会被拒绝并警告；"auto" 间隔达到这个长度时跳过预热，因为缓存本来就活得过窗口：

text
00:00  normal model request
00:20  normal model request; window restarts
00:24  warming request
00:50  warming stops

当某个模型请求（包括压缩）正在运行时，OpenCode 绝不发送预热请求。间隔到期时如果请求还没结束，预热会等它结束、且该请求的缓存尚未过期时立即补发；如果缓存已过期，预热停止，直到下一次正常请求：

text
00:00  normal model request sent
00:04  interval due; request still running
00:04:30  response finishes; warming request
00:08:30  warming request

请求内容

预热请求使用会话当前的模型、智能体、指令和对话上下文。OpenCode 临时附加配置的提示词、做一次模型调用、然后丢弃响应：

text
[current session context]
[transient user message: keep-alive prompt]
→ one model response, discarded

这个请求不让新输入进入、不往历史里加消息、也不改动会话的持久状态。OpenCode 不派发本地工具调用、也不延续工具循环；默认提示词还明确让模型不要使用工具。

失败处理

预热失败只记录日志，不会让会话失败或改变会话。OpenCode 等到下一个间隔再试，同时原有的活跃窗口继续倒计时：

text
00:04  warming request fails; session is unchanged
00:08  next warming attempt

如果一次预热请求「没吃到缓存」（从缓存读的量少于写入的量），该会话的预热会停止，直到下一次非预热请求。不报告缓存用量的提供商永远不会算作 miss：

text
00:04  warming request misses the cache; warming stops
00:10  normal model request; warming resumes
00:14  warming request

成本

预热请求是真实的提供商请求：会消耗 token、产生费用、占用速率限额，也会像其它模型请求一样失败。

  • 间隔越短，请求量越大。
  • 窗口越长，允许的预热请求越多。
  • 只有当提供商侧的收益值得这些额外用量时，才开启预热。

比如对一个没有 cache.ttl 的模型，默认配置在一次不间断的 30 分钟窗口里最多允许 7 次预热：在第 4、8、12、16、20、24、28 分钟。

⚠️ 注意

预热是「花钱保折扣」的交易，不是免费的优化。如果缓存折扣低于 50%，一次成功的预热要用掉真金白银的 token 换一份省钱的机会；对便宜模型或短会话，这笔账可能不划算。开之前先看清楚：你的模型有没有 cache.ttl？你的暂停真的常超过缓存寿命吗？

禁用

把 warming 设为 false 显式禁用。省略该字段同样保持关闭：

opencode.jsonc
{
  "warming": false,
}
