TUI 界面

TUI（终端用户界面）是 OpenCode 的主战场：在项目里启动、输入需求、按回车，剩下的交给它。这一页讲清发消息、附加上下文、切模型、管会话等全部日常操作。

快速开始

进入你的项目目录并启动：

bash
cd ~/code/my-project
opencode

然后输入你的需求，例如：

text
Explain how authentication works in this project

按 Enter 发送。想换行输入，按 Shift+Enter、Ctrl+Enter、Alt+Enter 或 Ctrl+J。OpenCode 正在工作时，Enter 用于给当前会话「引路」（追加指示）；先按 Ctrl+X 再按 Enter，可以把 prompt 排进队列稍后发送。

🧠 通俗理解

「工作Enter 引导、Ctrl+X+Enter 排队」的分工可以这样记：模型正在干活时你按 Enter，相当于隔着门喊话提醒它——它收到后会调整方向；而 Ctrl+X + Enter 是在门口放了个纸条，等它干完手头的事再按纸条上的新任务开始下一轮。

上下文：@ 引用文件

输入 @ 可以搜索文件，选中后会把该文件附加到 prompt 里。在 @ 之后继续输入可以缩小搜索范围：

text
Review @src/auth.ts for error handling problems

路径后还可以带上行号或行号区间：

text
Explain @src/auth.ts#20-45

⚠️ 注意

@ 是在空格后触发的文件搜索，不是普通的字符——如果你在路径中间手动补了个 @ 并期望它自动搜索，那是不行的。正确姿势是删除后重新输入 @，让搜索框弹出来再选择。另外引用大文件时尽量配合行号区间（如 #20-45），能显著减少 token 消耗。

Shell：! 执行命令

在空 prompt 的开头输入 ! 进入 shell 模式。输入命令后按 Enter 执行；按 Esc 可以不执行就退出 shell 模式：

text
!git status

Shell 命令在会话的工作目录中运行，其输出会留在会话里——模型之后可以直接看到这些输出内容。

💡 扩展

「输出留在会话里」是这个功能的精髓：相当于你在跟同事讨论时顺手贴了一张终端截图。比如你先 !npm test 看到一堆报错，接着直接问「为什么这些测试失败了」，模型能引用刚才的报错输出作答，不用你复制粘贴。

斜杠命令

输入 / 会列出所有斜杠命令。继续输入可以过滤列表，选中后按 Enter 执行：

text
/models

常用命令包括 /new、/sessions、/models、/agents、/undo、/redo 和 /editor。按 Ctrl+P 可以打开命令面板（command palette），看到当前视图下所有可用操作。命令的完整清单见TUI 命令一页。

OpenCode 更新后，会在主页一次性显示本次发布的新功能亮点。想再看一次可以运行 /highlights；在 cli.json 里把 "highlights" 设为 false 则不再自动弹出。

边问边聊：/btw

运行 /btw <问题> 可以针对目前的对话内容快速提一个小问题。回答会使用会话的上下文和当前模型，但不会加入对话记录，因此不影响后续 prompt。运行期间 prompt 底栏会显示一个 /btw 指示器，答案以对话框形式弹出，按 C 可以复制：

text
/btw why did the test in step 2 fail?

🧠 通俗理解

/btw（by the way，顺便问一句）就像开会时的小声嘀咕：你听着听着不明白，私下问一句「刚才第二步为什么失败」，得到的解答不会被记进会议纪要——主对话的上下文干干净净，不会因为这次插问而跑偏。省钱、不干扰主线，一举两得。

切换模型与 Agent

按 Ctrl+X 再按 M 选择模型，或直接运行 /models。按 F2 可以在最近用过的模型之间循环切换。

按 Ctrl+X 再按 A 选择 agent，或运行 /agents。按 Shift+Tab 在 agent 之间循环切换。

会话与标签页

按 Ctrl+X 再按 N 开启新会话。按 Ctrl+X 再按 L 或运行 /sessions 回到已有会话；Ctrl+O 可以同时打开最近的会话和项目。

标签页默认开启。用 Ctrl+Tab 和 Ctrl+Shift+Tab 在标签页之间移动，Ctrl+X 再按 W 关闭当前标签页，Ctrl+Shift+T 重新打开最近关闭的标签页。

💡 扩展

标签页和会话是两层概念：一个标签页里跑着一个会话，多个标签页可以并行推进不同任务（比如一个在改 bug，一个在写文档）。会话本身不会因为关闭标签页而消失，随时可以从 /sessions 里捞回来接着用。

撤销与重做

按 Ctrl+X 再按 U，或运行 /undo，可以撤销最近一条用户消息以及它之后的所有工作。被撤销的 prompt 会回到输入框，方便你改完再发。

按 Ctrl+X 再按 R，或运行 /redo，可以恢复刚才撤销的工作。注意：如果你直接发送了新的 prompt，相当于接受这次撤销，从当前状态继续往后走。

⚠️ 注意

「发送新 prompt 会吃掉 redo 的机会」这个细节很容易踩坑：撤销后临时起意问了个别的问题，再想恢复刚才的工作就来不及了。如果还想回去，先把新想法记在别处，用 /redo 恢复原工作后再说。

外部编辑器

设置好 VISUAL 或 EDITOR 环境变量后，按 Ctrl+X 再按 E，或运行 /editor，可以在那个编辑器里编辑当前 prompt。保存退出后文本回到输入框，再按 Enter 发送：

bash
export EDITOR="nvim"
opencode

💡 扩展

外部编辑器适合「长 prompt」：要写一段好几行的需求描述、贴大段代码时，在 vim 或 VS Code 里编辑比在 TUI 输入框里舒服得多。快捷键的默认前导键是 Ctrl+X，想改成别的（比如 Emacs 风格）见快捷键一页。
