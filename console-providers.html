提供商

把你已经在付费的提供商账号（如 Anthropic、OpenAI 或 AWS Bedrock）接进 Console，与工作区里的所有人共享它们的模型。Console 保管密钥，通过自己的网关对外提供各提供商的服务——成员用模型时完全看不到提供商密钥。你自己的工具也能通过提供商 API（Providers API）使用同一个网关。

🧠 通俗理解

这就像公司的「钥匙托管 + 总机」：老板把各家的 API key 托管给 Console（钥匙不上交给员工），员工想用某个模型就拨总机（Console 网关），总机拿托管钥匙转接。好处有三：key 不外泄、换 key 不用通知所有人、用量全部走同一本账。所有者和管理员在 Providers 标签页管理提供商；成员运行 /connect 后就能在 OpenCode 里用到已启用的模型。

连接提供商

  1. 打开 Providers 页，点击 Connect Provider。
  2. 从目录里挑一个提供商，填入它的 API key。
  3. 可选：点击 Test connection 测试连通性，然后点 Save 保存。

目录里包括 Anthropic、OpenAI、Google、xAI、DeepSeek、Mistral、Groq、OpenRouter 等等。目录里的提供商自带预配置好的模型列表。

云提供商

云提供商需要多填几项信息。

提供商所需信息
Azure资源名称（Resource name）和 API key
AWS Bedrock区域（Region）和 API key
Google Vertex AI区域和服务账号 JSON（service account JSON）

自定义提供商

点击 Add Custom Provider 可以接入任何其他端点，再用 Add Model 添加它的模型。

字段说明
Base URL（基础 URL）Console 转发请求的目标地址，例如 https://api.deepseek.com/v1。
Format（格式）Chat Completions、Responses API、Anthropic Compatible 或 Google Generative AI。
Auth mode（认证模式）Bearer、API key 请求头，或自定义请求头。
Credential（凭据）Console 发给提供商的密钥。

💡 扩展

「Format」决定 Console 用哪种协议方言和目标端点对话：OpenAI 系的 Chat Completions、新一代 Responses API、Anthropic 的 messages 协议、Google 的 Generative AI 协议。选对了格式，中转站、私有部署模型（如 vLLM、Ollama）都能当成标准提供商接入——这也是自带网关方案相对「纯转发」的核心价值。

选择模型

点开一个提供商即可查看它的模型。只有启用的模型才对成员可用。

  • 用 Enabled 开关打开或关闭某个模型。
  • 打开 New models，以后提供商新加的模型会自动启用。

编辑模型

点击一个模型即可编辑。关闭面板时自动保存修改。

区域可以修改的内容
General（常规）显示名称、API ID、工具支持、输入和输出类型
Variants（变体）带独立请求头或请求体的变体
Configuration（配置）默认变体、请求头和请求体、token 上限
Cost Tiers（成本档位）每 1M tokens 的输入、输出、缓存读取、缓存写入价格

自定义定价

目录模型初始使用提供商的官方标价。如果你谈到了优惠价（比如 OpenAI 合同折扣），可以在 Cost Tiers 里覆盖价格，让用量报表和预算与你的实际支出一致。

字段官方标价你的价格
输入价格$2.50$2.00
输出价格$15.00$12.00
缓存读取价格$0.25$0.20

你改过的价格会在提供商页面上高亮显示。在字段上用 Restore default value，或在模型上用 ⋯ › Restore...，即可恢复官方标价。

当模型在超过某个上下文长度后加价时（例如提示词超过 200K tokens），可以添加一个 Context 档位。

⚠️ 注意

自定义定价只影响账目记录，不会改变你实际被提供商收取的金额。它的价值在于让 Console 里的用量报表、预算提醒、成本分摊与真实账单对得上；如果团队按模型用量向内部分摊成本，这一步尤其重要，否则报表数字和财务数字会对不上。

自定义模型

点击 Add Model，填上 Display name（显示名称）和 Model ID，即可添加目录里没有的模型。在已有模型上使用 ⋯ › Duplicate... 可以基于它的设置快速复制一份。

OpenCode 模型

Models 标签页管理 Console 自带的模型，费用从工作区额度中扣除。它的操作方式和提供商页面一样：

  • 单独开启或关闭某个模型。
  • 关闭 Free models，可以为整个工作区屏蔽免费模型。
  • 开启 New models，新的 Console 模型会自动启用。

想只用你自己的提供商，可以在 ⋯ › Disable 里禁用整个 Console 提供商。

在 OpenCode 中使用

成员运行 /connect 并选择工作区。每个启用的提供商都会以「工作区名 / 提供商名」的形式出现，/models 会列出其中启用的模型。

示例/models 中的显示名
Acme Inc. / Anthropic

在 Settings › General 中打开 Managed providers only，可以把所有人的 OpenCode 限制为只使用工作区的提供商。

发送身份（Send identity）

当提供商是你自己运营的网关时，在它的页面上打开 Send identity。此后 Console 发往该网关的每个模型请求都会带上一个 x-opencode-actor 请求头，标明请求背后的成员或服务账号，你的网关就能按发送者记录日志或做限制。

HTTP 请求头
x-opencode-actor: eyJhbGciOiJFUzI1NiIsInR5cCI6Im9wZW5jb2RlLWFjdG9yK2p3dCIsImtpZCI6Ii4uLiJ9...
  • 默认关闭；修改 base URL 也会把它关掉。
  • 提供商仍处于厂商自家 API（如 https://api.openai.com/v1）时，不显示这个设置——因为厂商会忽略这个头。
  • Console 会移除客户端发来的任何 x-opencode-* 请求头，所以你的网关收到的 x-opencode-actor 只可能是 Console 签名的那一个。
  • Test connection 和模型列表功能仅凭凭据调用 GET <base URL>/models，所以不要在该路由上强制要求这个请求头。

💡 扩展

为什么这个头可信？因为它是 Console 用 ES256 私钥签名的 JWT，且 Console 会剥掉客户端伪造的同名头。对网关来说，这意味着「谁在用我的 key」从猜变成了可验证的事实——审计日志、按团队限流、异常检测都能落到真实身份上。

Token 结构

这个请求头是 Console 为每个请求签发的 JWT。

字段取值
algES256
typopencode-actor+jwt
isshttps://opencode.ai/inference
aud提供商的 base URL（去掉末尾斜杠）
iat、expexp 在 iat 之后 120 秒
Claim（声明）取值
sub成员为 user_id，否则为 service_account_id
workspace_id请求所在的工作区

验证 Token

Console 在 https://opencode.ai/inference/.well-known/jwks.json 公布其公钥，响应带 Cache-Control: public, max-age=300。校验顺序：签名、签发者、受众、类型和有效期，然后是工作区。下面的例子使用 jose：

ts
import { createRemoteJWKSet, jwtVerify } from "jose"

const keys = createRemoteJWKSet(new URL("https://opencode.ai/inference/.well-known/jwks.json"))

export async function sender(request: Request) {
  const token = request.headers.get("x-opencode-actor")
  if (!token) throw new Error("Missing x-opencode-actor")
  const { payload } = await jwtVerify(token, keys, {
    issuer: "https://opencode.ai/inference",
    audience: "https://llm.example.com/v1",
    algorithms: ["ES256"],
    typ: "opencode-actor+jwt",
    maxTokenAge: "120s",
    clockTolerance: "5s",
  })
  if (payload.workspace_id !== "org_...") throw new Error("Another workspace")
  return payload
}

把 audience 设为 Console 中保存的提供商 base URL（去掉末尾斜杠），并把 org_... 替换成你 Console URL 中的工作区 ID。Console 在启用新的签名密钥之前会先公布它，因此按 kid 查找密钥的验证器（如 createRemoteJWKSet）在密钥轮换期间也能持续工作。

禁用或移除

打开提供商的 ⋯ 菜单：

  • Disable：对成员隐藏该提供商及其模型，但保留设置。
  • Remove...：删除该提供商及其模型。弹窗会显示最近有哪些人用过它，并提供 Disable instead（改为禁用）选项。

要轮换密钥，点击提供商页面上的凭据并输入新的即可。

计费

提供商直接向你收取 token 费用，Console 不为这些 token 收取额度。Console 仍会按模型定价记录每个请求及其成本，因此用量报表和预算都会包含这些请求。

想在自己的工具（而非 OpenCode）中调用提供商，请使用提供商 API。
