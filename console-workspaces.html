工作区

工作区（Workspace）是 Console 中一切内容的容器：成员、额度、预算、提供商、策略和服务账号都在里面。用量和账单按工作区追踪。

🧠 通俗理解

工作区就是 Console 里的「一个独立账本+一个独立王国」：它有自己的成员名单、自己的钱（额度）、自己的规矩（策略）。公司可以开一个工作区给全员用，个人可以只用自己的 Personal 工作区，接私活的甚至可以给每个客户各开一个，账目互不干扰。工作区可以只有一个成员——额度、自己的提供商、预算、Go 订阅一个人也能全用上，邀请成员这件事等真需要时再说。

你的第一个工作区

注册时 Console 会自动创建一个名为 Personal 的工作区，你是它的所有者（Owner）兼唯一成员。如果你是从别人的邀请注册进来的，则会直接加入邀请方的工作区，不会创建 Personal 工作区。

创建工作区

  1. 打开顶栏的工作区菜单。
  2. 点击 Create Workspace。
  3. 输入工作区名称，点击 Create。

你将成为新工作区的所有者。

切换工作区

在工作区菜单里选择另一个工作区即可。Console 会让你停留在同一个页面上——从 /acme/settings/members 切换过去时，打开的是另一个工作区的 Members 页。

待处理的邀请会出现在同一个菜单的顶部。见 Members。

连接 OpenCode

在 OpenCode 里运行 /connect，然后在浏览器中选择工作区。此后 OpenCode 会使用该工作区的模型、策略和预算。

OpenCode 命令
/connect

再次运行 /connect 可以把 OpenCode 切换到另一个工作区。工作区策略会被替换成新工作区的策略，断开连接时会被清除。

角色

每位成员拥有且只有一个角色。新成员总是以 Member（成员）身份加入。

角色可以做什么
Member（成员）使用 OpenCode，查看自己的用量、日志和预算。
Admin（管理员）成员的一切权限，外加管理成员、账单、预算、提供商、策略、服务账号和设置。
Owner（所有者）管理员的一切权限，外加管理 SSO 和目录同步、授予 Owner 角色、删除工作区。

成员在 Activity 页查看自己的用量和日志；如果排行榜对成员可见，也能看到排行榜。当工作区订阅了 Go Teams 时，成员还能看到 Go 页，查看自己的上限。他们从账号菜单打开 Account。

角色规则

  • 一个工作区可以有多个所有者，并且始终至少保留一个。
  • 你不能授予比自己高的角色，所以只有所有者能任命新的所有者。
  • 你不能更改自己的角色。

转让所有权

  1. 以所有者身份打开 Settings › Members，把新所有者的角色设为 Owner。
  2. 让新所有者把你的角色改为 Admin 或 Member。

⚠️ 注意

转让所有权是个「两步接力」：先由现任 Owner 把对方提成 Owner，再由对方把自己降级。这个设计保证了「至少一名 Owner」的底线永远不破，也意味着你没法单方面把工作区丢给别人——必须对方配合完成第二步。

删除工作区

只有所有者能删除工作区，且必须至少还属于另一个工作区。

  1. 打开 Settings › General，点击 Delete workspace。
  2. 勾选每一项确认声明。
  3. 点击 Delete workspace 确认。

删除立即生效且不可撤销：

  • 成员立即失去访问权限。
  • 所有服务账号 API key 和待处理邀请被吊销。
  • 自动充值停止。
  • 进行中的 Go 订阅终止。
  • 剩余的额度余额被没收。

⚠️ 注意

有支付正在处理时，删除会被阻止，几分钟后重试即可。删除前把剩余额度用完或想清楚——余额会随工作区一起消失，不会退给你。

退出工作区

  1. 从账号菜单打开 Account。
  2. 在 Connected workspaces 下，点击工作区旁边的 Leave。
  3. 点击 Leave workspace 确认。

最后一位所有者不能退出——先把别的成员提成所有者。在启用了 SSO 或目录同步的工作区里，成员身份由你的身份提供商（IdP）管理，所以无法从 Console 退出。退出后想重新加入，需要重新索取一份邀请。

💡 扩展

SSO/目录同步工作区「Console 里退不掉」不是 bug 而是设计：成员名单的权威来源（source of truth）是身份提供商，比如公司 Okta 或 Azure AD。要离开这类工作区，得让 IT 管理员在 IdP 那边把你移出对应的组，同步之后你的 Console 成员身份自然消失。详见 SSO 和 SCIM 两章。
